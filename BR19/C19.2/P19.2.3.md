
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.2.3 (LEVEL 5)

**ID:** P19.2.3  
**Контейнер:** C19.2 (Prompt Optimizer)  
**Название:** Генерация вариантов с помощью LLM  

**Зависимости:** P19.2.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Реализовать генерацию нескольких вариантов улучшенного промпта на основе полученных данных (текущий промпт, список проблем, цели оптимизации). Для генерации используется внешняя LLM (например, OpenAI API). Сгенерированные варианты сохраняются в БД и становятся доступны через API.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Вызов LLM:**  
  – Использовать API OpenAI (или другого провайдера). Ключ и модель задаются переменными окружения `LLM_API_KEY`, `LLM_MODEL` (по умолчанию `gpt-4`).  
  – Промпт для LLM формируется на основе текущего промпта, списка проблем и целей. Пример шаблона:  
    ```text
    Улучши следующий промпт для агента, исправляя перечисленные проблемы:  
    Текущий промпт: {current_prompt}  
    Проблемы: {problems}  
    Цели: {goals}  
    Сгенерируй {num_variants} различных улучшенных версий. Каждая версия должна быть представлена в виде отдельного JSON-объекта с полями "version" и "prompt".
    ```  
  – Ответ LLM должен быть распарсен как JSON-массив вариантов.  
- **Сохранение:**  
  – Сгенерированные варианты сохраняются в таблице `candidates` (поля: `id`, `job_id`, `prompt_text`, `version`, `created_at`).  
- **Асинхронность:** генерация выполняется в фоновой задаче после получения контекста.  
- **Обработка ошибок:**  
  – Если LLM недоступен или возвращает некорректный ответ, задача помечается как `failed`, ошибка логируется.  
  – Можно повторить попытку (настраивается).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В фоновой задаче после получения контекста:  
  1. Сформировать промпт для LLM.  
  2. Отправить запрос к LLM (используя `httpx`).  
  3. Распарсить ответ.  
  4. Для каждого варианта создать запись в `candidates`.  
  5. Обновить статус задачи на `candidates_ready`.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При успешной генерации в БД появляются записи кандидатов.  
- API `GET /candidates` возвращает список сгенерированных вариантов (для завершённых задач).  
- При ошибке LLM задача помечается как `failed`.  
- Логирование работает.
