
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.2.4 (LEVEL 5)

**ID:** P19.2.4  
**Контейнер:** C19.2 (Prompt Optimizer)  
**Название:** Тестирование на калибровочных кейсах  

**Зависимости:** P19.2.3

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
После генерации вариантов необходимо оценить их качество на фиксированном наборе тестовых кейсов из Training Simulator (C3.3). Для каждого кандидата запускается тестирование, результаты сохраняются, и кандидаты, не прошедшие минимальный порог, отбрасываются.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Интеграция с C3.3:**  
  – Адрес задаётся переменной окружения `TRAINING_SIMULATOR_URL` (по умолчанию `http://c3.3:8080`).  
  – Для каждого кандидата вызывается API `POST /test` с телом, содержащим промпт и, возможно, ID задачи (для контекста).  
  – Ожидается ответ с метриками (success_rate, duration и т.д.).  
- **Порог отбора:** настраивается через конфигурацию (например, `min_success_rate = 0.8`).  
- **Сохранение:**  
  – Результаты тестирования сохраняются в таблице `candidates` (поле `test_results`).  
  – Кандидаты, не прошедшие порог, помечаются как `rejected`.  
- **Асинхронность:** тестирование выполняется параллельно для нескольких кандидатов (ограничивая степень параллелизма).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В фоновой задаче после генерации вариантов:  
  1. Для каждого кандидата асинхронно отправить запрос в C3.3.  
  2. Собрать результаты.  
  3. Применить порог, пометить rejected/valid.  
  4. Сохранить результаты.  
  5. Обновить статус задачи на `tested`.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Для каждого кандидата выполняется тестирование, результаты сохраняются.  
- Кандидаты, не прошедшие порог, не участвуют в дальнейшем.  
- API `GET /candidates` возвращает только прошедших (если нужно).  
- Логирование работает.
