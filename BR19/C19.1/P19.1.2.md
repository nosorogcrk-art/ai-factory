### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.1.2 (LEVEL 5) – ЭМБЕДДИНГОВАЯ КЛАСТЕРИЗАЦИЯ (ИСПРАВЛЕННАЯ)

#### 1. ЗАМЫСЕЛ ПАТЧА
Реализовать кластеризацию ошибок с использованием семантических эмбеддингов вместо TF‑IDF. Для каждого лога, классифицируемого как ошибка, извлекается текст, нормализуется и преобразуется в вектор с помощью единой модели эмбеддингов (из C2.1). Затем выполняется кластеризация методом k‑means. Результаты (кластеры, типичные тексты, статистика) сохраняются в БД и доступны через API. Все операции асинхронны, блокировка параллельных запусков – через БД.
---
#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ
- **Источники данных:**  
  – Логи выбираются из таблицы `logs` по условию: `event_type` содержит `error` или `failed` ИЛИ `details` содержит `"error"`.  
  – Для каждого лога извлекается текст ошибки через функцию `extract_error_text()` (учитывает поле `error` или `message` в `details`, иначе использует строковое представление).  
  – **Фильтрация:** поддерживаются опциональные параметры `from_time`, `to_time`, `service`.
- **Нормализация текста:**  
  – Приводится к нижнему регистру.  
  – Удаляются даты (`\d{4}-\d{2}-\d{2}`), временные метки (`\d{2}:\d{2}:\d{2}`), IP‑адреса, UUID.  
  – Сохраняются трёхзначные коды (404, 500) – они не заменяются.  
  – Числа из 1–2 или 4+ цифр заменяются на `#`.  
  – Лишние пробелы удаляются.
- **Векторизация:**  
  – Используется единый модуль `embedding_model.py` из контейнера C2.1 (файл должен быть скопирован в образ C19.1 или доступен через том).  
  – Модель загружается один раз при старте приложения. Рекомендуется смонтировать том `/root/.cache/huggingface` для кэширования модели и ускорения повторных запусков.  
  – Для каждого нормализованного текста вычисляется вектор размерности 384 (прямой вызов `encoder.encode()` с возможностью пакетной обработки).  
  – При ошибке загрузки модели или недоступности модуля задача кластеризации помечается как `failed`.
- **Кластеризация:**  
  – Выполняется алгоритмом k‑means (`sklearn.cluster.KMeans`).  
  – Число кластеров определяется автоматически (упрощённый метод локтя: вычисляется инерция для k от 2 до `MAX_CLUSTERS`, ищется точка, где разница инерции становится меньше средней). Если `FIXED_CLUSTERS` > 1, используется это значение.  
  – Ограничения: `MAX_CLUSTERS` (по умолчанию 20), `CLUSTER_SAMPLE_LIMIT` (по умолчанию 10 000).  
- **Сохранение результатов:**  
  – Создаётся временная таблица `new_clusters` с полями `pattern`, `count`, `last_seen`, `sample`.  
  – Для каждого кластера:  
    * Определяется элемент, ближайший к центроиду (по евклидову расстоянию).  
    * `pattern` – нормализованный текст этого элемента (первые 200 символов).  
    * `sample` – оригинальный текст ошибки этого элемента (до 500 символов).  
    * `count` – количество записей в кластере.  
    * `last_seen` – максимальная временная метка среди записей кластера.  
  – Старая таблица `error_clusters` заменяется атомарно: `DELETE` + `INSERT` из временной таблицы.  
- **Асинхронность и блокировка:**  
  – Запуск кластеризации происходит через фоновую задачу (`BackgroundTasks`).  
  – Перед запуском проверяется наличие активной задачи через `is_clustering_active()` (поиск записей в `analysis_jobs` со статусом `pending`/`running` и `job_id LIKE 'cluster_%'`).  
  – При старте создаётся запись в `analysis_jobs` со статусом `running`, после завершения статус меняется на `completed`/`failed`.  
- **API:**  
  – `POST /cluster` – запуск кластеризации (с опциональными фильтрами `from_time`, `to_time`, `service`).  
  – `GET /clusters` – список кластеров (сортировка по убыванию `count`, пагинация).  
  – `GET /clusters/{cluster_id}` – детали конкретного кластера.  
- **Логирование:**  
  – Все операции и ошибки записываются в файл `01_ЦЕХ/01_ЖУРНАЛЫ/log_analyzer.log`.  
  – При необходимости могут отправляться в BR18 (в будущих патчах).  
- **Доступ к модулю эмбеддингов в контейнере:**  
  – В `Dockerfile` добавить: `COPY ./BR2/C2.1/embedding_model.py ./`  
  – Либо смонтировать том с кодом BR2 и добавить путь в `PYTHONPATH`. Рекомендуется первый вариант для упрощения.

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ
- **Новые зависимости в `requirements.txt`:** `sentence-transformers==2.2.2`, `torch` (или `onnxruntime`).  
- **Импорт модуля эмбеддингов:**  
  ```python
  from embedding_model import get_encoder
  encoder = get_encoder()

- **Функция `cluster_errors`** модифицируется:  
    – После нормализации текстов, создаётся список `texts`.  
    – Векторизация: `embeddings = encoder.encode(texts, batch_size=64)`.  
    – Далее k‑means, выбор k, группировка и сохранение с атомарной заменой.
    
- **Обработка ошибок:** при недоступности модели или ошибке эмбеддинга задача кластеризации помечается как `failed`.

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)

- Приложение запускается, модуль эмбеддингов загружается один раз.
    
- При наличии ошибок в логах запуск `/cluster` создаёт задачу и возвращает `job_id`.
    
- Фоновая задача выполняет кластеризацию, результаты сохраняются в `error_clusters`.
    
- API `/clusters` возвращает список кластеров с заполненными полями.
    
- Если модель эмбеддингов недоступна или возвращает ошибку, задача завершается со статусом `failed`.
    
- Блокировка параллельных запусков работает (при повторном вызове возвращается 409).
    
- При наличии в логах ошибок с разными трёхзначными кодами (например, 404 и 500) они попадают в разные кластеры (проверяется на тестовых данных).
    
- Все действия логируются.
