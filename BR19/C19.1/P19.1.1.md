### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.1.1 (LEVEL 5) – ИСПРАВЛЕННАЯ

**ID:** P19.1.1  
**Контейнер:** C19.1 (Log Analyzer)  
**Название:** Базовая структура и API (заглушка)  

**Зависимости:** P18.1.1 (Log Aggregator)

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Создать каркас FastAPI-приложения для анализа логов. Реализовать эндпоинты для запуска анализа и получения статуса, но на данном этапе вся логика анализа заменена заглушками. Это позволит отладить взаимодействие с внешними компонентами и подготовить инфраструктуру для последующих патчей.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Стек:** Python + FastAPI, Uvicorn.  
- **Порт:** 8101 (настраивается через переменную окружения `PORT`).  
- **Эндпоинты-заглушки:**  
  - `POST /analyze` – принимает JSON с параметрами (например, `{"period": "last_24h"}`), возвращает `{"job_id": "ana_12345", "status": "started"}`.  
  - `GET /reports` – возвращает список доступных отчётов (пока пустой массив).  
  - `GET /reports/{id}` – возвращает заглушечный отчёт с фиктивными данными.  
  - `GET /patterns` – возвращает пустой список.  
- **Асинхронность:** даже заглушка должна использовать фоновые задачи (`BackgroundTasks`), чтобы имитировать реальное поведение. При получении запроса `POST /analyze` сразу возвращается ответ, а «анализ» выполняется в фоне (может просто записывать в лог).  
- **Хранение статуса:** для отслеживания задач анализа используется SQLite (таблица `analysis_jobs` с полями `job_id`, `status`, `result_path`, `created_at`). При запуске задачи создаётся запись со статусом `running`. По завершении статус меняется на `completed` и сохраняется путь к отчёту.  
- **Интеграция с C18.1:** на данном этапе не реализуется, только заглушка.  
- **Локальное логирование:** все запросы записываются в файл `01_ЦЕХ/01_ЖУРНАЛЫ/log_analyzer.log`.  
- **Эндпоинт /health** – возвращает `{"status": "ok"}`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать файл `log_analyzer.py` с FastAPI-приложением.  
- При старте инициализировать SQLite (таблица `analysis_jobs`).  
- В эндпоинте `POST /analyze` сгенерировать `job_id` (UUID), создать запись в БД со статусом `running`, запустить фоновую задачу (через `BackgroundTasks`), которая через некоторое время обновит статус на `completed` (для заглушки можно просто установить таймер).  
- Для `GET /reports` возвращать список всех задач (или только завершённых).  
- Для `GET /reports/{id}` возвращать статус и, если завершён, фиктивный отчёт.  
- Добавить `/health`.  
- Настроить логирование.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Приложение запускается на порту 8101.  
- `POST /analyze` возвращает JSON с `job_id` и сразу отвечает.  
- В БД создаётся запись задачи.  
- Фоновая задача имитирует выполнение (меняет статус через некоторое время).  
- `GET /reports` возвращает список задач.  
- `GET /reports/{id}` возвращает статус и отчёт.  
- Эндпоинт `/health` отвечает `{"status": "ok"}`.  
- Локальный лог-файл создаётся и содержит записи о запросах.
