
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.3.2 (LEVEL 5)

**ID:** P19.3.2  
**Контейнер:** C19.3 (Skill Updater)  
**Название:** Интеграция с C19.1 и BR17  

**Зависимости:** P19.3.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить возможность получения входных данных для обновления навыка: отчёты о проблемах и успешных кейсах из Log Analyzer (C19.1), а также текущую версию навыка из реестра навыков (C17.1). Эти данные будут использоваться в последующих патчах для генерации улучшений.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Источники данных:**  
  – **C19.1 (Log Analyzer):** API для получения информации о проблемах, связанных с конкретным навыком. Предполагается эндпоинт `GET /problems?skill_id=...` или получение из отчёта. Адрес задаётся переменной окружения `LOG_ANALYZER_URL` (по умолчанию `http://c19.1:8101`).  
  – **C17.1 (Skill Registry):** API для получения метаданных навыка (`GET /skills/{skill_id}`). Адрес задаётся переменной `SKILL_REGISTRY_URL` (по умолчанию `http://c17.1:8088`).  
- **Процесс:**  
  – При запуске задачи обновления (`POST /update/{skill_id}`) в фоновой задаче выполняются следующие шаги:  
    1. Запросить текущий навык из C17.1. Если навык не найден или статус `deleted`, задача завершается с ошибкой.  
    2. Запросить связанные проблемы/успешные кейсы из C19.1 (если доступно).  
    3. Сохранить полученные данные в контексте задачи (в JSON-поле таблицы `update_jobs`).  
    4. Если какой-либо источник недоступен, задача продолжается с предупреждением (проблемы будут пустыми).  
- **Асинхронность:** все запросы выполняются асинхронно в рамках фоновой задачи.  
- **Логирование:** все обращения и ошибки логируются.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В фоновой задаче (в обработчике `POST /update/{skill_id}`) после создания записи в БД выполнить:  
  1. Асинхронно запросить навык из C17.1 (используя `httpx`).  
  2. Асинхронно запросить проблемы из C19.1.  
  3. Сохранить полученные данные в поле `context` записи задачи (JSON).  
  4. Обновить статус задачи на `ready_for_generation`.  
- Обработать таймауты и ошибки.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При запуске обновления с корректным `skill_id` данные из C17.1 сохраняются в контексте.  
- При наличии отчёта из C19.1 он также сохраняется.  
- При недоступности сервисов задача продолжается с предупреждением.  
- В БД поле `context` заполняется JSON-объектом с полученными данными.
