### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.3.1 (LEVEL 5)

**ID:** P19.3.1  
**Контейнер:** C19.3 (Skill Updater)  
**Название:** Базовая структура и API (заглушка)  

**Зависимости:** отсутствуют

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Создать каркас FastAPI-приложения для автоматического обновления навыков. Реализовать эндпоинты для запуска процесса обновления конкретного навыка и получения истории обновлений. На данном этапе вся логика заменена заглушками для отладки API и подготовки инфраструктуры.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Стек:** Python + FastAPI, Uvicorn.  
- **Порт:** 8103 (настраивается через переменную окружения `PORT`).  
- **Эндпоинты-заглушки:**  
  - `POST /update/{skill_id}` – принимает JSON с параметрами (например, `{"based_on": "errors", "max_suggestions": 3}`), возвращает `{"job_id": "upd_abcde", "status": "started"}`.  
  - `GET /updates` – возвращает пустой список.  
- **Асинхронность:** даже заглушка должна использовать фоновые задачи (`BackgroundTasks`), чтобы имитировать реальное поведение. При получении запроса сразу возвращается ответ, а фоновая задача может просто логировать вызов и через некоторое время обновлять статус.  
- **Хранение статуса:** для отслеживания задач обновления используется SQLite (таблица `update_jobs` с полями `job_id`, `skill_id`, `status`, `created_at`, `result`). При запуске задачи создаётся запись со статусом `running`. По завершении статус меняется на `completed` или `failed`.  
- **Локальное логирование:** все запросы записываются в файл `01_ЦЕХ/01_ЖУРНАЛЫ/skill_updater.log`.  
- **Эндпоинт /health** – возвращает `{"status": "ok"}`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать файл `skill_updater.py` з FastAPI-приложением.  
- При старте инициализировать SQLite (таблица `update_jobs`).  
- В эндпоинте `POST /update/{skill_id}` сгенерировать `job_id` (UUID), создать запись в БД со статусом `running`, запустить фоновую задачу (через `BackgroundTasks`), которая через некоторое время обновит статус на `completed` (для заглушки можно просто установить таймер).  
- Для `GET /updates` возвращать список всех задач (или только завершённых).  
- Добавить `/health`.  
- Настроить логирование.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Приложение запускается на порту 8103.  
- `POST /update/{skill_id}` возвращает JSON с `job_id` и сразу отвечает.  
- В БД создаётся запись задачи.  
- Фоновая задача имитирует выполнение (меняет статус).  
- `GET /updates` возвращает список задач.  
- Эндпоинт `/health` отвечает `{"status": "ok"}`.  
- Локальный лог-файл создаётся и содержит записи о запросах.
