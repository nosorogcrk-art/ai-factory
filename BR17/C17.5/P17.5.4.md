
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P17.5.4 (LEVEL 5)

**ID:** P17.5.4  
**Контейнер:** C17.5 (Skill Publisher)  
**Название:** Кэширование  

**Зависимости:** P17.5.3

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить кэширование ответов для снижения нагрузки на реестр и систему версионирования, а также для ускорения ответов. Кэш должен учитывать ID навыка, версию и, возможно, другие параметры (например, `agent_type` для будущих патчей).

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Тип кэша:** in-memory LRU-кэш с ограниченным размером (например, 1000 элементов) и временем жизни (TTL) – например, 5 минут.  
- **Ключ кэша:** строка вида `{skill_id}:{version}:{agent_type}`. Если версия не указана, используется `latest`.  
- **Инвалидация:**  
  - Принудительная инвалидация по запросу (можно добавить эндпоинт `POST /cache/invalidate` для администратора).  
  - Автоматическая по истечении TTL.  
- **Сохранение:** при попадании в кэш возвращать сохранённый объект, при промахе – обращаться к источникам, затем сохранять в кэш.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Использовать `cachetools.TTLCache` или аналогичную библиотеку.  
- В функциях получения навыка (одиночный и batch) реализовать проверку кэша перед вызовом внешних сервисов.  
- При сохранении в кэш учитывать, что версия может быть `None` (последняя).  
- Добавить опциональный эндпоинт для ручной инвалидации (с проверкой прав).  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Повторный запрос одного и того же навыка (с теми же параметрами) в течение TTL не приводит к повторному вызову C17.1/C17.2.  
- При изменении данных в реестре старый кэш перестаёт использоваться после истечения TTL.  
- Batch-запросы также используют кэш для каждого навыка.  
- Инвалидация по запросу работает.
