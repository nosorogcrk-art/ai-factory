
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P17.1.2 (LEVEL 5)

**ID:** P17.1.2  
**Контейнер:** C17.1 (Skill Registry)  
**Название:** Валидация и расширенные фильтры

**Зависимости:** P17.1.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Расширить функциональность реестра: добавить полноценную валидацию входных данных (формат версии, проверка существования зависимостей), поддержку фильтрации, пагинации и сортировки при получении списка навыков, а также эндпоинт для получения статистики.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Валидация:**
  - Формат `version` должен соответствовать семантическому версионированию (например, `1.2.3`, `2.0.0-beta`). Использовать библиотеку `packaging.version` или регулярное выражение.
  - Поле `status` должно быть одним из: `draft`, `active`, `deprecated`, `deleted`.
  - Поля `tags`, `task_types`, `languages` – массивы строк (проверка типа).
  - Поле `depends_on` – массив ID навыков. Каждый ID должен существовать в БД (кроме самого себя) и не быть в статусе `deleted`. При создании или обновлении проверять это.
  - Поле `related_patches` – массив строк, валидация существования патчей не обязательна (можно игнорировать).
- **Фильтрация и пагинация для `GET /skills`:**
  - Параметры запроса:
    - `status` – фильтр по статусу (можно несколько через запятую).
    - `tags` – фильтр по тегам (пересечение).
    - `task_types` – фильтр по типам задач.
    - `languages` – фильтр по языкам.
    - `limit` – количество записей на странице (по умолчанию 20, максимум 100).
    - `offset` – смещение.
    - `sort` – поле для сортировки (`name`, `created_at`). По умолчанию `created_at DESC`.
  - Возвращать объект с полями: `items` (массив навыков), `total` (общее количество), `limit`, `offset`.
- **Эндпоинт `GET /skills/stats`:** возвращает статистику:
  ```json
  {
    "total": 150,
    "active": 120,
    "draft": 20,
    "deprecated": 5,
    "deleted": 5
  }
  ```
- **Логирование:** все ошибки валидации и успешные запросы логируются в тот же лог-файл.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ

- Модифицировать Pydantic-модели, добавив валидаторы для `version` (регулярка или `packaging.version.parse`), для `depends_on` (запрос к БД).
- В эндпоинте `GET /skills` добавить парсинг параметров и построение SQL-запроса с учётом фильтров, пагинации и сортировки.
- Добавить эндпоинт `/skills/stats`, выполняющий агрегатные запросы.
- Обновить обработчики POST/PUT для использования новых валидаторов.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)

- При создании навыка с неверным форматом версии – ошибка 422.
- При указании в `depends_on` несуществующего ID – ошибка 422.
- Фильтрация по статусу, тегам работает корректно.
- Пагинация возвращает ожидаемые записи.
- Эндпоинт статистики возвращает корректные числа.
- Все ошибки логируются.
