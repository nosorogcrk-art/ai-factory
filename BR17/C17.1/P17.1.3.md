
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P17.1.3 (LEVEL 5)

**ID:** P17.1.3  
**Контейнер:** C17.1 (Skill Registry)  
**Название:** Интеграция с BR18 (логирование)

**Зависимости:** P17.1.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Добавить отправку логов о всех изменениях в реестре навыков (создание, обновление, удаление) в центральный лог-агрегатор BR18 (C18.1). Также логировать ошибки валидации. Это обеспечит централизованный мониторинг и прослеживаемость.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Адрес BR18:** переменная окружения `BR18_URL` (по умолчанию `http://br18:8080/api/logs`).
- **Формат лога (JSON):**
  ```json
  {
    "timestamp": "ISO 8601 UTC",
    "service": "C17.1",
    "event_type": "skill_created | skill_updated | skill_deleted | validation_error",
    "details": {
      "skill_id": "SKILL-001",
      "version": "1.2.3",
      "changed_fields": ["description", "status"], // для обновления
      "user": "argus" // можно брать из заголовка X-User (опционально)
    }
  }
  ```
- **События для логирования:**
  - После успешного POST (создание) – `skill_created`.
  - После успешного PUT/PATCH (обновление) – `skill_updated` с указанием изменённых полей (можно передавать список).
  - После успешного DELETE (мягкое удаление) – `skill_deleted`.
  - При ошибке валидации (422) – `validation_error` с деталями.
- **Асинхронность:** отправка должна выполняться в фоновом режиме (например, через `BackgroundTasks` в FastAPI), чтобы не задерживать ответ клиента.
- **Обработка ошибок:** если BR18 недоступен, ошибка не должна влиять на основной процесс, но должна логироваться локально.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ

- В файле `skill_registry.py` добавить функцию `send_log(event_type, details, background_tasks)`.
- В эндпоинтах после успешного выполнения операции (или при ошибке) вызывать эту функцию с соответствующими параметрами.
- Для определения изменённых полей в PUT/PATCH можно сравнивать старую и новую запись.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)

- При каждом успешном создании навыка в BR18 отправляется лог.
- При обновлении – лог с указанием изменённых полей.
- При удалении – лог.
- При ошибке валидации – лог.
- Отправка не блокирует ответ.
- При недоступности BR18 ошибка логируется локально.
