
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P17.2.2 (LEVEL 5)

**ID:** P17.2.2  
**Контейнер:** C17.2 (Skill Version Control)  
**Название:** Базовые операции с коммитами  

**Зависимости:** P17.2.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Реализовать REST API для выполнения базовых операций с Git-репозиторием навыков: создание коммита для конкретного навыка, получение истории изменений и получение содержимого файла навыка по указанной версии. Это позволит другим компонентам (например, C17.1) сохранять изменения и просматривать историю.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Эндпоинты (все внутри Docker-сети, порт 8089):**
  - `POST /commit/{skill_id}` – создаёт коммит для файла навыка.
    - Тело запроса (JSON): `{ "content": { ... }, "message": "commit message" }`
    - `content` – полный JSON-объект навыка (соответствует структуре из C17.1).
    - Действия:
      1. Проверить, существует ли файл `{skill_id}.json` в репозитории (если нет – создать).
      2. Записать новое содержимое в файл.
      3. Выполнить `git add` для этого файла.
      4. Выполнить `git commit` с указанным сообщением.
    - Возвращает: `{ "commit_hash": "abc123def" }` или ошибку.
  - `GET /history/{skill_id}` – возвращает список коммитов для файла.
    - Ответ: JSON-массив объектов с полями `hash`, `author`, `date`, `message`.
    - Используется `git log --pretty=format:'%H|%an|%ad|%s'` для файла.
  - `GET /file/{skill_id}?ref=<commit_hash>` – возвращает содержимое файла навыка на указанной версии.
    - Параметр `ref` обязателен (можно указать хеш коммита или тег).
    - Возвращает JSON-объект навыка (как в C17.1).
- **Обработка ошибок:**
  - Если файл не существует в репозитории – 404.
  - Если коммит не найден – 404.
  - Ошибки Git – 500 с описанием.
- **Логирование:** все операции записываются в локальный лог (например, `version_control.log`).

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ

- В FastAPI-приложении добавить эндпоинты.
- Использовать GitPython для работы с репозиторием.
- Для `POST /commit`:
  - Получить репозиторий, путь к файлу: `repo_path / f"{skill_id}.json"`.
  - Записать JSON в файл (с отступами).
  - Выполнить `repo.index.add([file_path])`.
  - Выполнить `repo.index.commit(message)`.
  - Вернуть хеш коммита.
- Для `GET /history`:
  - Получить коммиты, затрагивающие файл: `repo.iter_commits(paths=file_path)`.
  - Преобразовать в список.
- Для `GET /file`:
  - Получить коммит по хешу, затем получить содержимое файла через `commit.tree / file_path`.data_stream.read() и декодировать JSON.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)

- При отправке POST /commit с корректными данными создаётся коммит, возвращается его хеш.
- GET /history/{skill_id} возвращает список коммитов (может быть пустым).
- GET /file?ref=... возвращает корректное содержимое файла.
- При неверных параметрах возвращаются соответствующие HTTP-ошибки.
- Логирование работает.
