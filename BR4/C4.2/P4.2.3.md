
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P4.2.3 (LEVEL 5)

**ID:** P4.2.3  
**Контейнер:** C4.2 (Graph Visualizer)  
**Название:** Интеграция с BR2 (метаданные и поиск)  
**Зависимости:** P4.2.2  

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Обогатить узлы графа метаданными из семантической памяти (BR2) и добавить возможность поиска узлов по запросу. API будет дополнено эндпоинтом для семантического поиска узлов, а также поля узлов обогатятся заголовками, датами и типами, полученными из C2.3.  

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  
- **Интеграция с C2.3:** использовать его API для получения метаданных по ID документа. Предполагается эндпоинт `/metadata/{id}` или `/search` с фильтром по ID.  
- **Новые эндпоинты:**  
  - `GET /api/graph/enriched` – возвращает граф с дополнительными полями в узлах: `title`, `source_type`, `timestamp` (если доступны).  
  - `GET /api/search?q=текст` – выполняет семантический поиск по C2.3 и возвращает список узлов, релевантных запросу.  
- **Модификация существующего эндпоинта `/api/graph`:** можно оставить как есть или заменить на обогащённую версию. Для обратной совместимости можно добавить параметр `enriched`.  
- **Кэширование метаданных:** метаданные для каждого ID можно кэшировать в памяти с TTL (например, 1 час), чтобы не нагружать C2.3.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  
- В `graph_api.py` добавить функцию `fetch_metadata_from_br2(doc_id)`, которая обращается к C2.3.  
- При построении обогащённого графа для каждого узла вызывать эту функцию и добавлять поля.  
- Добавить эндпоинт `/api/search`, который вызывает семантический поиск C2.3 и возвращает результаты в формате узлов.  
- Реализовать кэширование.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  
- При запросе `/api/graph/enriched` узлы содержат дополнительные поля (если они есть в BR2).  
- Эндпоинт `/api/search` возвращает список узлов, соответствующих запросу.  
- При недоступности C2.3 обогащённый граф возвращается без дополнительных полей (с предупреждением в логе).  
- Кэширование работает.
