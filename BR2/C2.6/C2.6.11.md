### 1. Цель

Добавить в C2.6 два новых эндпоинта для работы с **глобальной памятью завода** (отдельной от проектов):

- `POST /index` – индексация одного или нескольких документов (паспортов веток, контейнеров, спецификаций патчей, L2) в векторную коллекцию `factory_docs`.
- `POST /search` – семантический поиск по глобальной памяти завода.

Это позволит C1.2 и другим агентам (Cline) находить аналогичные решения, переиспользовать патчи и учиться на истории проектирования.

### 4. Добавляемые эндпоинты

| Метод | Путь | Описание | Тело запроса | Ответ |
|-------|------|----------|--------------|-------|
| POST | `/index` | Индексация документов завода | `{"documents": ["/path/to/file1.md", "/path/to/file2.py"]}` | `{"status": "ok", "indexed_count": 2, "errors": []}` |
| POST | `/search` | Семантический поиск по глобальной памяти | `{"query": "текст запроса", "limit": 5}` | `{"results": [{"path": "/path", "score": 0.85, "snippet": "...", "metadata": {...}}]}` |

**Детали:**

#### 4.1. Эндпоинт `/index`

- Принимает список абсолютных или относительных (от корня завода) путей к файлам.
- Для каждого файла:
  - Проверяет существование файла. Если нет – пропускает с ошибкой в `errors`.
  - Читает содержимое (до 10 МБ, иначе ошибка).
  - Генерирует ID документа: `file_{sha256(path)}` (или `path` с заменой `/` на `_`).
  - Генерирует эмбеддинг (через существующую `get_encoder()`).
  - Сохраняет в коллекцию `factory_docs` (создаёт, если не существует).
  - Метаданные: `path`, `filename`, `size`, `timestamp`, `type` (определяется по расширению: `.md` → `markdown`, `.json` → `json`, `.py` → `code`).
- Возвращает количество успешно проиндексированных документов и список ошибок.
- Логирует каждую индексацию (локально и в BR18).

#### 4.2. Эндпоинт `/search`

- Принимает `query` (строка) и `limit` (целое, 1–50, по умолчанию 5).
- Выполняет поиск по коллекции `factory_docs` (если коллекция не существует – возвращает пустой массив).
- Возвращает массив результатов, отсортированных по убыванию `score`.
- Для каждого результата: `path`, `score` (0–1), `snippet` (первые 200 символов содержимого), `metadata`.
- Логирует поиск (локально и в BR18).

### 5. Изменения в существующем коде

#### 5.1. `models.py`

Добавить:

```python
class IndexRequest(BaseModel):
    documents: list[str]   # пути к файлам

class IndexResponse(BaseModel):
    status: str
    indexed_count: int
    errors: list[str]

class GlobalSearchRequest(BaseModel):
    query: str
    limit: int = 5

class GlobalSearchResult(BaseModel):
    path: str
    score: float
    snippet: str
    metadata: dict

class GlobalSearchResponse(BaseModel):
    results: list[GlobalSearchResult]
```

#### 5.4. `test_services.py` и `test_api.py`

Добавить юнит-тесты:

#### 5.5. E2E-тест с LLM-судьёй (обязателен)

- **Сценарий:** проиндексировать 3 документа (паспорт контейнера, спецификацию патча, L2). Затем выполнить поиск по запросу «управление аккаунтами Telegram». LLM-судья оценивает, что в топ-2 результатов есть документ, релевантный запросу.
- **Критерии:** релевантность ≥ 0.8.
- **Тестовые данные:** подготовить тестовые файлы в папке `tests/data/`.
