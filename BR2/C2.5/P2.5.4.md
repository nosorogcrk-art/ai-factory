
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P2.5.4 (LEVEL 5)

**ID:** P2.5.4  
**Контейнер:** C2.5 (Source Quality Filter)  
**Название:** Интеграция с C2.4 и BR18

**Зависимости:** P2.5.3

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Обеспечить вызов фильтра качества из сборщика внешних источников (C2.4) и добавить отправку логов в BR18 (Log Aggregator). Модифицировать C2.4 так, чтобы перед индексацией каждого источника он отправлял запрос в C2.5 и действовал согласно ответу. В C2.5 добавить отправку логов в BR18 при каждом вызове.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

**2.1. Модификация C2.4 (сборщик)**
- В скриптах `github_collector.py` или `external_to_indexer.py` добавить вызов API C2.5 перед обработкой репозитория.
- Если C2.5 возвращает `allowed: false`, репозиторий (или конкретный файл) не должен индексироваться, а причина должна логироваться.
- Адрес C2.5 должен быть задан в переменной окружения `FILTER_SERVICE_URL` (по умолчанию `http://c2.5:8085`).

**2.2. Добавление логирования в BR18 в C2.5**
- В эндпоинте `/check` после обработки запроса отправлять лог-событие в BR18 (асинхронно).
- Адрес BR18 задаётся через переменную окружения `BR18_URL` (по умолчанию `http://br18:8080/api/logs`).
- Формат лога:
  ```json
  {
    "timestamp": "...",
    "service": "C2.5",
    "event_type": "source_checked",
    "details": {
      "source_url": "...",
      "type": "...",
      "allowed": true/false,
      "reason": "..."
    }
  }
  ```
- В случае ошибки отправки лога не прерывать основной процесс, только локально логировать.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ
- В C2.5 добавить функцию `send_log` (аналогично P0.4.4) и вызывать её после выполнения `check_source`.
- В C2.4 (например, в `github_collector.py`) перед вызовом `collect_repo` выполнить HTTP POST к C2.5 и проанализировать ответ. При отрицательном ответе пропустить репозиторий и записать причину в лог.
- Настроить тайм-ауты (например, 5 секунд) и обработку ошибок (если C2.5 недоступен – возможно, разрешить индексацию с предупреждением).

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)
- При запуске C2.4 с конфигурацией, содержащей репозиторий, не проходящий фильтр, этот репозиторий не клонируется и не индексируется.
- В логах C2.4 есть запись о пропуске с указанием причины.
- В BR18 поступают логи от C2.5 о каждой проверке (можно проверить, временно подняв заглушку).
- При недоступности C2.5 сборщик продолжает работу (индексирует с предупреждением).
