
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P2.5.3 (LEVEL 5)

**ID:** P2.5.3  
**Контейнер:** C2.5 (Source Quality Filter)  
**Название:** Конфигурация и настраиваемые пороги

**Зависимости:** P2.5.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Добавить возможность задания правил фильтрации через внешний конфигурационный файл (`source_quality_config.json`). Функция `check_source` должна читать этот файл при запуске и при каждом запросе использовать актуальные настройки. Также реализовать автоматическую перезагрузку конфигурации при изменении файла (hot reload) или периодическую проверку.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Файл конфигурации:** располагается по пути `/config/source_quality_config.json` (монтируется как volume). Пример структуры см. в паспорте C2.5.
- **Загрузка конфигурации:**
  - При старте сервиса файл читается и парсится.
  - Создаётся объект конфигурации в памяти.
  - Периодически (например, каждые 60 секунд) проверяется `mtime` файла; если изменился – конфигурация перезагружается.
- **Модификация `check_source`:** функция должна принимать не только `source_data`, но и текущую конфигурацию (или конфигурация должна быть доступна глобально). Рекомендуется передавать конфигурацию как аргумент, чтобы облегчить тестирование.
- **Логирование:** при перезагрузке конфигурации записывать событие в лог.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ
- Создать модуль `config.py`, который:
  - Загружает JSON из файла.
  - Предоставляет функцию `get_config()` для получения актуальной конфигурации (с кэшированием и проверкой mtime).
- Модифицировать `source_filter.py`: изменить сигнатуру `check_source(source_data, config)`. Внутри использовать параметры из конфигурации вместо хардкода.
- В API (`main.py`) при каждом запросе получать актуальную конфигурацию через `get_config()` и передавать в `check_source`.
- Добавить логирование перезагрузки конфигурации.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)
- При запуске без конфигурационного файла используются значения по умолчанию (можно определить в коде).
- При изменении файла конфигурации новые правила начинают применяться без перезапуска сервиса.
- Логи фиксируют перезагрузку.
- Работа API сохраняется.
