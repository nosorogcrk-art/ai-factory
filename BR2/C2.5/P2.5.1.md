
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P2.5.1 (LEVEL 5)

**ID:** P2.5.1  
**Контейнер:** C2.5 (Source Quality Filter)  
**Название:** Базовый модуль качества источников

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Реализовать ядро фильтра качества – функцию `check_source`, которая на основе входных данных об источнике (тип, метрики) принимает решение: допускать источник к индексации или нет. На этом этапе правила задаются непосредственно в коде (hardcoded), без внешней конфигурации. Функция будет использоваться последующими патчами для создания REST API и интеграции с конфигурацией.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Язык:** Python 3.11.
- **Функция `check_source(source_data: dict) -> (bool, str)`**, где:
  - `source_data` – словарь, содержащий поля, аналогичные описанным в паспорте C2.5 (см. раздел 3). Минимально необходимые поля: `type` (строка), а также соответствующие типу метрики.
  - Возвращает кортеж: `(allowed: bool, reason: str)`. Если `allowed = False`, `reason` содержит описание причины отказа.
- **Правила (хардкод):**
  - Для GitHub:
    - `stars >= 100`
    - `last_commit` не старше 1 года от текущей даты (рассчитывается динамически)
    - `has_tests == True`
    - `license` должен быть в списке разрешённых: `["MIT", "Apache-2.0", "BSD-3-Clause", "BSD-2-Clause", "ISC"]`
  - Для arXiv:
    - `published_date` не старше 2 лет
    - `category` должен быть в `["cs.AI", "cs.LG", "cs.CL", "stat.ML"]`
  - Для блогов:
    - `published_date` не старше 1 года
    - `domain` должен быть в списке доверенных: `["medium.com", "dev.to", "habr.com", "opensource.com"]`
  - Если тип неизвестен – возвращать `(False, "unknown source type")`.
- **Логирование:** модуль может записывать в локальный лог-файл (например, `source_filter.log`) информацию о проверках (по желанию, но не обязательно на этом этапе).

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ
- Создать файл `source_filter.py` в директории `agents/tools/` (или аналогичной).
- Определить функцию `check_source` с описанной логикой.
- Добавить вспомогательные функции для проверки дат.
- Написать простые юнит-тесты для проверки правил.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)
- Функция `check_source` возвращает ожидаемые результаты для различных входных данных (тесты проходят).
- Код соответствует стандартам PEP 8, есть docstring.
- При неверных или отсутствующих полях функция не падает с исключением, а возвращает `(False, "missing field")`.
