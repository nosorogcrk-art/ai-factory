
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P18.2.4 (LEVEL 5)

**ID:** P18.2.4  
**Контейнер:** C18.2 (Metrics Dashboard)  
**Название:** Исторические данные  

**Зависимости:** P18.2.3

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить долговременное хранение метрик для возможности построения графиков за произвольные периоды. Использовать SQLite для записи агрегированных значений с временными метками. Реализовать эндпоинт для получения временных рядов.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **База данных:** SQLite, файл `/data/metrics.db` (монтируемый том).  
- **Таблица `metrics_history`:**  
  - `timestamp` (DATETIME)  
  - `name` (TEXT)  
  - `value` (REAL)  
  - `tags` (TEXT) – JSON-строка с дополнительными тегами (опционально).  
- **Запись в БД:**  
  – Периодически (например, раз в минуту) фоновый процесс берёт текущие агрегаты для каждой метрики и записывает их в БД.  
  – Можно также записывать сырые значения, но для экономии места ограничимся агрегатами.  
- **Эндпоинт:**  
  - `GET /api/metrics/history/{name}?from=ISO&to=ISO&limit=1000` – возвращает массив записей для указанной метрики в заданном интервале.  
  - Параметры `from` и `to` опциональны; по умолчанию последние 24 часа.  
  - Ответ:  
    ```json
    [
      { "timestamp": "2026-03-18T10:00:00Z", "value": 123.4 },
      ...
    ]
    ```  
- **Индексация:** создать индекс по `name` и `timestamp` для быстрых запросов.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Добавить функцию инициализации БД (создание таблицы) при старте.  
- Запустить фоновую задачу, которая каждые 60 секунд берёт текущие агрегаты и вставляет их в БД.  
- В эндпоинте `GET /history` выполнить SQL-запрос с фильтрацией и вернуть результат.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Через минуту после запуска в БД появляются записи метрик.  
- Запрос `/api/metrics/history/tasks_completed?from=...&to=...` возвращает корректный временной ряд.  
- При отсутствии данных возвращается пустой массив.  
- SQLite-файл создаётся и не растёт бесконтрольно (только агрегаты раз в минуту).
