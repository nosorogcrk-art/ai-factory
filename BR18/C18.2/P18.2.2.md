
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P18.2.2 (LEVEL 5)

**ID:** P18.2.2  
**Контейнер:** C18.2 (Metrics Dashboard)  
**Название:** Агрегация и вычисление метрик  

**Зависимости:** P18.2.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить логику расчёта агрегированных статистик (среднее, максимум, p95 и т.д.) по каждой метрике на основе накопленных сырых значений. Агрегаты вычисляются периодически (например, каждые 10 секунд) и хранятся в памяти для быстрого доступа через API.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Фоновый процесс:**  
  – Использовать `APScheduler` или `asyncio` для запуска задачи каждые `AGGREGATION_INTERVAL` секунд (по умолчанию 10).  
  – Задача перебирает все метрики, для каждой из последних значений (за окно, например, последние 5 минут или все доступные) вычисляет:  
    * среднее (mean)  
    * максимум (max)  
    * минимум (min)  
    * сумму (sum)  
    * 95-й перцентиль (p95) – при достаточном количестве точек  
  – Результаты сохраняются в отдельном словаре `aggregates`:  
    ```json
    {
      "metric_name": {
        "mean": 123.4,
        "max": 500,
        "min": 10,
        "sum": 12345,
        "p95": 450,
        "last_update": "ISO timestamp"
      }
    }
    ```  
- **Окно агрегации:** может быть задано конфигурацией (например, использовать все имеющиеся значения).  
- **Логирование:** ошибки агрегации записываются в локальный лог.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Добавить в приложение планировщик, который при старте запускает фоновую задачу.  
- В задаче получить доступ к хранилищу сырых метрик, для каждой вычислить агрегаты.  
- Для p95 можно использовать `numpy.percentile` или реализацию вручную.  
- Сохранить результаты в глобальной переменной.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- После запуска агрегаты вычисляются с заданной периодичностью.  
- При наличии данных для метрики агрегаты корректны (проверяется тестами).  
- При отсутствии значений для метрики агрегаты не вычисляются (или возвращаются нули).  
- Фоновая задача не мешает приёму новых метрик.
