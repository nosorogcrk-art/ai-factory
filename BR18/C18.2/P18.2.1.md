### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P18.2.1 (LEVEL 5)

**ID:** P18.2.1  
**Контейнер:** C18.2 (Metrics Dashboard)  
**Название:** Базовая структура и приём метрик  

**Зависимости:** отсутствуют

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Создать FastAPI-приложение, которое будет принимать метрики от различных компонентов системы через HTTP POST и сохранять их в оперативной памяти (кольцевой буфер) для последующей агрегации. Это фундамент для всего сервиса метрик.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Стек:** Python + FastAPI, Uvicorn.  
- **Порт:** 8094 (настраивается через переменную окружения `PORT`).  
- **Эндпоинт:**  
  - `POST /api/metrics` – принимает метрику в формате JSON.  
  - Обязательные поля:  
    - `name` (str) – название метрики (например, `tasks_completed`).  
    - `value` (float) – числовое значение.  
    - `timestamp` (str) – время в формате ISO 8601.  
    - `source` (str) – источник (например, `BR1`, `ГЕФЕСТ`).  
  - Опционально: `tags` (dict) – дополнительные теги.  
  - Валидация через Pydantic; при отсутствии обязательных полей возвращать 400.  
- **Хранение в памяти:**  
  – Для каждой метрики хранится кольцевой буфер (например, `collections.deque` с максимальным размером, скажем 1000 значений).  
  – Структура: `{ "metric_name": deque([(timestamp, value, tags), ...]) }`.  
  – При превышении лимита старые значения отбрасываются.  
- **Локальное логирование:** все успешные приёмы и ошибки записываются в файл `01_ЦЕХ/01_ЖУРНАЛЫ/metrics.log` (JSON Lines).  
- **Эндпоинт /health** – возвращает `{"status": "ok"}`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать файл `metrics_dashboard.py` с FastAPI-приложением.  
- Определить Pydantic-модель `MetricIn` с описанными полями.  
- В эндпоинте `POST /api/metrics` выполнить валидацию, добавить значение в соответствующий deque (создать, если нет).  
- Логировать каждый запрос (можно с помощью `logging`).  
- Добавить эндпоинт `/health`.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Приложение запускается на порту 8094.  
- При отправке корректной метрики на `/api/metrics` возвращается `200 OK`, значение сохраняется в памяти.  
- При отправке неполных данных возвращается 422 (или 400) с описанием ошибки.  
- Локальный лог-файл создаётся и содержит записи.  
- Эндпоинт `/health` отвечает `{"status": "ok"}`.
