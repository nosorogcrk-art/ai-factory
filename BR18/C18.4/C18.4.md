#### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ
Индексатор, который связывает логи и метрики с конкретными артефактами завода: патчами, задачами, агентами, ветками. Строит поисковый индекс для быстрого нахождения всех событий, относящихся к определённому контексту (например, «все логи по патчу P1.2.3»). Интегрируется с BR2 для обеспечения семантического поиска по естественно-языковым запросам (например, «покажи ошибки при использовании навыка SKILL-042»). Обеспечивает выполнение требований Traceability Gate (проверка связи патчей со смыслами) и предоставляет данные для аудита и отладки.

#### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **Источники данных:**  
  – **C18.1 (Log Aggregator):** все логи, поступающие от компонентов.  
  – **Реестр задач BR7:** информация о патчах и задачах (их ID, статусы, связи).  
  – **BR2 (Memory):** данные о документах и их связях (для семантического обогащения).  
  – **BR17 (Skills):** данные о навыках (для связывания с ними логов).  

- **Построение индекса:**  
  – При получении нового лога парсятся его поля, особенно `details`. Извлекаются идентификаторы патчей (`P1.2.3`), задач, агентов, навыков.  
  – Строится обратный индекс: для каждого ID хранится список ссылок на логи (с временными метками).  
  – Индекс хранится в高性能 БД (например, Elasticsearch, или для простоты – SQLite с полнотекстовым поиском).  

- **API для поиска:**  
  – `GET /api/trace/{entity_type}/{id}` – возвращает все логи, связанные с указанной сущностью (патч, задача, агент, навык).  
  – `GET /api/search?q=...` – семантический поиск по содержимому логов (с использованием BR2 для расширения запроса).  
  – `GET /api/gate/check/{patch_id}` – проверка для Traceability Gate: есть ли у патча связь со смыслом (через BR2).  

- **Интеграция с BR2:**  
  – При семантическом запросе текст запроса отправляется в C2.3 (Semantic Search) для получения списка релевантных документов/смыслов, а затем по этим смыслам ищутся логи.  

- **Логирование:**  
  – Все запросы к API и ошибки индексации отправляются в C18.1.

#### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8096):**  
  – Пример запроса: `GET /api/trace/patch/P1.2.3`  
    Ответ:  
    ```json
    {
      "entity_id": "P1.2.3",
      "logs": [
        { "timestamp": "...", "service": "C7.2", "event_type": "handover_completed", ... },
        { "timestamp": "...", "service": "C1.2", "event_type": "patch_created", ... }
      ]
    }
    ```  
  – `GET /api/search?q=ошибка+при+рефакторинге` – семантический поиск, возвращает логи.

- **Для внутреннего использования BR6 (Semantic Auditor) и BR1:** могут вызываться напрямую.

#### 4. ИНТЕГРАЦИИ

- **C18.1 (Log Aggregator):** получение потока логов (через подписку или периодическое чтение).  
- **BR7 (реестр задач):** получение данных о патчах.  
- **BR2 (Memory):** семантический поиск для обогащения запросов.  
- **BR6 (Semantic Auditor):** использует API для проверки traceability.  
- **BR1 (Мета-Мозг):** может запрашивать логи для анализа.
