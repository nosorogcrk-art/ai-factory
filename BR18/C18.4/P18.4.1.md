### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P18.4.1 (LEVEL 5)

**ID:** P18.4.1  
**Контейнер:** C18.4 (Traceability Index)  
**Название:** Базовая структура и приём логов  

**Зависимости:** отсутствуют

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Создать базовое FastAPI-приложение, которое будет принимать логи от Log Aggregator (C18.1) или других компонентов по HTTP и сохранять их в сыром виде для последующей индексации. На данном этапе индексация не выполняется – логи просто записываются в файл или в оперативную память для отладки. Это позволит отладить взаимодействие с источниками логов.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Стек:** Python + FastAPI, Uvicorn.  
- **Порт:** 8096 (настраивается через переменную окружения `PORT`).  
- **Эндпоинт:**  
  - `POST /api/logs` – принимает лог (один или массив) в формате, аналогичном C18.1 (объект с полями `timestamp`, `service`, `event_type`, `details`).  
  - Валидация: проверка наличия обязательных полей. При несоответствии – 400.  
- **Хранение:**  
  – Логи временно сохраняются в оперативной памяти (например, в список) для последующей обработки. Можно также записывать их в файл `raw_logs.jsonl` для отладки.  
  – На данном этапе никакого индексирования не происходит.  
- **Локальное логирование:** все операции записываются в `01_ЦЕХ/01_ЖУРНАЛЫ/traceability_index.log`.  
- **Эндпоинт /health** – возвращает `{"status": "ok"}`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать файл `traceability_index.py` с FastAPI-приложением.  
- Определить Pydantic-модель `LogEntry` (аналогично C18.1).  
- В эндпоинте `POST /api/logs` проверять входные данные, при успехе добавлять лог в глобальный список (или писать в файл).  
- Возвращать `202 Accepted`.  
- Добавить эндпоинт `/health`.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Приложение запускается на порту 8096.  
- При отправке корректного лога на `/api/logs` возвращается `202`, лог сохраняется в памяти (или файле).  
- При неверных данных – 400.  
- Локальный лог-файл содержит записи о полученных запросах.
