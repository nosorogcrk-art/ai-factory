
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P18.4.5 (LEVEL 5)

**ID:** P18.4.5  
**Контейнер:** C18.4 (Traceability Index)  
**Название:** Интеграция с реестром задач и навыков  

**Зависимости:** P18.4.4

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Обогатить индекс дополнительными данными из реестра задач (BR7) и хранилища навыков (BR17) для улучшения качества поиска и возможности фильтрации по статусам, версиям и т.д. Например, можно добавить в индекс информацию о том, активна ли задача, или версию навыка.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Источники данных:**  
  – BR7: API для получения информации о задаче (статус, название).  
  – BR17: API для получения метаданных навыка (название, версия, статус).  
- **Обогащение:**  
  – При добавлении лога, если в нём найдены ID задач/навыков, делать дополнительные запросы к соответствующим сервисам и сохранять полученные данные в отдельной таблице `entity_metadata`.  
  – Таблица `entity_metadata`: `entity_type`, `entity_id`, `metadata_json`, `last_updated`.  
  – Это позволит при поиске возвращать не только логи, но и актуальную информацию о сущности.  
- **Использование в API:**  
  – Эндпоинт `GET /api/trace/{type}/{id}` может опционально включать метаданные сущности (параметр `include_metadata=true`).  
  – При семантическом поиске также можно возвращать метаданные.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Добавить фоновую задачу, которая периодически обновляет метаданные для известных сущностей (или делать это синхронно при первом обнаружении).  
- В эндпоинте `GET /api/trace` при наличии параметра `include_metadata` выполнять запрос к `entity_metadata`.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При добавлении лога с ID задачи выполняется запрос к BR7, и метаданные сохраняются.  
- При запросе `GET /api/trace/patch/P1.2.3?include_metadata=true` возвращаются логи и метаданные задачи.  
- При недоступности BR7/BR17 метаданные не сохраняются, но процесс не ломается.
