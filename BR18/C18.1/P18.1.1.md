### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P18.1.1 (LEVEL 5)

**ID:** P18.1.1  
**Контейнер:** C18.1 (Log Aggregator)  
**Название:** Базовая структура и приём логов  

**Зависимости:** отсутствуют

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Создать базовое FastAPI-приложение, которое принимает логи от различных компонентов системы по HTTP, выполняет минимальную валидацию и сохраняет их в файловой системе в формате JSON Lines (по одной записи на строку). Это основа для централизованного сбора логов, которая в дальнейшем будет дополнена ротацией, пакетной обработкой и другими функциями.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Стек:** Python + FastAPI, Uvicorn.  
- **Порт:** 8093 (настраивается через переменную окружения `PORT`).  
- **Хранение:** логи сохраняются в директории `/data/logs` (монтируемый том). Имя файла: `logs-YYYY-MM-DD.jsonl` (например, `logs-2026-03-18.jsonl`). Если файл не существует, он создаётся при первой записи.  
- **Эндпоинт:**  
  - `POST /api/logs` – принимает один лог в формате JSON.  
  - Тело запроса должно содержать объект с обязательными полями: `timestamp` (строка в формате ISO 8601), `service` (строка), `event_type` (строка). Поле `details` (объект) – опционально, но рекомендуется.  
  - При несоответствии схемы возвращается `400 Bad Request` с описанием ошибки.  
  - При успешном приёме лог дописывается в текущий дневной файл (одна строка – один JSON).  
  - Ответ: `202 Accepted` (асинхронная обработка) или `200 OK` (после синхронной записи). Для простоты можно реализовать синхронно, но с учётом будущей асинхронности.  
- **Валидация:**  
  - Проверка наличия обязательных полей.  
  - Проверка формата `timestamp` (должен быть распознаваем `datetime.fromisoformat`).  
  - Остальные поля не проверяются (на данном этапе).  
- **Логирование собственных действий:**  
  - Запись в локальный лог-файл `01_ЦЕХ/01_ЖУРНАЛЫ/log_aggregator.log` информации о полученных запросах (количество, ошибки).  
- **Конфигурация:** через переменные окружения:  
  - `LOG_DIR` – директория для хранения логов (по умолчанию `/data/logs`).  
  - `MAX_LOG_SIZE` – не используется на этом этапе.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать файл `log_aggregator.py` с FastAPI-приложением.  
- Определить Pydantic-модель `LogEntry` с полями `timestamp`, `service`, `event_type`, `details` (опционально).  
- В эндпоинте `POST /api/logs` извлечь JSON, провалидировать, открыть файл в режиме добавления, записать JSON-строку и символ новой строки.  
- Для формирования имени файла использовать текущую дату.  
- Добавить эндпоинт `/health` для проверки работоспособности.  
- Настроить логирование через `logging`.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Приложение запускается на указанном порту.  
- При отправке корректного лога на `/api/logs` он появляется в файле `/data/logs/logs-YYYY-MM-DD.jsonl` одной строкой.  
- При отправке лога без обязательных полей возвращается 400.  
- При неверном формате timestamp – 400.  
- Локальный лог-файл содержит записи о каждом принятом логе и ошибках.  
- Эндпоинт `/health` возвращает `{"status": "ok"}`.
