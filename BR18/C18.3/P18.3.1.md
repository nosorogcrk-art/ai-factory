### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P18.3.1 (LEVEL 5)

**ID:** P18.3.1  
**Контейнер:** C18.3 (Alert Manager)  
**Название:** Базовая структура и хранение правил  

**Зависимости:** отсутствуют

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Создать базовое FastAPI-приложение для управления правилами оповещений. Реализовать CRUD-операции для правил, хранящихся в локальном JSON-файле. Это обеспечит возможность создания, просмотра, изменения и удаления правил через API, что в дальнейшем позволит интегрироваться с командной консолью (C4.3).

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Стек:** Python + FastAPI, Uvicorn.  
- **Порт:** 8095 (настраивается через переменную окружения `PORT`).  
- **Хранение правил:** файл `/data/alerts_rules.json` (монтируемый том). Если файл не существует, при старте создаётся с пустым массивом.  
- **Структура правила (JSON):**  
  ```json
  {
    "id": "string",              // уникальный идентификатор, генерируется автоматически
    "name": "string",            // название
    "description": "string",     // описание
    "condition": "string",       // условие, например "cpu_usage > 90"
    "channels": ["telegram"],    // список каналов уведомления
    "cooldown_minutes": 60,      // период тишины после срабатывания (в минутах)
    "created_at": "ISO 8601",    // дата создания
    "updated_at": "ISO 8601"     // дата последнего изменения
  }
  ```
- **API эндпоинты:**  
  - `GET /api/rules` – возвращает список всех правил.  
  - `POST /api/rules` – создаёт новое правило. Тело запроса содержит все поля, кроме `id`, `created_at`, `updated_at`. ID генерируется автоматически (например, UUID). Возвращает созданное правило.  
  - `GET /api/rules/{id}` – возвращает правило по ID или 404.  
  - `PUT /api/rules/{id}` – полностью заменяет правило.  
  - `DELETE /api/rules/{id}` – удаляет правило.  
  - `PATCH /api/rules/{id}` – (опционально) частичное обновление.  
- **Валидация:**  
  - Обязательные поля: `name`, `condition`, `channels` (не пустой массив).  
  - `channels` должен содержать только допустимые каналы (набор строк, например, `telegram`, `slack`, `email`, `webhook`).  
- **Логирование:** все действия записываются в локальный файл `01_ЦЕХ/01_ЖУРНАЛЫ/alert_manager.log`.  
- **Эндпоинт /health** – возвращает `{"status": "ok"}`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать файл `alert_manager.py` с FastAPI-приложением.  
- При старте загрузить правила из файла (если нет – инициализировать пустым списком).  
- Определить Pydantic-модели для входящих данных и ответов.  
- Реализовать эндпоинты с операциями чтения/записи файла.  
- Для генерации ID использовать `uuid.uuid4()`.  
- Добавить middleware для логирования запросов (или логировать вручную).  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Приложение запускается на порту 8095.  
- При `GET /api/rules` возвращается список (возможно пустой).  
- При `POST /api/rules` с корректными данными правило создаётся, возвращается с заполненными `id`, `created_at`, `updated_at`.  
- При `GET /api/rules/{id}` существующего правила возвращается его объект.  
- При `DELETE /api/rules/{id}` правило удаляется (файл обновляется).  
- При неверных данных возвращается 422.  
- Эндпоинт `/health` отвечает `{"status": "ok"}`.  
- Локальный лог содержит записи о всех операциях.
