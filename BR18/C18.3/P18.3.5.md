
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P18.3.5 (LEVEL 5)

**ID:** P18.3.5  
**Контейнер:** C18.3 (Alert Manager)  
**Название:** Логирование в BR18 и история алертов  

**Зависимости:** P18.3.4

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить отправку всех событий (срабатывания, ошибки) в центральный лог-агрегатор BR18 (C18.1) и реализовать эндпоинт для получения истории сработавших алертов. Это обеспечит централизованную наблюдаемость и возможность анализа.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Адрес BR18:** переменная окружения `BR18_URL` (по умолчанию `http://br18:8080/api/logs`).  
- **Формат лога:**  
  ```json
  {
    "timestamp": "ISO 8601",
    "service": "C18.3",
    "event_type": "alert_triggered",
    "details": {
      "rule_id": "cpu_high",
      "metric": "cpu_usage",
      "value": 95.2,
      "threshold": 90,
      "channels": ["telegram", "slack"],
      "success": true
    }
  }
  ```  
- **События для логирования:**  
  - Каждое срабатывание алерта (успешное или с ошибкой отправки).  
  - Изменения правил (создание, обновление, удаление) – опционально.  
- **История алертов:**  
  – Хранить срабатывания в локальной БД (SQLite) с полями: `timestamp`, `rule_id`, `value`, `channels`, `success`.  
  – Эндпоинт `GET /api/alerts/history` – возвращает последние N записей (по умолчанию 100).  
  – Опциональные параметры: `from`, `to`, `rule_id`.  
- **Асинхронность:** отправка логов в BR18 выполняется в фоновом режиме.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Добавить SQLite для хранения истории (таблица `alerts_history`).  
- При срабатывании алерта записывать событие в БД и отправлять лог в BR18.  
- Добавить эндпоинт `/api/alerts/history` с фильтрацией.  
- Обрабатывать ошибки отправки (не должны влиять на основную работу).  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При каждом срабатывании алерта запись появляется в БД истории.  
- В BR18 отправляется соответствующий лог.  
- Эндпоинт `/api/alerts/history` возвращает историю (можно проверить через curl).  
- При недоступности BR18 ошибка логируется локально.  
- Все параметры настраиваются через переменные окружения.
