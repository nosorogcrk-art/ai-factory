### **P1.2.1: Декомпозитор** (LEVEL 5)

**ID:** P1.2.1  
**Контейнер:** C1.2 (Patch Architect)  
**Название:** `decomposer.py` – разбиение крупных задач на атомарные патчи

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Создание скрипта, который принимает описание стратегической задачи (например, «улучшить систему логирования», «оптимизировать промпты Гефеста») и разбивает её на атомарные патчи уровня L4. Каждый патч изменяет не более 5 файлов и имеет чёткие границы. Результат записывается в реестр задач (`task_registry.json`) для дальнейшей обработки.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ
- **Входные данные:** JSON-объект, содержащий:
  - `task_id` (строка, опционально) – идентификатор исходной задачи (если уже существует).
  - `description` (строка) – описание крупной задачи.
  - `context` (словарь) – дополнительные параметры (например, целевые компоненты).
- **Выходные данные:** JSON-объект со списком созданных патчей (их ID).
- **Алгоритм:**
  1. Загружает текущий реестр задач из `01_ЦЕХ/ТЕКУЩИЕ_ЗАДАЧИ/task_registry.json`.
  2. Анализирует описание задачи (возможно, с помощью простых правил или регулярных выражений) и генерирует список подзадач.
  3. Для каждой подзадачи создаёт запись в реестре с полями:
     - `id` – уникальный идентификатор (например, `IMP-<дата>-<номер>`).
     - `title` – краткое название.
     - `description` – подробное описание.
     - `status` – `NEW`.
     - `assigned_to` – `null`.
     - `created_at` – текущая дата.
     - `updated_at` – текущая дата.
     - `history` – пустой массив.
     - `type` – `improvement` (тип задачи – улучшение завода).
  4. Сохраняет обновлённый реестр.
  5. Возвращает список ID созданных патчей.
- **Логирование:** записывает действия в `01_ЦЕХ/01_ЖУРНАЛЫ/decomposer.log`.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД)

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-

"""
decomposer.py – разбиение крупных задач на атомарные патчи.
"""

import json
import sys
import logging
from pathlib import Path
from datetime import datetime

TASK_REGISTRY_PATH = Path("01_ЦЕХ/ТЕКУЩИЕ_ЗАДАЧИ/task_registry.json")
LOG_FILE = Path("01_ЦЕХ/01_ЖУРНАЛЫ/decomposer.log")
LOG_FILE.parent.mkdir(parents=True, exist_ok=True)

logging.basicConfig(filename=LOG_FILE, level=logging.INFO,
                    format='%(asctime)s - %(levelname)s - %(message)s')

def load_registry():
    if not TASK_REGISTRY_PATH.exists():
        return []
    with open(TASK_REGISTRY_PATH, "r", encoding="utf-8") as f:
        return json.load(f)

def save_registry(registry):
    with open(TASK_REGISTRY_PATH, "w", encoding="utf-8") as f:
        json.dump(registry, f, indent=2, ensure_ascii=False)

def generate_patches(description, context):
    """
    Генератор подзадач на основе описания.
    Здесь можно использовать более сложную логику (например, обращение к LLM),
    но в первой версии используем шаблонные правила.
    """
    patches = []
    # Пример: разбиваем по ключевым словам
    if "логирование" in description.lower():
        patches.append({
            "title": "Улучшить формат логов",
            "description": "Добавить временные метки и уровни логирования во все скрипты агентов."
        })
        patches.append({
            "title": "Добавить ротацию логов",
            "description": "Настроить автоматическое удаление старых логов."
        })
    elif "промпт" in description.lower():
        patches.append({
            "title": "Оптимизировать промпт Гефеста",
            "description": "Улучшить инструкции для агента Гефест, добавить примеры."
        })
    else:
        # Если ничего не подошло, создаём один общий патч
        patches.append({
            "title": f"Реализовать: {description[:50]}...",
            "description": description
        })
    return patches

def main():
    data = json.load(sys.stdin)
    description = data.get("description", "")
    context = data.get("context", {})

    registry = load_registry()
    patches = generate_patches(description, context)

    created_ids = []
    for patch in patches:
        # Генерируем ID (IMP-20250317-001)
        date_str = datetime.now().strftime("%Y%m%d")
        # Подсчитываем уже существующие задачи с таким префиксом
        count = sum(1 for t in registry if t["id"].startswith(f"IMP-{date_str}"))
        new_id = f"IMP-{date_str}-{count+1:03d}"
        task = {
            "id": new_id,
            "title": patch["title"],
            "description": patch["description"],
            "status": "NEW",
            "assigned_to": None,
            "created_at": datetime.now().isoformat(),
            "updated_at": datetime.now().isoformat(),
            "history": [],
            "type": "improvement"
        }
        registry.append(task)
        created_ids.append(new_id)
        logging.info(f"Created patch {new_id}: {patch['title']}")

    save_registry(registry)
    result = {"created_patches": created_ids}
    print(json.dumps(result, ensure_ascii=False, indent=2))

if __name__ == "__main__":
    main()
```

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)
- Скрипт `decomposer.py` создан и размещён в `agents/tools/`.
- При подаче JSON-описания на stdin в реестр добавляются новые задачи с типом `improvement`.
- Логирование ведётся.
- Скрипт не ломается при отсутствии реестра (создаёт новый).
- Созданные задачи имеют корректные ID и поля.

### **P1.2.2: Генератор зависимостей** (LEVEL 5)

**ID:** P1.2.2  
**Контейнер:** C1.2 (Patch Architect)  
**Название:** `dependency_gen.py` – определение зависимостей между патчами

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Скрипт анализирует новые и существующие патчи, выявляет зависимости между ними (например, один патч требует наличия другого) и обновляет файл графа зависимостей `GRAPH_DEPENDENCIES.json`. Зависимости могут определяться на основе общих файлов, ключевых слов или явных указаний.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ
- **Зависимости:** P1.2.1 (созданные патчи), существующий реестр задач.
- **Входные данные:** (опционально) список ID патчей, для которых нужно обновить зависимости.
- **Выходные данные:** обновлённый файл `00_ПАМЯТЬ/ГРАФЫ/GRAPH_DEPENDENCIES.json` (структура: `{ "nodes": [...], "edges": [{"from": "id1", "to": "id2"}] }`).
- **Алгоритм:**
  1. Загружает реестр задач.
  2. Загружает текущий граф зависимостей (если есть).
  3. Для каждого патча извлекает из описания упоминания других патчей (например, `P1.2.1`). Для простоты ищем паттерны вида `[A-Z][0-9.]+`.
  4. Если найден ID существующего патча, добавляет ребро зависимости (от текущего к найденному).
  5. Сохраняет обновлённый граф.
- **Логирование:** в `01_ЦЕХ/01_ЖУРНАЛЫ/dependency_gen.log`.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД)

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-

"""
dependency_gen.py – автоматическое определение зависимостей между патчами.
"""

import json
import re
import sys
import logging
from pathlib import Path

TASK_REGISTRY_PATH = Path("01_ЦЕХ/ТЕКУЩИЕ_ЗАДАЧИ/task_registry.json")
GRAPH_PATH = Path("00_ПАМЯТЬ/ГРАФЫ/GRAPH_DEPENDENCIES.json")
LOG_FILE = Path("01_ЦЕХ/01_ЖУРНАЛЫ/dependency_gen.log")

LOG_FILE.parent.mkdir(parents=True, exist_ok=True)
GRAPH_PATH.parent.mkdir(parents=True, exist_ok=True)

logging.basicConfig(filename=LOG_FILE, level=logging.INFO,
                    format='%(asctime)s - %(levelname)s - %(message)s')

def load_json(path, default=None):
    if path.exists():
        with open(path, "r", encoding="utf-8") as f:
            return json.load(f)
    return default if default is not None else {}

def save_json(path, data):
    with open(path, "w", encoding="utf-8") as f:
        json.dump(data, f, indent=2, ensure_ascii=False)

def extract_ids(text):
    """Извлекает из текста все подстроки, похожие на ID патчей (например, IMP-20250317-001)."""
    pattern = r'\b(?:IMP-\d{8}-\d{3}|P\d+\.\d+\.\d+)\b'
    return re.findall(pattern, text)

def main():
    registry = load_json(TASK_REGISTRY_PATH, [])
    graph = load_json(GRAPH_PATH, {"nodes": [], "edges": []})

    # Собираем все существующие ID
    existing_ids = {task["id"] for task in registry if "id" in task}

    # Добавляем все ID как узлы (если их нет)
    for task in registry:
        tid = task["id"]
        if tid not in [n["id"] for n in graph["nodes"]]:
            graph["nodes"].append({"id": tid, "label": task.get("title", tid), "type": "patch"})

    # Сканируем описания задач на наличие ссылок
    for task in registry:
        from_id = task["id"]
        text = task.get("description", "") + " " + task.get("title", "")
        found_ids = extract_ids(text)
        for to_id in found_ids:
            if to_id in existing_ids and to_id != from_id:
                # Проверяем, не существует ли уже такое ребро
                edge_exists = any(e["from"] == from_id and e["to"] == to_id for e in graph["edges"])
                if not edge_exists:
                    graph["edges"].append({"from": from_id, "to": to_id})
                    logging.info(f"Added dependency: {from_id} -> {to_id}")

    save_json(GRAPH_PATH, graph)
    print(json.dumps({"status": "ok", "edges_added": len(graph["edges"])}))

if __name__ == "__main__":
    main()
```

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)
- Скрипт `dependency_gen.py` создан и может быть запущен без аргументов.
- При наличии в описаниях задач ссылок на другие патчи в граф добавляются соответствующие рёбра.
- Узлы создаются для всех задач.
- Логирование ведётся.
- Граф сохраняется в указанном формате.

### **P1.2.3: Создатель спецификаций** (LEVEL 5)

**ID:** P1.2.3  
**Контейнер:** C1.2 (Patch Architect)  
**Название:** `spec_generator.py` – генерация спецификаций L5 для патчей

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Для каждого нового патча, созданного декомпозитором (P1.2.1), скрипт генерирует файл спецификации уровня L5 на основе соответствующего шаблона из методологии (BR3, C3.1). Спецификация заполняется данными из описания патча и сохраняется в директорию `01_ЦЕХ/ЧЕРНОВИКИ/СПЕКИ/`.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ
- **Зависимости:** P1.2.1 (патчи), P3.1.1 (шаблоны спецификаций).
- **Входные данные:** (опционально) список ID патчей, для которых нужно создать спецификации. Если не указан, обрабатываются все патчи с типом `improvement`, у которых ещё нет спецификации.
- **Выходные данные:** файлы спецификаций в папке `01_ЦЕХ/ЧЕРНОВИКИ/СПЕКИ/` с именами `<ID патча>.md`.
- **Алгоритм:**
  1. Загружает реестр задач.
  2. Определяет, для каких патчей нужно создать спецификацию.
  3. Для каждого такого патча загружает шаблон L5 (например, `ШАБЛОН_L5.md` из `00_КАНОН/Методология/ШАБЛОНЫ/`).
  4. Заменяет в шаблоне плейсхолдеры (например, `{{PATCH_ID}}`, `{{TITLE}}`, `{{DESCRIPTION}}`) на данные из задачи.
  5. Сохраняет результат в файл.
- **Логирование:** в `01_ЦЕХ/01_ЖУРНАЛЫ/spec_generator.log`.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД)

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-

"""
spec_generator.py – генерация спецификаций L5 для патчей.
"""

import json
import sys
import logging
from pathlib import Path

TASK_REGISTRY_PATH = Path("01_ЦЕХ/ТЕКУЩИЕ_ЗАДАЧИ/task_registry.json")
TEMPLATE_PATH = Path("00_КАНОН/Методология/ШАБЛОНЫ/ШАБЛОН_L5.md")
SPEC_DIR = Path("01_ЦЕХ/ЧЕРНОВИКИ/СПЕКИ/")
LOG_FILE = Path("01_ЦЕХ/01_ЖУРНАЛЫ/spec_generator.log")

SPEC_DIR.mkdir(parents=True, exist_ok=True)
LOG_FILE.parent.mkdir(parents=True, exist_ok=True)

logging.basicConfig(filename=LOG_FILE, level=logging.INFO,
                    format='%(asctime)s - %(levelname)s - %(message)s')

def load_template():
    if not TEMPLATE_PATH.exists():
        # Заглушка, если шаблона нет – создаём минимальный
        return """# СПЕЦИФИКАЦИЯ ПАТЧА {{PATCH_ID}}

## 1. ЗАМЫСЕЛ
{{DESCRIPTION}}

## 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ
*Будут уточнены в процессе реализации.*

## 3. РЕАЛИЗАЦИЯ
*Код и описание изменений.*

## 4. КРИТЕРИЙ ПРИЕМКИ (DoD)
*Условия завершения патча.*

## 5. ИСТОРИЯ ИЗМЕНЕНИЙ
- {{DATE}}: Создана спецификация.
"""
    with open(TEMPLATE_PATH, "r", encoding="utf-8") as f:
        return f.read()

def generate_spec(task, template):
    from datetime import datetime
    content = template.replace("{{PATCH_ID}}", task["id"])
    content = content.replace("{{TITLE}}", task.get("title", ""))
    content = content.replace("{{DESCRIPTION}}", task.get("description", ""))
    content = content.replace("{{DATE}}", datetime.now().strftime("%Y-%m-%d"))
    return content

def main():
    registry = load_json(TASK_REGISTRY_PATH, [])
    template = load_template()

    # Определяем, какие патчи обрабатывать
    target_ids = sys.argv[1:] if len(sys.argv) > 1 else None

    for task in registry:
        if task.get("type") != "improvement":
            continue
        if target_ids and task["id"] not in target_ids:
            continue
        spec_file = SPEC_DIR / f"{task['id']}.md"
        if spec_file.exists():
            logging.info(f"Spec for {task['id']} already exists, skipping.")
            continue
        spec_content = generate_spec(task, template)
        with open(spec_file, "w", encoding="utf-8") as f:
            f.write(spec_content)
        logging.info(f"Generated spec for {task['id']}")

def load_json(path, default):
    if path.exists():
        with open(path, "r", encoding="utf-8") as f:
            return json.load(f)
    return default

if __name__ == "__main__":
    main()
```

- Спецификации сохраняются в правильной папке.
