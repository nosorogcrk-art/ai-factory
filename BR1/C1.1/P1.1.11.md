### 1. Цель

При анализе проблем и генерации гипотез Дедал должен использовать **векторную память завода (C2.6)** для поиска релевантных артефактов (паспортов, спецификаций, ранее найденных решений, лучших практик). Это позволит:

- Находить аналогичные проблемы и готовые решения из истории.
- Повышать качество гипотез за счёт доказательной базы.
- Сокращать дублирование работы.

Реализовать вызов `POST /search` к C2.6 в процессе работы метода `analyze_logs` и при формировании гипотез.

#### 3.2. Формат вызова C2.6

- **Метод:** POST
- **Путь:** `/search`
- **Заголовки:** `Content-Type: application/json`
- **Тело:**
  ```json
  {
    "query": "текст проблемы или ошибки",
    "limit": 5
  }
  ```
- **Ответ (200):**
  ```json
  {
    "results": [
      {
        "path": "/data/BR1/C1.1/C1.1.md",
        "score": 0.85,
        "snippet": "Первые 200 символов содержимого",
        "metadata": {"type": "markdown", "filename": "C1.1.md"}
      }
    ]
  }
  ```

#### 3.3. Логика интеграции

1. В методе `analyze_logs` после сбора ошибок (или внутри генерации гипотез) для каждой выявленной проблемы (например, «контейнер C20.3 часто падает») выполнять поиск в C2.6.
2. Формировать поисковый запрос из описания проблемы (например, `f"{error_type} {container} {error_message}"`).
3. Выполнять асинхронный HTTP-запрос к C2.6 (через `httpx.AsyncClient`).
4. Полученные результаты (первые 1–3 с высоким `score`) добавлять в отчёт как `evidence` (доказательства) для гипотезы.
5. Если поиск не дал результатов или C2.6 недоступен – не прерывать анализ, просто логировать предупреждение.

### 4. Детальные требования

#### 4.1. Добавить в `services.py` метод `_search_memory(query: str) -> List[dict]`

- Выполняет POST-запрос к `{self.project_memory_url}/search`.
- Возвращает список результатов (пустой при ошибке).
- Логирует ошибки (но не прерывает).

#### 4.2. В методе `analyze_logs` после выявления ошибок (например, после формирования `error_types` и `containers_with_issues`)

- Для каждого типа ошибки (например, `timeout`) выполнить поиск.
- Для каждого контейнера с проблемами выполнить поиск.
- Результаты агрегировать и добавить в отчёт.

Пример:

```python
evidence_by_hypothesis = {}
for error_type, count in error_types.items():
    if count > 5:
        query = f"ошибка {error_type} в контейнерах завода"
        results = await self._search_memory(query)
        if results:
            evidence_by_hypothesis[error_type] = results[:2]
```

Затем при формировании гипотез добавить в рекомендации ссылки.

#### 4.3. Обработка ошибок

- Если `PROJECT_MEMORY_URL` не задан или C2.6 недоступен – пропустить поиск, логировать WARNING.
- Таймаут запроса – 5 секунд.
