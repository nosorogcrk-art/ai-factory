### 1. Цель

Дедал должен учитывать результаты проверок Ревы (C6.2) при анализе системы и генерации гипотез. Если Рева обнаружила нарушения в контейнерах, паспортах, спецификациях или коде, Дедал должен:

- Повышать приоритет гипотез, связанных с этими нарушениями.
- Включать в отчёт ссылки на отчёты Ревы.
- Предлагать решения, направленные на устранение конкретных нарушений.

Это замкнёт цикл: Рева находит проблему → Дедал предлагает улучшение → Cline/Гефест исправляет → Рева проверяет снова.

### 3. Технические параметры

#### 3.1. Источник данных об отчётах Ревы

На первом этапе – **заглушка**, читающая локальный файл `01_ЦЕХ/01_ЖУРНАЛЫ/reva_reports.json`. В будущем заменится на реальный вызов API C6.2 или чтение из BR18.

**Формат записи в файле (JSON Lines, каждая строка – один отчёт):**
```json
{"timestamp": "2026-04-05T10:00:00Z", "service": "C6.2", "event_type": "review_completed", "details": {"target": "BR1/C1.1/C1.1.md", "status": "rework", "violations": [{"rule": "has_tests", "message": "No tests found", "severity": "error"}], "suggestions": ["Add pytest tests"]}}
```

#### 3.2. Переменные окружения

| Переменная | Значение по умолчанию | Описание |
|------------|----------------------|-----------|
| `REVA_REPORTS_PATH` | `01_ЦЕХ/01_ЖУРНАЛЫ/reva_reports.json` | Путь к файлу с отчётами Ревы (для заглушки) |
| `USE_REVA_STUB` | `true` | Использовать заглушку |

#### 3.3. Логика интеграции

1. В методе `analyze_logs` после сбора ошибок, перед генерацией гипотез, вызвать `_fetch_reva_reports(period_hours)`.
2. Для каждого отчёта:
   - Извлечь `target` (файл или контейнер), `violations`, `suggestions`.
   - Сохранить в поле `reva_feedback` отчёта Дедала.
   - При формировании гипотез (в `_generate_hypotheses_from_errors`) учитывать эти данные: если есть нарушения с `severity = "error"`, создавать гипотезу с `priority = "high"`.
3. Добавить в `AnalysisReport` поле `reva_feedback: List[dict]`.

### 4. Детальные требования

#### 4.1. В `services.py` добавить метод `_fetch_reva_reports(period_hours: int) -> List[dict]`

- Если `USE_REVA_STUB == true`, читать файл `REVA_REPORTS_PATH`, фильтровать записи за последние `period_hours` (по полю `timestamp`), возвращать список.
- Если заглушка выключена – пока возвращать пустой список (в будущем – HTTP-запрос).
- При ошибках (файл не найден, некорректный JSON) – логировать WARNING и возвращать пустой список.

#### 4.2. В `models.py` дополнить `AnalysisReport`

```python
class AnalysisReport(BaseModel):
    # ... существующие поля ...
    reva_feedback: List[dict] = []
```

#### 4.3. В методе `analyze_logs`:

```python
reva_reports = await self._fetch_reva_reports(period_hours)
# ... формирование отчёта ...
report.reva_feedback = reva_reports
```

#### 4.4. В методе `_generate_hypotheses_from_errors` (если он выделен, иначе внутри `analyze_logs`):

- Для каждого отчёта Ревы с `severity = "error"` добавить гипотезу: «Исправить нарушение в {target}: {violation.message}» с приоритетом `high`.
- Добавить в `recommendations` предложения из `suggestions`.
