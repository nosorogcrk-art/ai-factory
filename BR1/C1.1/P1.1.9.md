### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P1.1.9 (LEVEL 5)

**ID:** P1.1.9  
**Контейнер:** C1.1 (Cognitive Engine)  
**Название:** Заменить заглушки на реальные вызовы BR18 и BR19  

**Зависимости:** P18.2.3 (API метрик C18.2), P19.2.5 (API Prompt Optimizer C19.2)

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
В предыдущих патчах (P1.1.5, P1.1.8) были созданы заглушки для взаимодействия с BR18 и BR19. Теперь, когда соответствующие сервисы реализованы и предоставляют полноценные API, необходимо заменить эти заглушки на реальные вызовы. Cognitive Engine должен получать актуальные метрики из C18.2 (Metrics Dashboard) и улучшенные версии промптов/гипотез из C19.2 (Prompt Optimizer). Это обеспечит работу механизмов анализа и самообучения на реальных данных.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Модифицируемые файлы:**  
  – `cognitive_engine.py` (или аналогичный, содержащий логику сбора и анализа)  
  – Возможно, отдельные модули, где были заглушки (например, `metric_collector_br18.py`, `hypothesis_generator_br19.py`).  
- **Интеграция с C18.2 (Metrics Dashboard):**  
  – Адрес C18.2 задаётся переменной окружения `METRICS_DASHBOARD_URL` (по умолчанию `http://c18.2:8094`).  
  – Используется эндпоинт `GET /api/metrics` для получения текущих агрегированных метрик.  
  – Для получения исторических данных (если требуется) – `GET /api/metrics/history/{name}`.  
  – Заглушка, которая ранее возвращала фиктивные данные, заменяется на реальный HTTP-запрос с обработкой ошибок.  
- **Интеграция с C19.2 (Prompt Optimizer):**  
  – Адрес C19.2 задаётся переменной `PROMPT_OPTIMIZER_URL` (по умолчанию `http://c19.2:8102`).  
  – Предполагается, что после P19.2.5 Prompt Optimizer предоставляет API для получения сгенерированных кандидатов (например, `GET /candidates?prompt_id=...`) и, возможно, для отправки запроса на оптимизацию.  
  – Cognitive Engine может:  
    * Запрашивать список доступных кандидатов для конкретного промпта.  
    * Отправлять запрос на создание новой оптимизации (если нужно).  
  – В зависимости от архитектуры, замена заглушки может означать вызов API для получения уже готовых улучшений.  
- **Асинхронность:** все вызовы должны выполняться асинхронно, чтобы не блокировать основной цикл Cognitive Engine. Использовать `httpx.AsyncClient`.  
- **Обработка ошибок:**  
  – При недоступности сервисов логировать предупреждение и продолжать работу с последними известными данными (или с пустыми).  
  – Таймауты (например, 5 секунд) должны быть настроены.  
- **Логирование:**  
  – Успешные вызовы и ошибки записываются в `cognitive_engine.log`.  
  – Также, если возможно, отправлять логи в BR18 (через механизм, реализованный ранее).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В модуле сбора метрик заменить вызов заглушки на асинхронный запрос к `METRICS_DASHBOARD_URL/api/metrics`.  
- В модуле работы с гипотезами заменить заглушку на запрос к `PROMPT_OPTIMIZER_URL/candidates` с необходимыми параметрами.  
- Добавить обработку исключений и повторные попытки (опционально).  
- Интегрировать полученные данные в общий поток обработки Cognitive Engine.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При запуске Cognitive Engine выполняются реальные запросы к C18.2 и C19.2.  
- Полученные метрики корректно используются в анализе.  
- Полученные кандидаты промптов обрабатываются (например, передаются в генератор гипотез).  
- При недоступности сервисов логируются ошибки, но система продолжает работу (с использованием старых данных или в ограниченном режиме).  
- Все вызовы асинхронны и не блокируют основной поток.
