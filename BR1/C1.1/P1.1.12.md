### 1. Цель

Добавить в API Дедала два новых эндпоинта:

- `POST /hypothesis/{hypothesis_id}/approve` – утвердить гипотезу и создать задачу в handover.
- `POST /hypothesis/{hypothesis_id}/reject` – отклонить гипотезу с указанием причины.

Это позволит вам (или CEO-агенту) управлять гипотезами, которые Дедал генерирует ежедневно. Утверждённые гипотезы автоматически превращаются в задачи для Cline (или Гефеста). Отклонённые сохраняются с комментарием для истории и анализа.

### 4. Логика работы

#### 4.1. Утверждение гипотезы (`/approve`)

1. Проверить, что гипотеза с указанным ID существует в `self.hypothesis_tasks` (или в БД, если будет реализовано хранилище). Пока гипотезы хранятся в памяти, но это допустимо на этапе MVP.
2. Проверить, что статус гипотезы – `pending` (не утверждена и не отклонена ранее). Если нет – вернуть 409 Conflict.
3. Вызвать метод `create_hypothesis_task` (который уже реализован и вызывает handover через P1.1.10) с теми же параметрами (гипотеза, приоритет, related_containers). Если задача уже создавалась ранее (handover_task_id уже есть), то не создавать повторно, а вернуть существующий ID.
4. Обновить статус гипотезы на `approved`, сохранить `handover_task_id`.
5. Вернуть ответ с `handover_task_id`.

#### 4.2. Отклонение гипотезы (`/reject`)

1. Проверить существование гипотезы.
2. Проверить, что статус `pending`.
3. Обновить статус на `rejected`, сохранить причину (`reason`).
4. Логировать событие.
5. Вернуть ответ.

### 5. Детальные требования

#### 5.1. Модели Pydantic (добавить в `models.py`)

```python
class ApproveRequest(BaseModel):
    comment: Optional[str] = None

class RejectRequest(BaseModel):
    reason: str

class ApproveResponse(BaseModel):
    status: str
    handover_task_id: str

class RejectResponse(BaseModel):
    status: str
    reason: str
```

#### 5.2. Доработка `services.py`

- В классе `CognitiveEngineService` добавить методы:
  - `async def approve_hypothesis(self, hypothesis_id: str, comment: str = None) -> dict`
  - `async def reject_hypothesis(self, hypothesis_id: str, reason: str) -> dict`
- Метод `approve_hypothesis` должен:
  - Найти гипотезу в `self.hypothesis_tasks`.
  - Если статус не `pending` – вернуть ошибку.
  - Если `handover_task_id` уже есть – вернуть его (не создавать повторно).
  - Если нет – вызвать `self.create_hypothesis_task` с теми же параметрами (текст, приоритет, related_containers). Обратить внимание: `create_hypothesis_task` уже создаёт задачу в handover и возвращает объект `HypothesisTask`. Нужно извлечь `handover_task_id` и обновить существующую запись.
  - Обновить статус гипотезы на `approved`.
  - Логировать в BR18.
  - Вернуть `{"handover_task_id": ..., "status": "approved"}`.
- Метод `reject_hypothesis`:
  - Найти гипотезу.
  - Если статус не `pending` – ошибка.
  - Обновить статус на `rejected`, сохранить `reason` (добавить поле `rejection_reason` в модель `HypothesisTask`).
  - Логировать.
  - Вернуть `{"status": "rejected", "reason": reason}`.

#### 5.3. Добавить эндпоинты в `main.py`

```python
@app.post("/hypothesis/{hypothesis_id}/approve", response_model=dict)
async def approve_hypothesis(hypothesis_id: str, req: ApproveRequest):
    result = await cognitive_service.approve_hypothesis(hypothesis_id, req.comment)
    return result

@app.post("/hypothesis/{hypothesis_id}/reject", response_model=dict)
async def reject_hypothesis(hypothesis_id: str, req: RejectRequest):
    result = await cognitive_service.reject_hypothesis(hypothesis_id, req.reason)
    return result
```

#### 5.4. Логирование

- При approve: отправить событие в BR18 с типом `hypothesis_approved`, детали: `hypothesis_id`, `handover_task_id`, `comment`.
- При reject: событие `hypothesis_rejected`, детали: `hypothesis_id`, `reason`.

Использовать существующую заглушку `send_log_to_br18` (пока локально, но позже будет реальная отправка).

#### 5.5. Обработка ошибок

- Гипотеза не найдена → 404.
- Статус не `pending` → 409 Conflict с сообщением "Hypothesis already approved/rejected".
- Ошибка при создании задачи в handover (например, handover недоступен) → 500 Internal Server Error, гипотеза остаётся `pending`, но ошибка логируется.
