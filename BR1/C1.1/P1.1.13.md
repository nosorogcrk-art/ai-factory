### 1. Цель

Добавить в Дедала внутренний планировщик, который автоматически запускает анализ логов и метрик (вызов `/analyze`) раз в сутки в заданное время (например, в 8:00 утра). Результаты (отчёты с гипотезами) сохраняются в файловую систему и становятся доступными через API. Планировщик должен работать в фоновом режиме, не блокируя основной HTTP-сервер.

Это позволит вам ежедневно получать свежие гипотезы без ручного запуска.

### 3. Технические параметры

#### 3.1. Время запуска

- По умолчанию – 8:00 утра по местному времени сервера (можно настроить через переменную окружения `DAILY_ANALYSIS_HOUR`).
- Первый запуск – при старте контейнера (если текущее время > 8:00, то запустить сразу, иначе дождаться).

#### 3.2. Реализация планировщика

- Использовать `asyncio.create_task` с бесконечным циклом и `asyncio.sleep`.
- В цикле: вычислить время до следующего запуска (8:00 следующего дня), заснуть, затем выполнить `analyze_logs` с параметрами по умолчанию (`period_hours=24`).
- Сохранять отчёт в папку `01_ЦЕХ/МЕТРИКИ/daedalus_reports/` с именем `report_YYYYMMDD.json`.
- Логировать каждый автоматический запуск (в локальный лог и BR18).

#### 3.3. Настройки через переменные окружения

| Переменная | Значение по умолчанию | Описание |
|------------|----------------------|-----------|
| `DAILY_ANALYSIS_HOUR` | `8` | Час запуска (0–23) |
| `DAILY_ANALYSIS_ENABLED` | `true` | Включить/отключить планировщик |
| `REPORTS_DIR` | `01_ЦЕХ/МЕТРИКИ/daedalus_reports` | Папка для хранения отчётов |

#### 3.4. Формат имени файла отчёта

- `report_YYYYMMDD_HHMMSS.json` (например, `report_20260405_080000.json`).

#### 3.5. Содержание отчёта

- Полный JSON-отчёт, который возвращает `/analyze` (тот же `AnalysisReport`).
- Дополнительно добавить поле `scheduled: true` и `scheduled_at` (время запуска).

### 4. Детальные требования

#### 4.1. В `services.py` добавить метод `run_daily_analysis()`

- Вызывает `self.analyze_logs(period_hours=24, container_filter=None)`.
- Сохраняет результат в файл (используя `self._save_report_to_file(report)`).
- Логирует успех/ошибку.
- Возвращает `report_id` (имя файла).

#### 4.2. В `main.py` при старте приложения (lifespan)

- Если `DAILY_ANALYSIS_ENABLED == true`, запустить фоновую задачу `_scheduler_loop()`.
- В `_scheduler_loop`:
  - Вычислить время до следующего запуска.
  - Подождать.
  - Вызвать `cognitive_service.run_daily_analysis()`.
  - Повторить.

#### 4.3. Сохранение отчётов в файловую систему

- Создавать папку `REPORTS_DIR`, если её нет.
- Использовать `json.dump` для сохранения.
- Имя файла: `report_{datetime.now().strftime("%Y%m%d_%H%M%S")}.json`.

#### 4.4. Логирование

- При запуске планировщика: `INFO: Daily analysis scheduler started, next run at {next_run_time}`.
- При выполнении анализа: `INFO: Running scheduled daily analysis`.
- При ошибке: `ERROR: Scheduled analysis failed: {error}`.
- Отправлять события в BR18 (через заглушку) с типами `daily_analysis_started`, `daily_analysis_completed`, `daily_analysis_failed`.
