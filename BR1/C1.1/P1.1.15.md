### 1. Цель

Дедал должен использовать **GitHub API** для поиска популярных репозиториев, соответствующих выявленным проблемам (ошибки, архитектурные паттерны, лучшие практики). Найденные примеры добавляются в отчёт как `evidence` (доказательства) для генерируемых гипотез, что повышает обоснованность предложений и позволяет использовать проверенные решения из открытых источников.

### 3. Технические параметры

#### 3.1. Переменные окружения (добавить в `docker-compose.yml` для C1.1)

| Переменная | Значение по умолчанию | Описание |
|------------|----------------------|-----------|
| `GITHUB_TOKEN` | (пусто) | Персональный токен GitHub для увеличения лимита запросов (опционально) |
| `GITHUB_API_ENABLED` | `true` | Включить/выключить поиск на GitHub |

#### 3.2. Формат вызова GitHub API

- **Метод:** GET
- **URL:** `https://api.github.com/search/repositories?q={query}&sort=stars&order=desc&per_page=3`
- **Заголовки:** `Authorization: token {GITHUB_TOKEN}` (если токен задан), `Accept: application/vnd.github.v3+json`
- **Ответ (200):**
  ```json
  {
    "total_count": 123,
    "items": [
      {
        "name": "repo-name",
        "full_name": "user/repo-name",
        "html_url": "https://github.com/user/repo-name",
        "description": "Описание репозитория",
        "stargazers_count": 5000,
        "language": "Python"
      }
    ]
  }
  ```

#### 3.3. Формирование поискового запроса (`query`)

Поисковый запрос формируется на основе выявленных проблем и ошибок. Примеры:

- Для ошибки `timeout` в контейнере `C20.3`: `docker healthcheck timeout best practices`
- Для ошибки `connection_error`: `httpx retry async best practices`
- Для нарушений стандартов: `fastapi pytest best practices`

В методе `analyze_logs` после сбора ошибок (или внутри генерации гипотез) для каждой значимой проблемы (частота > 5, приоритет high) выполнять поиск на GitHub.

#### 3.4. Логика работы

1. В `services.py` добавить метод `_search_github(query: str, limit: int = 3) -> List[dict]`.
2. Если `GITHUB_API_ENABLED == false` – возвращать пустой список.
3. Выполнять асинхронный GET-запрос через `httpx.AsyncClient` (уже используется в сервисе).
4. При успешном ответе парсить `items`, извлекать `name`, `html_url`, `stargazers_count`, `description`, `language`.
5. При ошибках (сетевые проблемы, таймаут, 403/429 – лимит API) логировать WARNING и возвращать пустой список. Не прерывать анализ.
6. Результаты добавлять в отчёт (в поле `github_evidence` или в `recommendations` с префиксом `[GitHub]`).

#### 3.5. Обработка лимитов GitHub API

- Без токена: 60 запросов в час.
- С токеном: 5000 запросов в час.
- При превышении лимита GitHub возвращает 403. Дедал должен логировать предупреждение и не повторять запрос до следующего цикла анализа.

### 4. Детальные требования

#### 4.1. Добавить метод `_search_github` в `CognitiveEngineService`

```python
async def _search_github(self, query: str, limit: int = 3) -> List[dict]:
    """Поиск репозиториев на GitHub по запросу."""
    if not self.github_api_enabled:
        return []
    headers = {"Accept": "application/vnd.github.v3+json"}
    if self.github_token:
        headers["Authorization"] = f"token {self.github_token}"
    url = f"https://api.github.com/search/repositories?q={query}&sort=stars&order=desc&per_page={limit}"
    try:
        async with httpx.AsyncClient() as client:
            response = await client.get(url, headers=headers, timeout=10.0)
            response.raise_for_status()
            data = response.json()
            items = data.get("items", [])
            results = []
            for item in items:
                results.append({
                    "name": item.get("full_name"),
                    "url": item.get("html_url"),
                    "stars": item.get("stargazers_count"),
                    "description": item.get("description", ""),
                    "language": item.get("language")
                })
            logger.info(f"GitHub search for '{query}' returned {len(results)} results")
            return results
    except Exception as e:
        logger.warning(f"GitHub API error: {e}")
        return []
```

#### 4.3. Интеграция в `analyze_logs`

После выявления `error_types` и `containers_with_issues`, для каждого типа ошибки с частотой > 5 выполнить поиск на GitHub и сохранить результаты в отчёте. Добавить новое поле `github_evidence` в `AnalysisReport`.

В `models.py` добавить:

```python
class GitHubEvidence(BaseModel):
    name: str
    url: str
    stars: int
    description: str
    language: Optional[str] = None

class AnalysisReport(BaseModel):
    # ... существующие поля ...
    github_evidence: Dict[str, List[GitHubEvidence]] = {}
```

При формировании отчёта:

```python
report.github_evidence = {}
for error_type, count in error_types.items():
    if count > 5:
        query = self._build_github_query(error_type)
        evidence = await self._search_github(query)
        if evidence:
            report.github_evidence[error_type] = [GitHubEvidence(**e) for e in evidence]
```

- Успешный поиск: INFO с количеством результатов.
- Ошибка API: WARNING с текстом ошибки.
- Отправка события в BR18 (через заглушку) с типом `github_search_performed`.
