### 1. Цель

В текущей реализации Дедала метод `_create_handover_task` в `services.py` использует заглушку (возвращает фиктивный ID). Заменить эту заглушку на реальный HTTP-вызов к API handover (C7.2) для создания задачи при утверждении гипотезы. При этом Дедал должен:

- Генерировать уникальный `task_id` (например, `HYP-{hypothesis_id}` или `IMP-{timestamp}`).
- Отправлять POST-запрос на эндпоинт `/take` handover API с телом:  
  ```json
  {
    "task_id": "сгенерированный_id",
    "actor": "АРХИ",
    "comment": "Гипотеза Дедала: {текст гипотезы}"
  }
  ```
- Обрабатывать ответ: если успех – сохранять `handover_task_id`, иначе логировать ошибку и возвращать `None`.
- Логировать все вызовы и ошибки в BR18 (через существующую заглушку логирования, которую потом тоже заменим).

### 3. Технические параметры

#### 3.1. Переменные окружения (добавить в `docker-compose.yml` для C1.1)

| Переменная | Значение по умолчанию | Описание |
|------------|----------------------|-----------|
| `HANDOVER_URL` | `http://handover:8080` | Базовый URL handover API (C7.2) |

#### 3.2. Формат вызова handover

- **Метод:** POST
- **Путь:** `/take`
- **Заголовки:** `Content-Type: application/json`
- **Тело:**
  ```json
  {
    "task_id": "HYP-{hypothesis_id}",
    "actor": "АРХИ",
    "comment": "Гипотеза Дедала: {hypothesis_text[:200]}"
  }
  ```
- **Успешный ответ (200):** `{"success": true, "new_status": "IN_PROGRESS"}`
- **Ошибка (400):** `{"success": false, "error": "..."}`

#### 3.3. Логика работы

1. В методе `create_hypothesis_task` (после создания объекта `HypothesisTask`, но до возврата) вызывать реальный HTTP-запрос.
2. Генерировать `task_id` в формате `HYP-{hypothesis_id}` (где `hypothesis_id` – уже сгенерированный UUID). Это обеспечит уникальность и связь с гипотезой.
3. Использовать `httpx.AsyncClient` для асинхронного запроса (как уже используется в других местах `services.py`).
4. Обрабатывать возможные исключения (сетевые ошибки, таймаут, HTTP-статус не 200). В случае ошибки логировать в локальный лог и BR18, а `handover_task_id` оставить `None`. Сама гипотеза должна оставаться в статусе `pending`, чтобы её можно было позже повторить или вручную утвердить.
5. При успешном ответе (поле `success: true`) извлечь `handover_task_id` (можно использовать тот же `task_id`, который мы отправили, или получить из ответа, если handover вернёт что-то). В текущей реализации handover не возвращает task_id в ответе, но мы его знаем – это `HYP-{hypothesis_id}`. Поэтому просто сохраняем его.
6. Обновить поле `handover_task_id` в объекте `HypothesisTask` и сохранить в словаре `self.hypothesis_tasks`.
