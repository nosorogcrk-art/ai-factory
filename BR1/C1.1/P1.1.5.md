### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P1.1.5 (LEVEL 5)

**ID:** P1.1.5  
**Контейнер:** C1.1 (Cognitive Engine)  
**Название:** Интеграция с BR18 – сбор метрик (заглушка)

**Зависимости:** P1.1.1, (ждёт BR18)

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Доработать существующий скрипт `metric_collector.py`, добавив в него возможность получать метрики из будущего сервиса BR18 (Log Aggregator, Metrics Dashboard, Alert Manager). Поскольку BR18 ещё не реализован, все вызовы к нему заменяются заглушками, которые либо возвращают фиксированные тестовые данные, либо читают данные из локальных файлов (например, из ранее собранных метрик). Это позволит в будущем легко переключиться на реальные запросы, не меняя архитектуру.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Целевой файл:** `agents/tools/metric_collector.py` (существующий).  
- **Добавляемые функции-заглушки:**  
  - `fetch_from_br18_logs(query_filter)` – вместо реального HTTP-запроса возвращает пустой список или пример лога, читаемый из локального файла `stub_logs.json` (если он есть).  
  - `fetch_from_br18_metrics()` – возвращает фиксированный набор метрик (например, те же, что собирает P1.1.1).  
  - `check_alerts()` – возвращает список алертов (пустой или пример).  
- **Модификация основного сценария:**  
  - Вместо прямого сбора из локальных файлов, скрипт теперь вызывает заглушки, которые могут либо обращаться к локальным файлам (если нужно сохранить существующее поведение), либо использовать заглушечные данные.  
  - Добавить конфигурационный параметр `USE_BR18_STUB` (через переменную окружения), который определяет, использовать ли заглушки (по умолчанию `true`). При `false` – позже будут реальные вызовы.  
- **Логирование:** записывать в `metric_collector.log`, какие данные были получены от заглушек.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В начале файла добавить константу `BR18_STUB = os.getenv("USE_BR18_STUB", "true").lower() == "true"`.  
- Создать функции `_fetch_logs_stub()`, `_fetch_metrics_stub()`, `_check_alerts_stub()`.  
- В основной функции `collect_metrics()` заменить прямые чтения файлов на вызовы этих функций.  
- Для обратной совместимости (если заглушка отключена) можно оставить старый код как fallback.  

**Пример:**  
```python
def _fetch_metrics_stub():
    # Если есть сохранённые ранее метрики, читаем их
    if Path("01_ЦЕХ/МЕТРИКИ/latest_metrics.json").exists():
        with open("01_ЦЕХ/МЕТРИКИ/latest_metrics.json") as f:
            return json.load(f)
    return {"error": "no metrics"}
```

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Скрипт `metric_collector.py` продолжает работать как раньше (при `USE_BR18_STUB=true`), собирая данные из локальных источников.  
- При включённой заглушке все вызовы, которые в будущем пойдут в BR18, заменены на заглушки.  
- Логи фиксируют использование заглушек.  
- Код содержит комментарии, указывающие, что при реализации BR18 заглушки следует заменить на реальные HTTP-запросы.
