
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P1.1.6 (LEVEL 5)

**ID:** P1.1.6  
**Контейнер:** C1.1 (Cognitive Engine)  
**Название:** Классификатор с учётом навыков (заглушка)

**Зависимости:** P1.1.4

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Расширить классификатор задач (`task_classifier.py`) возможностью учитывать наличие и актуальность навыков из BR17 при определении типа задачи и её приоритета. Поскольку BR17 ещё не реализован, добавляется заглушка, которая либо игнорирует навыки, либо возвращает фиктивный список доступных навыков. В будущем эта заглушка будет заменена реальными вызовами к BR17.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Целевой файл:** `agents/tools/task_classifier.py`.  
- **Добавляемые функции-заглушки:**  
  - `check_skills_availability(skills_list)` – принимает список идентификаторов навыков, возвращает словарь с информацией о каждом навыке: существует ли он, активен ли, версия. Заглушка возвращает все переданные навыки как существующие и активные, если список не пуст; если пуст – возвращает пустой словарь.  
  - `find_skills_by_context(context)` – по описанию задачи пытается найти подходящие навыки через семантический поиск (в будущем через BR2). Заглушка возвращает пустой список или фиксированный набор (`["SKILL-042"]`).  
- **Модификация классификации:**  
  - При классификации, если задача связана с выполнением (например, тип `refactor`), классификатор может проверять, есть ли необходимые навыки у агента (пока заглушка всегда говорит «да»).  
  - Добавить поле `required_skills` в выходной результат классификации (пока пустое или заполненное заглушкой).  
- **Логирование:** записывать факт вызова заглушек.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В файле добавить функцию `_check_skills_stub` и `_find_skills_stub`.  
- В основной функции `classify()` при необходимости добавить вызовы этих функций.  
- Использовать переменную окружения `USE_BR17_STUB` (по умолчанию `true`).  

**Пример:**  
```python
def _check_skills_stub(skills):
    return {s: {"exists": True, "active": True, "version": "1.0.0"} for s in skills}
```

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Классификатор продолжает работать как раньше, если навыки не используются.  
- При наличии параметров, требующих навыков, заглушка возвращает фиктивные данные.  
- В выходном результате появилось поле `required_skills` (может быть пустым).  
- Логи фиксируют использование заглушек.

### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P1.1.7 (LEVEL 5)

**ID:** P1.1.7  
**Контейнер:** C1.1 (Cognitive Engine)  
**Название:** Анализатор аномалий с данными BR18 (заглушка)

**Зависимости:** P1.1.5 (заглушка BR18), P1.1.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Модифицировать анализатор аномалий (`anomaly_detector.py`), чтобы он мог использовать данные из BR18 (логи, алерты) для более точного выявления проблем. Поскольку BR18 ещё не готов, все обращения к нему заменяются заглушками, которые читают данные из локальных файлов (например, из журналов агентов) или возвращают пустые списки.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Целевой файл:** `agents/tools/anomaly_detector.py`.  
- **Добавляемые функции-заглушки:**  
  - `get_logs_from_br18(filters)` – заглушка, возвращающая последние строки из локальных журналов (например, из `01_ЦЕХ/01_ЖУРНАЛЫ/`), отфильтрованные по дате и типу.  
  - `get_alerts_from_br18()` – возвращает список алертов, возможно из локального файла `alerts.json`.  
- **Модификация логики:**  
  - Вместо прямого чтения журналов агентов (которое уже есть) можно оставить текущий подход, но добавить возможность получать логи из BR18 через заглушку.  
  - При обнаружении аномалии добавить в отчёт поле `br18_data_used`, указывающее, были ли использованы данные из BR18.  
- **Логирование:** фиксировать вызовы заглушек.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Ввести функцию `_get_br18_logs_stub`, которая обходит файлы журналов в `01_ЦЕХ/01_ЖУРНАЛЫ/` и возвращает строки, соответствующие фильтру. Это почти повторяет существующую логику, но выделено для будущей замены.  
- В основной функции `detect_anomalies` заменить прямые вызовы чтения журналов на вызовы этой заглушки.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Анализатор по-прежнему выявляет аномалии на основе локальных журналов.  
- При включённой заглушке BR18 он использует ту же локальную логику, но через унифицированный интерфейс.  
- Логи фиксируют, что данные получены через заглушку.

### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P1.1.8 (LEVEL 5)

**ID:** P1.1.8  
**Контейнер:** C1.1 (Cognitive Engine)  
**Название:** Генератор гипотез с BR19 (заглушка)

**Зависимости:** P1.1.3, (ждёт BR19)

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Дополнить генератор гипотез (`hypothesis_generator.py`) возможностью взаимодействия с системой самообучения BR19 для получения улучшенных промптов и навыков, а также для инициирования A/B-тестов. Поскольку BR19 ещё не реализован, все обращения к нему заменяются заглушками, которые либо ничего не делают, либо возвращают фиктивные результаты.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Целевой файл:** `agents/tools/hypothesis_generator.py`.  
- **Добавляемые функции-заглушки:**  
  - `send_to_br19_log_analyzer(logs)` – отправляет логи в BR19 для глубокого анализа; заглушка просто записывает факт отправки в локальный лог.  
  - `get_improved_prompts_from_br19()` – возвращает пустой список или пример улучшенного промпта.  
  - `request_ab_test(control, treatment)` – инициирует A/B-тест; заглушка возвращает фиктивный ID теста.  
- **Модификация генерации гипотез:**  
  - После выявления аномалии, перед созданием задачи, генератор может вызвать заглушки для обогащения.  
  - В выходных данных гипотезы добавить поля `br19_used` и `ab_test_id` (опционально).  
- **Логирование:** фиксировать вызовы заглушек.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В файле добавить заглушечные функции с именами `_br19_send_logs`, `_br19_get_prompts`, `_br19_request_ab`.  
- В основной функции `generate_hypotheses` добавить вызовы этих функций в соответствующих местах (например, после сбора аномалий).  
- Использовать переменную окружения `USE_BR19_STUB` для включения/отключения заглушек.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Генератор гипотез продолжает создавать задачи на основе аномалий, как и раньше.  
- При включённой заглушке BR19 в логах появляются записи о вызовах заглушек.  
- Код содержит комментарии, указывающие, как заменить заглушки на реальные вызовы в будущем.
