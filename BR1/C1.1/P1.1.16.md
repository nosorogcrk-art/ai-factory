### 1. Цель

Дедал должен периодически (раз в сутки, вместе с планировщиком P1.1.13) читать внешние источники знаний:

- **RSS-ленты** технических блогов (Habr, Medium, Dev.to, блоги компаний) для отслеживания новых статей, туториалов, best practices.
- **arXiv** – свежие научные статьи по темам AI, LLM, software engineering, microservices.

Найденные материалы должны:
- Сохраняться в векторную память (C2.6) для последующего семантического поиска.
- Использоваться как `evidence` при генерации гипотез (если статья/пост релевантны выявленной проблеме).
- Быть доступными в отчётах Дедала (раздел `external_insights`).

Это позволит заводу быть в курсе мировых трендов и использовать лучшие практики индустрии.

### 3. Технические параметры

#### 3.1. Переменные окружения (добавить в `docker-compose.yml` для C1.1)

| Переменная | Значение по умолчанию | Описание |

| `EXTERNAL_UPDATE_HOUR` | `9` | Час запуска сбора (в дополнение к основному планировщику) |

#### 3.2. RSS

- **Библиотека:** `feedparser` (нужно добавить в `requirements.txt`).
- **Логика:** для каждой ленты из `RSS_FEEDS` выполнить GET-запрос, распарсить XML, извлечь последние 5 записей (заголовок, ссылка, описание, дата).
- **Фильтрация:** пропускать записи старше 7 дней (чтобы не дублировать при каждом запуске). Хранить хеши ссылок (MD5) в локальном файле `external_cache.json`, чтобы не добавлять одно и то же повторно.

#### 3.3. arXiv

- **API:** `http://export.arxiv.org/api/query?search_query=cat:{category}&sortBy=submittedDate&sortOrder=descending&max_results=5`
- **Парсинг:** XML (Atom), извлечь `title`, `id` (ссылка), `summary`, `published` (дата), `author`.
- **Категории:** задаются через `ARXIV_CATEGORIES` (список через запятую). Для каждой категории выполняется отдельный запрос.

#### 3.4. Сохранение в C2.6 (индексация)

- Каждая найденная статья/пост сохраняется в векторную память через `POST /index` C2.6.
- Метаданные: `source` (RSS/arXiv), `source_name` (например, "Habr Python"), `url`, `title`, `date`, `summary`.
- Документ индексируется с ID вида `ext_{hash(url)}`.

#### 3.5. Логика работы (встраивание в планировщик)

- В методе `run_daily_analysis` (из P1.1.13) после основного анализа вызывать `_fetch_external_sources()`.
- Результаты (список внешних материалов) сохранять в отчёте в поле `external_insights`.
- При формировании гипотез (например, для ошибки `timeout`) выполнять семантический поиск по C2.6 среди внешних документов (если есть) и добавлять ссылки в `evidence`.

#### 4.2. В `services.py` добавить методы

```python
async def _fetch_rss_feeds(self) -> List[dict]:
    """Читает RSS-ленты и возвращает список статей."""
    results = []
    feeds = json.loads(os.getenv("RSS_FEEDS", "[]"))
    for feed_info in feeds:
        url = feed_info.get("url")
        name = feed_info.get("name")
        if not url:
            continue
        try:
            import feedparser
            parsed = feedparser.parse(url)
            for entry in parsed.entries[:5]:
                results.append({
                    "source": "rss",
                    "source_name": name,
                    "title": entry.get("title"),
                    "url": entry.get("link"),
                    "summary": entry.get("summary", "")[:500],
                    "published": entry.get("published")
                })
        except Exception as e:
            logger.warning(f"RSS feed {url} failed: {e}")
    return results

async def _fetch_arxiv(self) -> List[dict]:
    """Читает arXiv и возвращает список статей."""
    if not self.arxiv_enabled:
        return []
    categories = os.getenv("ARXIV_CATEGORIES", "cs.AI,cs.SE,cs.LG").split(",")
    results = []
    for cat in categories:
        url = f"http://export.arxiv.org/api/query?search_query=cat:{cat}&sortBy=submittedDate&sortOrder=descending&max_results=5"
        try:
            async with httpx.AsyncClient() as client:
                response = await client.get(url, timeout=15.0)
                response.raise_for_status()
                # Парсинг XML (можно через xml.etree.ElementTree)
                import xml.etree.ElementTree as ET
                root = ET.fromstring(response.text)
                ns = {"atom": "http://www.w3.org/2005/Atom"}
                for entry in root.findall("atom:entry", ns):
                    title = entry.find("atom:title", ns).text
                    link = entry.find("atom:id", ns).text
                    summary = entry.find("atom:summary", ns).text[:500]
                    published = entry.find("atom:published", ns).text
                    results.append({
                        "source": "arxiv",
                        "source_name": f"arXiv {cat}",
                        "title": title,
                        "url": link,
                        "summary": summary,
                        "published": published
                    })
        except Exception as e:
            logger.warning(f"arXiv API for {cat} failed: {e}")
    return results
```

#### 4.3. Метод `_fetch_external_sources` (объединяет RSS и arXiv)

```python
async def _fetch_external_sources(self) -> List[dict]:
    """Собирает статьи из всех внешних источников."""
    rss_items = await self._fetch_rss_feeds()
    arxiv_items = await self._fetch_arxiv()
    return rss_items + arxiv_items
```

После получения списка статей для каждой проверить, не индексировалась ли ранее (по хешу URL). Если нет – отправить `POST /index` в C2.6.

```python
async def _index_external_article(self, article: dict) -> None:
    doc_id = f"ext_{hashlib.md5(article['url'].encode()).hexdigest()[:16]}"
    content = f"{article['title']}\n\n{article['summary']}"
    metadata = {
        "source": article["source"],
        "source_name": article["source_name"],
        "url": article["url"],
        "title": article["title"],
        "date": article.get("published", "")
    }
    async with httpx.AsyncClient() as client:
        await client.post(f"{self.project_memory_url}/index", json={
            "documents": [{"id": doc_id, "content": content, "metadata": metadata}]
        })
```
