### **C1.1: Cognitive Engine (Когнитивный движок)**

**Ветка-родитель:** BR1 | **ID:** C1.1 | **Ответственный:** ДЕДАЛ

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Обработка мета-запросов, рефлексия системы и принятие стратегических решений. Это «мозг» завода, который анализирует текущее состояние (метрики, логи, статусы задач), выявляет узкие места, классифицирует задачи на доработку самого завода и предлагает направления развития. Интегрируется с системой мониторинга (BR18) для получения актуальных данных о производительности и с системой самообучения (BR19) для использования улучшенных промптов и гипотез. Дедал использует этот модуль для постоянного улучшения архитектуры, методологии и навыков агентов.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**  

- **Сбор метрик из BR18:**  
  – Регулярно (по расписанию или по событию) запрашивает у **C18.2 (Metrics Dashboard)** агрегированные показатели: среднее время выполнения задач, частоту ошибок, затраты токенов, загрузку агентов, процент успешных handover и т.д.  
  – Получает из **C18.1 (Log Aggregator)** выборки логов по заданным фильтрам (например, все ошибки за последний час).  
  – Подписывается на алерты из **C18.3 (Alert Manager)** для немедленного реагирования на критические ситуации.  

- **Анализ и выявление аномалий:**  
  – На основе собранных данных запускает алгоритмы обнаружения аномалий: зависшие задачи, неэффективные промпты, повторяющиеся ошибки, отклонения от стандартов.  
  – Использует статистические методы и правила, заданные в методологии (BR3).  
  – При обнаружении аномалии формирует запись в журнале и, при необходимости, инициирует создание задачи на исправление.  

- **Классификация задач на доработку:**  
  – Поступающие запросы (от Владельца, от других агентов, из очереди) и выявленные аномалии классифицируются по типу: улучшение промптов, рефакторинг кода агентов, изменение конфигурации, добавление новых шаблонов, создание/обновление навыков и т.д.  
  – Использует как rule-based подход, так и семантический анализ через **BR2 (C2.3)** для поиска аналогичных ситуаций в эволюционной памяти.  
  – Учитывает доступные навыки из **BR17** (через C7.4 или прямое обращение к C17.1) для определения возможности выполнения задачи.  

- **Генерация гипотез и предложений:**  
  – На основе классификации и данных из BR18 формирует гипотезы по оптимизации.  
  – Для сложных гипотез может привлекать внешние LLM (например, DeepSeek) через API.  
  – Результаты передаются в **BR19 (C19.2 Prompt Optimizer, C19.3 Skill Updater)** для дальнейшей проработки и тестирования.  
  – Также может напрямую создавать задачи (патчи) в реестре задач (через BR7) или передавать их в **C1.2 (Patch Architect)** для декомпозиции.  

- **Взаимодействие с BR19 (Self-Learning):**  
  – Отправляет в BR19 сырые данные (логи, метрики, классифицированные проблемы) для глубокого анализа.  
  – Получает от BR19 улучшенные версии промптов и навыков, а также результаты A/B-тестов.  
  – На основе полученных рекомендаций инициирует внедрение улучшений через BR20 (CI/CD).  

- **Формирование отчётов:**  
  – Периодически (daily/weekly) генерирует отчёты для Владельца: ключевые метрики, выявленные проблемы, предложенные улучшения, статус выполняемых задач.  
  – Отчёты сохраняются в `01_ЦЕХ/01_ЖУРНАЛЫ/` и могут отображаться через BR4.  

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**  

- **Input:**  
  – Метрики и логи из BR18 (через API C18.2, C18.1, C18.3).  
  – Запросы от Владельца (через BR4) или от других агентов (через BR7).  
  – Данные из BR2 (семантический поиск).  
  – Результаты анализа и улучшения из BR19.  
  – Информация о навыках из BR17 (опционально).  

- **Output:**  
  – Стратегические рекомендации и гипотезы (в BR19, в очередь задач).  
  – Классифицированные задачи для C1.2 (Patch Architect).  
  – Отчёты (в файловую систему и в BR4).  
  – Команды на запуск экспериментов в BR19.  
  – Логи собственных действий (в BR18).  

**4. ИНТЕГРАЦИИ**  

- **BR18 (Monitoring):**  
  – **C18.1 Log Aggregator** – получение логов.  
  – **C18.2 Metrics Dashboard** – получение агрегированных метрик.  
  – **C18.3 Alert Manager** – подписка на алерты.  
  – **C18.5 Cost Tracker** – получение данных о затратах токенов.  
- **BR19 (Self-Learning):**  
  – **C19.1 Log Analyzer** – передача сырых логов для глубинного анализа.  
  – **C19.2 Prompt Optimizer** – получение улучшенных промптов.  
  – **C19.3 Skill Updater** – получение улучшенных навыков.  
  – **C19.4 A/B Tester** – запрос на проведение экспериментов.  
- **BR2 (Memory):** семантический поиск через C2.3 для поиска аналогичных ситуаций.  
- **BR17 (Skills):** через C17.1 получение информации о навыках, через C7.4 (опционально).  
- **BR7 (Workforce):** создание задач в реестре, взаимодействие с C7.2 (SAD Logic) для постановки задач.  
- **BR3 (Methodology):** использование правил и порогов из канонов.  
- **BR4 (Visual Dashboard):** отображение отчётов и статусов.  

**5. СТЕК ТЕХНОЛОГИЙ**  

- Python (скрипты анализа, интеграции).  
- HTTP-клиенты для вызовов API BR18, BR19, BR2, BR17.  
- Библиотеки для статистического анализа (numpy, scipy).  
- Библиотеки для работы с JSON, файловой системой.  
- (Опционально) вызовы LLM (DeepSeek) через API.  
- Логирование в `01_ЦЕХ/01_ЖУРНАЛЫ/cognitive_engine.log` и отправка в BR18.  

**6. СПИСОК ПАТЧЕЙ И ИХ ФУНКЦИИ**

| **P1.1.2** | Анализатор аномалий (`anomaly_detector.py`) | Выявление аномалий на основе собранных метрик и классификации. |

| **P1.1.6** | Классификатор с учётом навыков | Расширение классификатора: учёт доступных навыков из BR17 при определении типа задачи. |

| **P1.1.8** | Генератор гипотез с BR19 | Интеграция с BR19: отправка данных в Log Analyzer, получение улучшенных промптов/навыков, инициирование A/B тестов. |

*Примечание:* патчи P1.1.5–P1.1.8 реализуются после того, как соответствующие компоненты BR18 и BR19 достигнут необходимой зрелости. В итоге Cognitive Engine обретает полную функциональность, описанную в данном паспорте.
