
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.4.3 (LEVEL 5)

**ID:** P20.4.3  
**Контейнер:** C20.4 (Test Runner)  
**Название:** Интеграция с C17.4 (Skill Tester)  

**Зависимости:** P20.4.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить возможность функционального тестирования навыков через вызов C17.4 (Skill Tester). Для каждого файла навыка, если он изменился, запускается тестирование в изолированной среде. Результаты тестирования добавляются в общий отчёт.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Новый тип тестов:** `functional` (включает запуск C17.4).  
- **Интеграция с C17.4:**  
  – Адрес задаётся переменной окружения `SKILL_TESTER_URL` (по умолчанию `http://c17.4:8091`).  
  – Для каждого файла навыка вызывается `POST /test/{skill_id}` с телом, содержащим, возможно, конкретные тесты.  
  – Получение результата: либо синхронно (если C17.4 возвращает сразу), либо асинхронно с опросом статуса.  
- **Процесс:**  
  1. Определить, какие файлы являются навыками (по пути или расширению).  
  2. Для каждого навыка отправить запрос в C17.4.  
  3. Собрать результаты (passed/failed, детали).  
  4. Добавить в общий отчёт.  
- **Обработка ошибок:** если C17.4 недоступен или тест не удалось запустить, помечать как ошибку тестирования.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В фоновой задаче после семантических тестов, если запрошен `functional`:  
  1. Для каждого файла-навыка вызвать C17.4 (асинхронно).  
  2. Дождаться результатов (опрашивать при необходимости).  
  3. Сохранить в БД.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При наличии навыков в наборе файлов для каждого из них выполняется запрос к C17.4.  
- Результаты тестирования (успех/неудача) сохраняются в отчёте.  
- При ошибке вызова C17.4 тест помечается как неудачный.
