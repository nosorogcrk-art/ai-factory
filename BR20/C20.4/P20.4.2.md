
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.4.2 (LEVEL 5)

**ID:** P20.4.2  
**Контейнер:** C20.4 (Test Runner)  
**Название:** Семантические тесты  

**Зависимости:** P20.4.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить семантические тесты, проверяющие ссылочную целостность и соответствие внутренним схемам. Например, для навыков – проверка, что все зависимости `depends_on` ссылаются на существующие навыки (через C17.1), для промптов – проверка наличия обязательных полей (по шаблонам из BR3). Тесты выполняются после синтаксических, если они запрошены.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Новые типы тестов:** `semantic` (добавляется в список `tests` в запросе).  
- **Интеграция с внешними сервисами:**  
  – Для проверки ссылок на навыки – вызов C17.1 (Skill Registry) `GET /skills/{id}`. Адрес задаётся переменной `SKILL_REGISTRY_URL`.  
  – Для проверки ссылок на документы – вызов BR2 (Memory) через C2.3 (Semantic Search) или прямой доступ к индексу.  
  – Для проверки соответствия схемам – использовать заранее загруженные JSON-схемы из методологии (BR3).  
- **Алгоритм семантической проверки для навыка (файл навыка):**  
  1. Проверить, что все поля, указанные как обязательные в метаданных (например, `name`, `version`, `instruction`), присутствуют.  
  2. Проверить, что все ID в поле `depends_on` существуют в реестре навыков (статус не `deleted`).  
  3. Проверить, что версия соответствует семантическому версионированию (опционально).  
- **Для промпта:**  
  1. Проверить наличие обязательных разделов (согласно шаблону из BR3).  
  2. Проверить, что ссылки на другие промпты (если есть) существуют.  
- **Результат:** для каждого файла – список ошибок семантики.  
- **Хранение:** результаты дописываются в ту же запись теста (поле `details` может содержать структурированный отчёт).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В фоновой задаче после синтаксических тестов (если запрошены семантические) выполнить:  
  1. Для каждого файла определить его тип (по пути или содержимому).  
  2. Вызвать соответствующие функции проверки, которые обращаются к внешним API.  
  3. Собрать ошибки.  
  4. Сохранить в БД.  
- Для обращений к внешним сервисам использовать `httpx` с таймаутами.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При запросе тестов с типом `semantic` выполняются дополнительные проверки.  
- Для навыка с несуществующей зависимостью возвращается ошибка.  
- Для корректного навыка ошибок нет.  
- Результаты семантических тестов сохраняются в отчёте.  
- При недоступности внешних сервисов тест помечается как ошибка (или пропускается с предупреждением – настраивается).
