### 📄 ПАСПОРТ КОНТЕЙНЕРА C20.3: ROLLBACK MANAGER (МЕНЕДЖЕР ОТКАТА)

**Ветка-родитель:** BR20 | **ID:** C20.3 | **Ответственный:** ГЕФЕСТ

---

#### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ
Механизм быстрого возврата к предыдущей версии конфигураций в случае обнаружения проблем после деплоя. Хранит историю успешных деплоев и соответствующие слепки файлов. При получении сигнала от системы мониторинга (BR18) или по ручной команде через BR4 мгновенно восстанавливает предшествующее стабильное состояние. Ведёт журнал откатов и логирует все действия в BR18.

---

#### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **История деплоев:**  
  – Получает от C20.2 (Auto Deployer) уведомления о каждом успешном деплое (с указанием репозитория, коммита/тега, окружения, времени).  
  – Сохраняет эту информацию в локальной БД (SQLite).  
  – При необходимости может хранить полные слепки конфигураций (путем копирования файлов из C20.1).  

- **Триггеры отката:**  
  – По API (ручной вызов из BR4).  
  – Автоматически, если от BR18 (Alert Manager) поступил сигнал о критической ошибке после деплоя (например, алерт с метаданными, содержащими ID деплоя).  

- **Процесс отката:**  
  1. По ID деплоя или по целевой дате определяется предыдущая стабильная версия.  
  2. Через C20.1 получаются файлы этой версии (или используются сохранённые слепки).  
  3. Применяются к целевому окружению через C20.5 (аналогично деплою).  
  4. В C20.1 создаётся новый коммит (с пометкой "rollback to version X") для фиксации отката.  
  5. Результат отката логируется.  

- **API:**  
  – `POST /rollback` – выполнить откат (параметры: `deploy_id` или `environment` и `target_version`).  
  – `GET /history` – история деплоев и откатов.  

- **Логирование:**  
  – Все действия отправляются в C18.1.

---

#### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8107):**  
  – Пример отката: `POST /rollback`  
    ```json
    {
      "deploy_id": "dep_123",
      "reason": "errors detected in monitoring"
    }
    ```  
    Ответ: `{ "rollback_id": "rb_456", "status": "started" }`  

- **Исходящие вызовы:** к C20.1, C20.5, целевым сервисам.

---

#### 4. ИНТЕГРАЦИИ

- **C20.1 (GitOps Core):** получение файлов версий.  
- **C20.2 (Auto Deployer):** получение уведомлений о деплоях.  
- **C20.5 (Environment Manager):** применение конфигураций в окружении.  
- **BR18 (Alert Manager):** получение сигналов об ошибках.  
- **BR4 (Command Console):** ручной запуск.
