
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.2.5 (LEVEL 5)

**ID:** P20.2.5  
**Контейнер:** C20.2 (Auto Deployer)  
**Название:** Стратегии деплоя (blue-green/canary)  

**Зависимости:** P20.2.4

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить поддержку расширенных стратегий деплоя: blue-green и canary. Это требует взаимодействия с целевыми сервисами для постепенного переключения трафика и мониторинга метрик через BR18. Реализуется как опциональный этап, конфигурируемый для каждого окружения.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Конфигурация стратегий:** в параметрах окружения (из C20.5) добавляется поле `deployment_strategy` со значениями `direct`, `blue-green`, `canary`. Также могут быть параметры: `canary_percent` (начальный процент трафика), `canary_steps`, `canary_interval`.  
- **Blue-green:**  
  – Развернуть новую версию параллельно (например, в отдельном контейнере/сервисе).  
  – После успешного развёртывания переключить трафик на новую версию (через прокси или обновление конфигурации).  
  – Поддержка со стороны целевых сервисов (они должны уметь работать с несколькими версиями).  
- **Canary:**  
  – Развернуть новую версию и направить на неё небольшой процент запросов.  
  – Отслеживать метрики (через BR18) в течение заданного интервала.  
  – Если метрики в норме, увеличивать процент и повторять до 100%.  
  – Если метрики ухудшаются, инициировать откат.  
- **API целевых сервисов:** для поддержки этих стратегий необходимы специальные эндпоинты (например, `POST /deploy/blue-green`). Пока можно реализовать заглушки, логику непосредственного переключения оставить на будущее.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В фоновой задаче после получения параметров окружения проверить стратегию.  
- Для `direct` – просто применить изменения (как в P20.2.4).  
- Для `blue-green` – вызвать целевой сервис с указанием стратегии (если API поддерживает).  
- Для `canary` – выполнить цикл с постепенным увеличением процента, на каждом шаге проверяя метрики через BR18.  
- При неудаче на любом шаге – откат (вызов C20.3).  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Для окружения со стратегией `direct` поведение не меняется.  
- Для `blue-green` вызывается соответствующий эндпоинт (пока заглушка).  
- Для `canary` выполняется цикл, логируются шаги.  
- При ошибке вызывается откат.
