
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.2.6 (LEVEL 5)

**ID:** P20.2.6  
**Контейнер:** C20.2 (Auto Deployer)  
**Название:** Логирование и статус  

**Зависимости:** P20.2.5

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить отправку логов обо всех этапах деплоя (запуск, успех, ошибки) в центральный лог-агрегатор BR18 (C18.1). Также улучшить эндпоинт `/status`, чтобы он возвращал более детальную информацию о текущих и завершённых деплоях.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Адрес BR18:** переменная окружения `BR18_URL` (по умолчанию `http://br18:8080/api/logs`).  
- **Формат лога:**  
  ```json
  {
    "timestamp": "ISO 8601",
    "service": "C20.2",
    "event_type": "deploy_started | deploy_succeeded | deploy_failed | deploy_step",
    "details": {
      "deploy_id": "dep_123",
      "repo": "skills",
      "commit": "abc123",
      "environment": "staging",
      "step": "syntax_check",
      "status": "success"
    }
  }
  ```  
- **События для логирования:**  
  – Начало деплоя.  
  – Успешное завершение каждого этапа (синтаксис, тесты, применение).  
  – Завершение деплоя (успех/неудача).  
  – Ошибки.  
- **Эндпоинт `/status`:**  
  – Возвращает список последних N деплоев (по умолчанию 20) с деталями (статус, время, результаты этапов).  
  – Может принимать параметры `repo`, `environment`.  
- **Асинхронность:** отправка логов через `BackgroundTasks`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Добавить функцию `send_log(event_type, details, background_tasks)`.  
- В каждом значимом месте (начало деплоя, завершение этапа, ошибка) вызывать эту функцию.  
- В эндпоинте `/status` расширить запрос к БД для возврата более полной информации (можно хранить шаги в отдельной таблице).  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При каждом деплое отправляются логи в BR18.  
- Эндпоинт `/status` возвращает детальную историю.  
- Отправка логов асинхронна, не замедляет pipeline.  
- При недоступности BR18 ошибка логируется локально.
