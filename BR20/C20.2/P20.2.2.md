
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.2.2 (LEVEL 5)

**ID:** P20.2.2  
**Контейнер:** C20.2 (Auto Deployer)  
**Название:** Загрузка и проверка конфигураций  

**Зависимости:** P20.2.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
При запуске деплоя (автоматическом или ручном) реализовать этап загрузки файлов конфигураций из репозитория (через C20.1) и выполнения синтаксических проверок (линтеры, валидаторы). Результат проверки сохраняется и влияет на дальнейший ход pipeline.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Процесс деплоя:** теперь при создании задачи деплоя (в таблице `deploy_state`) запускается фоновая задача (через `BackgroundTasks`), которая выполняет шаги pipeline.  
- **Шаг 1: загрузка файлов**  
  – Для заданного репозитория и коммита (или ветки) вызывается C20.1: `GET /repos/{repo}/files?ref={commit}`. Поскольку такого эндпоинта нет, будем использовать `GET /repos/{repo}/files/{path}` для каждого файла. Упрощённо: можно получить список изменённых файлов через `GET /repos/{repo}/commits/{commit}` (если есть) или просто скачать весь репозиторий.  
  – Для простоты загружаем все файлы репозитория (через `git archive` или через последовательные запросы).  
- **Шаг 2: синтаксическая проверка**  
  – В зависимости от типа файла (расширение) применяются соответствующие валидаторы:  
    * `.json` – проверка JSON-синтаксиса.  
    * `.yaml`/`.yml` – проверка YAML-синтаксиса.  
    * `.md` – базовая проверка Markdown (можно просто наличие).  
  – Ошибки синтаксиса записываются в отчёт, деплой прерывается.  
- **Хранение результатов:** результаты проверок сохраняются в БД (таблица `deploy_results` или JSON-поле в `deploy_state`).  
- **API:**  
  – Внутренний эндпоинт (не для внешнего использования) может не добавляться.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В функции обработки деплоя (фоновой задаче) после создания записи выполнить:  
  1. Загрузить файлы из репозитория (можно использовать временную директорию).  
  2. Пройтись по всем файлам, для каждого провести синтаксическую проверку.  
  3. Если есть ошибки, установить статус деплоя `failed`, сохранить отчёт, завершить.  
  4. Если всё ок, перейти к следующему шагу (тесты).  
- Для синтаксической проверки использовать `json.loads`, `yaml.safe_load` и т.п.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При запуске деплоя для коммита с некорректным JSON деплой завершается с ошибкой.  
- При корректных файлах деплой продолжается.  
- Результаты сохраняются в БД.  
- Ошибки логируются.
