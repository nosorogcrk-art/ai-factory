
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.2.4 (LEVEL 5)

**ID:** P20.2.4  
**Контейнер:** C20.2 (Auto Deployer)  
**Название:** Применение конфигураций  

**Зависимости:** P20.2.3

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
После успешного прохождения тестов необходимо применить изменения в целевом окружении. Для этого нужно запросить параметры окружения у Environment Manager (C20.5) и затем для каждого типа конфигурации вызвать соответствующий целевой сервис (C7.1 для промптов, C17.5 для навыков и т.д.). Также фиксируется успешный деплой.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Интеграция с C20.5:**  
  – Адрес C20.5 задаётся переменной окружения `ENV_MANAGER_URL` (по умолчанию `http://c20.5:8109`).  
  – Вызывается `GET /environments/{env}` для получения параметров окружения (например, `staging`).  
- **Применение конфигураций:**  
  – На основе загруженных файлов и типа репозитория определяется целевой сервис:  
    * Для репозитория `prompts` – вызывать C7.1 (обновление промптов). Предполагается API `POST /prompts` или `PUT /prompts/{id}`.  
    * Для `skills` – вызывать C17.5 (публикация навыков).  
    * Для `canons` – возможно, обновление файлов в BR3 (но пока не реализовано).  
  – Для каждого изменённого файла отправляется запрос в соответствующий сервис с новым содержимым.  
- **Фиксация результата:**  
  – Если все применения успешны, деплой помечается как `success`, в репозитории создаётся тег (через C20.1) с версией (например, на основе даты или номера).  
  – Если какое-то применение не удалось, деплой помечается как `failed`.  
- **Логирование:** все действия логируются.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В фоновой задаче после тестов:  
  1. Запросить параметры окружения у C20.5.  
  2. Для каждого файла определить целевой сервис и отправить запрос.  
  3. При ошибке – остановиться, установить статус `failed`.  
  4. При успехе – создать тег через C20.1.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При успешном применении конфигураций вызываются целевые сервисы.  
- При ошибке одного из вызовов деплой останавливается.  
- Создаётся тег в репозитории.  
- Результат сохраняется в БД.
