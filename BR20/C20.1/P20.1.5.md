
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.1.5 (LEVEL 5)

**ID:** P20.1.5  
**Контейнер:** C20.1 (GitOps Core)  
**Название:** Валидация перед merge  

**Зависимости:** P20.1.4

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
При попытке слияния в защищённую ветку (например, `main`) автоматически запускать тесты через Test Runner (C20.4). Если тесты не пройдены, слияние запрещается. Это обеспечивает качество кода, попадающего в стабильные ветки.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Защищённые ветки:** настраиваются в конфигурации (например, `protected_branches: ["main", "production"]`).  
- **Интеграция с C20.4:**  
  – Адрес C20.4 задаётся переменной окружения `TEST_RUNNER_URL` (по умолчанию `http://c20.4:8108`).  
  – Перед выполнением merge вызывается `POST /test` с телом, содержащим информацию о коммите (или просто запускаются тесты для всей конфигурации).  
  – Ожидается ответ `{ "passed": true/false, "details": ... }`.  
- **Алгоритм:**  
  1. В эндпоинте `/merges` проверить, является ли целевая ветка защищённой.  
  2. Если да, получить текущий коммит исходной ветки (или коммит, который будет слит).  
  3. Вызвать C20.4 для запуска тестов (можно передать параметры).  
  4. Если тесты не пройдены, вернуть ошибку (409 Conflict) с деталями.  
  5. Если пройдены, выполнить слияние.  
- **Кэширование результатов тестов:** можно кэшировать, чтобы не запускать повторно для того же коммита.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В эндпоинте `/merges` добавить вызов функции `run_tests_if_protected(from_commit, to_branch)`.  
- Функция отправляет запрос в C20.4 и анализирует ответ.  
- При неудаче поднимает HTTPException.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При слиянии в защищённую ветку выполняется запрос к C20.4.  
- Если тесты не пройдены, слияние отклоняется.  
- Если тесты пройдены, слияние происходит.  
- При недоступности C20.4 слияние блокируется (или разрешается с предупреждением – настраивается).  
- Логирование запросов к C20.4 работает.
