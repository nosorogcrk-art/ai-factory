### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.1.1 (LEVEL 5)

**ID:** P20.1.1  
**Контейнер:** C20.1 (GitOps Core)  
**Название:** Базовая структура и инициализация репозиториев  

**Зависимости:** отсутствуют

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Создать FastAPI-приложение, которое управляет Git-репозиториями конфигураций. При первом запуске инициализировать структуру хранения репозиториев (создать директории, выполнить `git init` для каждого типа конфигураций). Предоставить API для получения списка доступных репозиториев. Это фундамент для всех последующих операций с версионированием конфигураций.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Стек:** Python + FastAPI, GitPython, Uvicorn.  
- **Порт:** 8105 (настраивается через переменную окружения `PORT`).  
- **Хранение репозиториев:** все репозитории располагаются в монтируемом томе `/data/git`. Каждый репозиторий – отдельная поддиректория (например, `/data/git/prompts`, `/data/git/skills`, `/data/git/canons`). Список репозиториев задаётся в конфигурационном файле `repos_config.json` (или через переменные окружения). Если файл не существует, используется список по умолчанию: `["prompts", "skills", "canons"]`.  
- **Инициализация:** при старте приложения для каждого репозитория из списка проверяется наличие директории и Git-репозитория (наличие поддиректории `.git`). Если репозиторий не инициализирован, выполняется `git init --bare` (или обычный `git init` – нужно решить). Для простоты будем использовать обычные (не bare) репозитории, доступные для чтения/записи. Также создаются базовые ветки: `main` (или `master`), `develop`.  
- **API эндпоинты:**  
  - `GET /repos` – возвращает список доступных репозиториев (их имена).  
  - `GET /repos/{repo}` – возвращает информацию о репозитории (последний коммит, ветки и т.п.) – опционально.  
- **Логирование:** все действия записываются в локальный файл `01_ЦЕХ/01_ЖУРНАЛЫ/gitops_core.log`.  
- **Эндпоинт /health** – возвращает `{"status": "ok"}`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать файл `gitops_core.py` с FastAPI-приложением.  
- При старте (в событии `startup`) выполнить функцию `init_repos()`, которая:  
  - Загружает список репозиториев из конфига.  
  - Для каждого имени создаёт директорию, если её нет.  
  - Проверяет наличие Git-репозитория (наличие `.git`); если нет – инициализирует через `git.Repo.init(path)`.  
  - Создаёт ветку `develop`, если её нет (проверить наличие и создать через `repo.create_head`).  
- Эндпоинт `GET /repos` просто возвращает список имён репозиториев.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При первом запуске в `/data/git` создаются директории для каждого репозитория, в них инициализируются Git-репозитории.  
- В каждом репозитории присутствует ветка `develop` (помимо `main`/`master`).  
- Эндпоинт `GET /repos` возвращает список имён репозиториев.  
- При повторном запуске повторной инициализации не происходит.  
- Локальный лог-файл создаётся и содержит записи о инициализации.  
- Эндпоинт `/health` отвечает `{"status": "ok"}`.
