
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.1.3 (LEVEL 5)

**ID:** P20.1.3  
**Контейнер:** C20.1 (GitOps Core)  
**Название:** Слияние и теги  

**Зависимости:** P20.1.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить возможность слияния веток (merge) и создания тегов (версий). Это необходимо для продвижения изменений по окружениям и фиксации релизных версий.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Новые эндпоинты:**  
  - `POST /repos/{repo}/merges` – слияние веток. Тело запроса:  
    ```json
    {
      "from": "feature/new",
      "to": "develop",
      "message": "Merge feature/new into develop"
    }
    ```  
    Ответ: `{ "merge_commit": "abc123", "status": "success" }`.  
  - `POST /repos/{repo}/tags` – создание тега. Тело запроса:  
    ```json
    {
      "tag": "v1.2.3",
      "ref": "develop",
      "message": "Release version 1.2.3"
    }
    ```  
    (если `ref` не указан, используется текущая HEAD ветки по умолчанию).  
  - `GET /repos/{repo}/tags` – список тегов.  
- **Валидация:** проверять существование веток/рефа, уникальность тега.  
- **Логирование:** все операции логируются.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В эндпоинте `/merges` выполнить `repo.git.merge(from_branch, to_branch)` (или через `repo.merge`). При конфликте возвращать ошибку.  
- Для создания тега использовать `repo.create_tag(tag, ref=ref, message=message)`.  
- Для получения списка тегов – `repo.tags`.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Слияние веток успешно выполняется (если нет конфликтов).  
- При конфликте возвращается ошибка.  
- Создаётся тег.  
- Список тегов возвращается.
