### **C3.4: Citations Agent (Агент цитирования)**

**Ветка-родитель:** BR3 | **ID:** C3.4 | **Ответственный:** АРХИ

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Автоматическая простановка ссылок на связанные документы в отчётах, спецификациях и других текстовых артефактах. Агент анализирует входной текст, извлекает явные упоминания идентификаторов (патчей, навыков, замыслов) и дополняет его семантическими ссылками на наиболее релевантные документы из Вики-Вселенной (BR2) даже в тех случаях, когда идентификаторы не указаны явно. Использование семантического поиска с метаданными повышает точность и информативность ссылок, улучшая навигацию и прослеживаемость.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**  

- **Извлечение явных идентификаторов:**  
  – Текст сканируется на наличие шаблонов вида `[[ID_Замысел]]`, `P1.2.3`, `SKILL-001` и т.п.  
  – Найденные идентификаторы проверяются на корректность (существование в соответствующих реестрах через BR2 или BR17).  
  – Для каждого найденного идентификатора добавляется стандартное оформление ссылки (например, в Markdown).  

- **Семантическое дополнение ссылок:**  
  – Исходный текст разбивается на логические блоки (абзацы, секции).  
  – Для каждого блока формируется запрос к **C2.3 (Semantic Search)** с параметрами:  
    * `query` = текст блока;  
    * `k` = настраиваемое количество кандидатов (например, 3);  
    * `filters` – могут применяться фильтры (например, ограничение по дате, типу источника).  
  – Полученные результаты фильтруются по порогу релевантности (`score` ≥ threshold).  
  – Для каждого подходящего документа проверяется, не был ли он уже упомянут в блоке (явно или семантически). Если нет, в конец блока добавляется ссылка вида `[[id_документа]]`.  
  – Количество добавляемых ссылок на блок ограничивается параметром (например, не более 2).  

- **Обогащение метаданными:**  
  – При наличии в ответе C2.3 расширенных метаданных (источник, дата, тип) агент может использовать их для форматирования ссылки (например, добавлять пометку «[внешний источник]» или дату).  
  – В будущем возможно использование поля `related_entities` для построения перекрёстных ссылок.  

- **Логирование:**  
  – Все действия агента (какие ссылки добавлены, какие не прошли порог, ошибки) отправляются в **BR18 (Log Aggregator)** в формате:  
    ```json
    {
      "timestamp": "2026-03-18T12:00:00Z",
      "service": "C3.4",
      "event_type": "citation_added | semantic_search_failed",
      "details": {
        "document_id": "целевой_документ",
        "block_preview": "первые 50 символов блока",
        "added_links": ["[[ID1]]", "[[ID2]]"],
        "semantic_candidates": 3,
        "threshold": 0.7
      }
    }
    ```

- **Конфигурация:**  
  – Параметры работы задаются в конфигурационном файле (например, `citations_config.json`):  
    * `similarity_threshold` – порог релевантности (по умолчанию 0.7).  
    * `max_semantic_links_per_block` – максимальное число семантических ссылок на блок.  
    * `enable_semantic` – включить/отключить семантический поиск.  
    * `filters` – фильтры по умолчанию (например, только внутренние источники).  

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**  

- **Input:**  
  – JSON-запрос с полями:  
    ```json
    {
      "text": "исходный текст для обработки",
      "options": {
        "add_semantic": true,
        "threshold": 0.75,
        "max_links": 2,
        "filters": {"source_type": "internal"}
      }
    }
    ```  
  – Либо вызов как функции из другого модуля (Python).  

- **Output:**  
  – JSON-ответ:  
    ```json
    {
      "processed_text": "текст с добавленными ссылками",
      "stats": {
        "explicit_links_found": 3,
        "semantic_links_added": 2,
        "errors": []
      }
    }
    ```  
  – Или просто строка с текстом, если используется как функция.

**4. ИНТЕГРАЦИИ**  

- **BR2 (C2.3 Semantic Search):** для получения семантически похожих документов с метаданными.  
- **BR2 (C2.2 Indexer):** (косвенно) для проверки существования документов по идентификаторам.  
- **BR17 (Skills Repository):** при необходимости проверки существования навыков (если в тексте встречаются `SKILL-...`).  
- **BR18 (Monitoring):** логирование событий.  
- **BR3 (Standards Lab):** использование конфигурационных параметров, заданных в методологии.  
- **BR4 (Visual Dashboard):** отображение статистики работы агента (опционально).  

**5. СТЕК ТЕХНОЛОГИЙ**  

- Python (основной язык).  
- HTTP-клиент для вызова C2.3 (если реализован как микросервис) или прямое импортирование модуля `semantic_search`.  
- Библиотеки для работы с регулярными выражениями (`re`) для поиска идентификаторов.  
- JSON для конфигурации и обмена данными.  
- (Опционально) асинхронность для параллельной обработки нескольких блоков.  

**6. СПИСОК ПАТЧЕЙ И ИХ ФУНКЦИИ**  

- **P3.4.1 (Базовый Citations Agent):** реализация извлечения явных идентификаторов из текста и добавления ссылок на основе правил (без семантики).  
- **P3.4.2 (Интеграция с семантическим поиском):** добавление вызова C2.3, фильтрации по порогу и вставки семантических ссылок. Реализация описанной выше логики.  
- **P3.4.3 (Интеграция с графом навыков):** расширение функциональности для использования поля `related_entities` из метаданных, добавление перекрёстных ссылок на связанные навыки.  
- **P3.4.4 (Использование расширенных метаданных):** доработка форматирования ссылок с учётом источника, даты и типа документа (например, выделение внешних источников). Этот патч зависит от полной реализации C2.3 с метаданными.  

*Примечание:* нумерация патчей может быть скорректирована в зависимости от фактической последовательности разработки. Основной функционал, описанный в данном паспорте, соответствует состоянию после выполнения P3.4.2 и P3.4.4.
