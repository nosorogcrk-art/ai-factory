
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P3.4.5 (LEVEL 5)

**ID:** P3.4.5  
**Контейнер:** C3.4 (Citations Agent)  
**Название:** Использование расширенных метаданных (источник, дата, связанные сущности)

**Зависимости:** P3.4.4, C2.3 (полностью реализованный с метаданными)

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Доработать Citations Agent для более глубокого использования метаданных, возвращаемых C2.3. В частности, использовать поле `related_entities` для создания перекрёстных ссылок на связанные навыки, патчи или документы. Также улучшить форматирование ссылок, добавляя информацию о дате публикации для внешних источников и возможность группировки ссылок по типу.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Использование `related_entities`:**  
  - Если найденный документ имеет поле `related_entities`, агент может дополнительно добавить ссылки на эти сущности, если они ещё не упомянуты в тексте. Например, если документ ссылается на навык SKILL-042, и этот навык не упомянут, можно добавить ссылку на него.  
  - Количество таких ссылок ограничивается отдельным параметром (например, `max_related_links`).  
- **Обогащение датой:**  
  - Для внешних источников добавлять дату публикации в формате `(ГГГГ-ММ-ДД)`.  
  - Для внутренних документов – дату последнего изменения (если есть).  
- **Группировка ссылок:**  
  - Вместо добавления ссылок в конец каждого абзаца можно собирать все ссылки в отдельный раздел "Связанные материалы" в конце документа. Это управляется параметром `link_placement: "inline" | "section"`.  
- **Конфигурация:**  
  - Добавить параметры:  
    - `use_related_entities` (bool) – включать ли связанные сущности.  
    - `max_related_links` (int) – максимальное количество добавляемых связанных сущностей.  
    - `link_placement` ("inline" | "section") – где размещать ссылки.  
    - `date_format` – формат даты (по умолчанию `%Y-%m-%d`).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В `citations_agent.py` расширить функцию `add_semantic_citations`.  
- После получения результатов от C2.3 для каждого блока:  
  - Собрать все ID из `results` и из их `related_entities`.  
  - Удалить дубликаты и уже имеющиеся в тексте.  
  - Ограничить количество добавляемых ссылок согласно параметрам.  
  - Если `link_placement == "section"`, не добавлять ссылки в текст, а собрать их в отдельный список, который затем будет добавлен в конец документа.  
- Для каждой ссылки формировать текст с учётом метаданных:  
  - Если есть дата, добавить ` (YYYY-MM-DD)`.  
  - Если источник внешний, добавить пометку `[ext]`.  

**Пример:**  
```python
def format_link(doc_id, metadata):
    parts = [f"[[{doc_id}]]"]
    if metadata.get('source_type') == 'external':
        parts.append(f"[ext]")
    if metadata.get('timestamp'):
        parts.append(f"({metadata['timestamp'][:10]})")
    return " ".join(parts)
```

- Для режима "section": в конце документа добавить раздел `## Связанные материалы` со списком ссылок.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При включённом параметре `use_related_entities` агент добавляет ссылки на сущности из поля `related_entities`.  
- Даты корректно отображаются для внешних источников.  
- Режим "section" создаёт отдельный раздел со ссылками в конце документа.  
- Все параметры конфигурации работают и не ломают старый функционал.  
- Логирование расширено для отслеживания добавленных связанных сущностей.
