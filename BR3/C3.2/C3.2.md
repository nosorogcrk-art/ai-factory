### **C3.2: Pipeline Configurator (Настройщик конвейера)** – ОБНОВЛЁННАЯ ВЕРСИЯ

**Ветка-родитель:** BR3 | **ID:** C3.2 | **Ответственный:** АРХИ

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Конфигурирование этапов производственного конвейера (Pipeline-16) под различные типы проектов или веток. Позволяет задавать обязательные и опциональные стадии, их последовательность, параметры (таймауты, допустимые роли, лимиты), а также интегрировать этапы проверки навыков, тестирования и непрерывной доставки. Обеспечивает единую точку управления жизненным циклом задачи от идеи до релиза.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**

- **Конфигурационный файл:** `00_КАНОН/Методология/pipeline_config.json`, содержащий описание этапов, их последовательность, правила перехода, а также параметры для каждого этапа.
- **Новые этапы, добавленные в конфигурацию:**  
  – **Skill Validation** – проверка наличия и актуальности навыков, необходимых для выполнения задачи (интеграция с BR17, C17.4).  
  – **Skill Testing** – запуск тестов навыков в изолированной среде (C17.4) для подтверждения работоспособности.  
  – **A/B Testing** – проведение экспериментов для сравнения версий промптов или навыков (C19.4), результаты влияют на выбор финальной версии.  
  – **CI/CD Integration** – автоматический деплой конфигураций (промптов, навыков, канонов) через BR20 с возможностью отката.
- **Адаптация под ветки:** можно создавать отдельные профили для разных веток (например, BR1, BR5, BR10 и т.д.), которые наследуют базовый конвейер, но могут переопределять параметры этапов или добавлять/убирать этапы.
- **Параметры этапов:** для каждого этапа могут быть заданы:  
  – `timeout` – максимальное время выполнения;  
  – `allowed_roles` – список ролей, имеющих право выполнять этап;  
  – `skill_requirements` – для этапов, связанных с навыками, указываются идентификаторы навыков и версионные ограничения;  
  – `thresholds` – пороговые значения успешности (например, для A/B тестов минимальный процент улучшения).
- **Интеграция с SAD Logic:** модель переходов в `task_model.json` (используется в BR7) частично генерируется или дополняется на основе этого конфига, особенно для новых этапов.

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**

- **Input:**  
  – Запрос на изменение конфигурации от АРХИ или ДЕДАЛА (через BR4 или напрямую).  
  – Автоматические триггеры от BR20 при изменениях в репозитории конфигураций.  
- **Output:**  
  – Актуальный JSON-файл конфигурации `pipeline_config.json`, доступный для чтения другими компонентами (оркестратор, BR1, BR7, BR10).  
  – (Опционально) сгенерированные фрагменты для `task_model.json`.

**4. ИНТЕГРАЦИИ**

- **BR17 (Skills Repository):** используется для проверки существования навыков, указанных в `skill_requirements`, и получения их статуса.  
- **BR19 (Self-Learning):** через этап A/B Testing конфигурация передаёт параметры экспериментов.  
- **BR20 (CI/CD):** этап CI/CD Integration указывает, какие изменения должны проходить через пайплайн деплоя.  
- **BR7 (SAD Logic):** предоставляет модель переходов, частично основанную на конфигурации.  
- **BR1 (Мета-Мозг):** использует конфигурацию для планирования и декомпозиции задач.  
- **BR18 (Monitoring):** логирует изменения конфигурации и результаты выполнения этапов.

**5. СТЕК ТЕХНОЛОГИЙ**

- JSON-схемы (возможно, использование JSON Schema для валидации).  
- Python (скрипты для валидации, генерации, обновления модели переходов).  
- Библиотеки для работы с JSON, возможно, `jsonschema`.  
- HTTP-клиент для взаимодействия с BR17, BR19 (если требуется проверка на лету).

**6. СПИСОК ПАТЧЕЙ И ИХ ФУНКЦИИ**

- **P3.2.1 (Базовая конфигурация):** создание `pipeline_config.json` с эталонным набором этапов Pipeline-16 (базовые этапы: L1–L6, без новых).  
- **P3.2.2 (Профили веток):** добавление возможности определять профили для конкретных веток (например, BR0, BR1) с переопределением отдельных параметров.  
- **P3.2.3 (Генератор модели переходов):** скрипт `generate_task_model.py`, который на основе `pipeline_config.json` обновляет или дополняет `task_model.json` (используется в BR7).  
- **P3.2.4 (Расширение конфигурации новыми этапами):** модификация `pipeline_config.json` и скриптов валидации для включения этапов Skill Validation, Skill Testing, A/B Testing, CI/CD Integration. Добавление соответствующих параметров и проверок. Этот патч выполняется после того, как BR17, BR19, BR20 достигнут достаточной зрелости.
