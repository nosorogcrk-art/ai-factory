# ЗОЛОТОЙ СТАНДАРТ ЦИФРОВОЙ ФАБРИКИ

**Статус:** ЧЕРНОВИК (после утверждения заменить на УТВЕРЖДЁН)

## 1. ЦЕЛЬ
Обеспечить единообразие, качество и прослеживаемость всех процессов разработки.

## 2. ОБЩИЕ ПРИНЦИПЫ
- **Прослеживаемость (Traceability):** Каждая единица работы (патч) должна иметь «пуповину» к утверждённому замыслу.
- **Атомарность:** Патч изменяет не более 5 файлов и затрагивает только один слой.
- **Запрет на код без спеки:** Написание кода (L6) допускается только после утверждения спецификации L5.
- **Единый источник истины:** Все документы хранятся в структурированном виде в папке `00_КАНОН/` и версионируются через Git.

## 3. ПРАВИЛА ДЛЯ АГЕНТОВ
- **АРГУС:** Обладает правом вето, контролирует соблюдение канонов, назначает задачи.
- **АРХИ:** Проектирует архитектуру, создаёт ТЗ, следит за соответствием стандартам.
- **ГЕФЕСТ:** Реализует код строго по ТЗ, обязан писать тесты.
- **РЕВА:** Проверяет код на соответствие стандартам, возвращает на доработку при нарушениях.
- **ГЕРМЕС:** Обеспечивает инфраструктуру, контролирует порты и безопасность среды.
- **МНЕМОСИНА:** Ведёт память, индексирует смыслы, анализирует противоречия.
- **ДЕДАЛ:** Управляет мета-логикой, саморефлексией и развитием САГА.

## 4. ТРЕБОВАНИЯ К ДОКУМЕНТАЦИИ
- Каждый документ уровня L1–L5 должен иметь уникальный ID и ссылку на родительский документ.
- Обязательные поля: замысел, границы, состав узлов, валидация.
- Изменения фиксируются в истории версий.

## 5. КОНТРОЛЬ КАЧЕСТВА
- Автоматические проверки: линтеры, семантический анализ, сканирование уязвимостей.
- Ручное ревью для критических патчей (по усмотрению Аргуса).
- Периодический аудит Мнемосиной на целостность смыслов.
