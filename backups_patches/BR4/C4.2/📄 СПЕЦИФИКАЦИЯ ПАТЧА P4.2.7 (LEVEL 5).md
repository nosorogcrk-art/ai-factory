### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P4.2.7 (LEVEL 5)

**ID:** P4.2.7  
**Контейнер:** C4.2 (Graph Visualizer)  
**Название:** Логирование в BR18  

**Зависимости:** P4.2.6  

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить в бэкенд Graph Visualizer middleware для логирования всех обращений к API в центральный лог-агрегатор BR18 (C18.1). Это обеспечит наблюдаемость использования визуализатора и поможет в отладке.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Механизм:**  
  - В FastAPI-приложении добавить middleware, который перехватывает каждый запрос, замеряет время выполнения и отправляет лог в BR18.  
  - Лог должен содержать: метод, путь, статус код, время выполнения, IP клиента (если доступно).  
- **Формат лога:**  
  ```json
  {
    "timestamp": "ISO 8601",
    "service": "C4.2",
    "event_type": "api_call",
    "details": {
      "method": "GET",
      "path": "/api/graph",
      "query": "type=semantic",
      "status_code": 200,
      "response_time_ms": 120,
      "client_ip": "192.168.1.100"
    }
  }
  ```  
- **Асинхронность:** отправка логов выполняется в фоновой задаче (через `asyncio.create_task` или `BackgroundTasks`), чтобы не задерживать ответ.  
- **Адрес BR18:** задаётся переменной окружения `BR18_URL` (по умолчанию `http://br18:8080/api/logs`).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В файле `graph_api.py` добавить функцию `send_log` для отправки POST-запроса в BR18.  
- Создать middleware, используя `@app.middleware("http")` или `BaseHTTPMiddleware`.  
- В middleware получить время начала, выполнить запрос, затем отправить лог.  
- Обрабатывать возможные ошибки отправки (не должны влиять на основной ответ).  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При каждом запросе к API Graph Visualizer (кроме `/health`, возможно) в BR18 отправляется лог.  
- Логи содержат все указанные поля.  
- Отправка не замедляет ответ клиента.  
- При недоступности BR18 ошибки логируются локально, но не ломают API.
