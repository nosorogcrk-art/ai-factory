
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P17.4.2 (LEVEL 5)

**ID:** P17.4.2  
**Контейнер:** C17.4 (Skill Tester)  
**Название:** Интеграция с C17.1 (получение навыка)  

**Зависимости:** P17.4.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Заменить заглушку на реальное получение данных навыка из реестра C17.1. При запуске теста сервис запрашивает метаданные навыка (инструкцию, зависимости) через API C17.1. Это позволяет в дальнейшем использовать реальные данные для тестирования. На данном этапе само тестирование ещё не реализовано, но данные сохраняются или логируются.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Адрес C17.1:** переменная окружения `SKILL_REGISTRY_URL` (по умолчанию `http://c17.1:8088`).  
- **Взаимодействие:**  
  - При вызове `POST /test/{skill_id}` выполняется GET-запрос к `/skills/{skill_id}` для получения полной записи навыка.  
  - Если навык не найден или статус `deleted`, возвращается ошибка 404.  
  - Полученные данные сохраняются во временном хранилище (например, в памяти) для последующего использования.  
- **Обновление статуса навыка (опционально):** после тестирования (в будущем) можно будет обновлять статус через PATCH `/skills/{id}`. Пока не реализуется.  
- **Логирование:** логируются запросы к C17.1 и ошибки.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Добавить HTTP-клиент (например, `httpx`) в зависимости.  
- В эндпоинте `POST /test/{skill_id}` перед возвратом заглушки выполнить запрос к C17.1.  
- При успешном получении данных сохранить их в глобальном словаре `test_sessions` по `test_run_id`.  
- При ошибке вернуть 404 или 500 с описанием.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При вызове `POST /test/SKILL-042` с существующим навыком сервис обращается к C17.1 и сохраняет данные.  
- Если навык не существует, возвращается 404.  
- В логах видны запросы к C17.1.  
- При недоступности C17.1 возвращается 500.
