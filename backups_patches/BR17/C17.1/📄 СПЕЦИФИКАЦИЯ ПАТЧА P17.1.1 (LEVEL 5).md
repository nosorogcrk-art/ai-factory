### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P17.1.1 (LEVEL 5)

**ID:** P17.1.1  
**Контейнер:** C17.1 (Skill Registry)  
**Название:** Базовая структура и CRUD (SQLite)

**Зависимости:** отсутствуют

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Создать базовое FastAPI-приложение для управления реестром навыков, использующее SQLite для хранения данных. Реализовать CRUD-операции (создание, чтение, обновление, мягкое удаление) над записями навыков. Обеспечить автоматическую генерацию ID для новых навыков, хранение метаданных и базовую валидацию обязательных полей. Это фундамент для всего реестра.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Стек:** Python + FastAPI, SQLite, Uvicorn.
- **Порт:** 8088 (по умолчанию, настраивается через переменную окружения `PORT`).
- **База данных:** файл `skills.db` в директории `/data` (монтируемый том).
- **Структура таблицы `skills`:** поля согласно паспорту C17.1 (id, name, version, description, author, created_at, updated_at, status, tags, task_types, languages, allowed_for_swarm, depends_on, related_patches, instruction). Все поля, кроме id, created_at, updated_at, должны быть в теле запроса.
- **API эндпоинты:**
  - `GET /skills` – возвращает список всех навыков (без пагинации и фильтров на данном этапе, просто все записи).
  - `GET /skills/{id}` – возвращает запись по ID или 404.
  - `POST /skills` – создаёт новый навык.
    - ID генерируется автоматически в формате `SKILL-XXX`, где XXX – следующий порядковый номер (можно хранить счётчик в отдельной таблице или вычислять по max(id)+1).
    - Тело запроса должно содержать все поля, кроме `id`, `created_at`, `updated_at`.
    - При успехе возвращает созданную запись с заполненными `id`, `created_at`, `updated_at`.
  - `PUT /skills/{id}` – полностью заменяет запись навыка (все поля обязательны, кроме `id`, `created_at`). Обновляет `updated_at`.
  - `DELETE /skills/{id}` – мягкое удаление: устанавливает статус `deleted`. Фактически запись не удаляется.
- **Валидация на данном этапе:** минимальная – проверка наличия обязательных полей (`name`, `version`, `description`, `author`, `status`, `instruction`). Формат версии не проверяется.
- **Логирование:** все действия записываются в локальный файл `01_ЦЕХ/01_ЖУРНАЛЫ/skill_registry.log` в формате JSON Lines (для отладки).

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ

- Создать файл `skill_registry.py` с FastAPI-приложением.
- При старте проверить наличие БД и создать таблицу, если её нет.
- Для генерации ID использовать отдельную таблицу `counter` или вычислять следующий номер на основе существующих ID.
- Реализовать Pydantic-модели для запросов и ответов.
- В эндпоинтах использовать `sqlite3` для работы с БД.
- Для мягкого удаления в PUT и DELETE просто менять статус, но не удалять строку.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)

- Приложение запускается, БД создаётся.
- Можно создать навык через POST, получить его по GET, обновить через PUT, удалить (статус меняется).
- GET /skills возвращает список всех навыков.
- При попытке создать навык без обязательных полей – ошибка 422.
- Локальный лог содержит записи о выполненных операциях.
