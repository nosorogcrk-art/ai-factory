
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P17.1.4 (LEVEL 5)

**ID:** P17.1.4  
**Контейнер:** C17.1 (Skill Registry)  
**Название:** (Опционально) поддержка PATCH

**Зависимости:** P17.1.3

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Добавить поддержку HTTP-метода PATCH для частичного обновления записи навыка. Это позволит изменять только отдельные поля, не передавая весь объект целиком. Необходимо обеспечить корректную валидацию только переданных полей и обновление `updated_at`.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Эндпоинт:** `PATCH /skills/{id}`
- **Тело запроса:** JSON-объект, содержащий только те поля, которые нужно обновить. Поля `id`, `created_at`, `updated_at` игнорируются (если переданы).
- **Алгоритм:**
  1. Получить текущую запись из БД.
  2. Обновить только переданные поля (при этом применить валидацию к каждому изменённому полю).
  3. Если поле `depends_on` обновляется, проверить существование всех указанных навыков.
  4. Установить `updated_at` в текущее время.
  5. Сохранить изменения.
  6. Вернуть обновлённую запись.
- **Валидация:** те же правила, что и для POST/PUT, но применяются только к переданным полям.
- **Логирование:** после успешного обновления отправить лог `skill_updated` с указанием изменённых полей.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ

- В эндпоинте использовать Pydantic-модель, где все поля опциональны (но валидаторы всё равно должны применяться, если поле передано).
- Прочитать текущую запись, создать словарь изменений, обновить запись и сохранить.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)

- При отправке PATCH с одним полем (например, `{"status": "active"}`) обновляется только это поле, остальные остаются без изменений.
- `updated_at` обновляется.
- При неверных данных (например, несуществующий навык в `depends_on`) возвращается ошибка 422.
- Лог отправляется с корректным списком изменённых полей.
