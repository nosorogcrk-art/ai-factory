### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P17.3.2 (LEVEL 5)

**ID:** P17.3.2  
**Контейнер:** C17.3 (Skill Graph)  
**Название:** Построение графа и базовые запросы  

**Зависимости:** P17.3.1 (инициализация и загрузка данных из C17.1)

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Реализовать построение графа зависимостей навыков в оперативной памяти на основе данных, полученных от C17.1 (реестр навыков), и предоставить API для получения полного графа, а также информации о конкретном навыке и его прямых зависимостях. Это позволит визуализировать граф (через C4.2) и использовать его в других компонентах.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Источник данных:** предполагается, что P17.3.1 уже реализован и периодически (раз в час) запрашивает из C17.1 список всех активных навыков (статус `active`). Для каждого навыка извлекается поле `depends_on` (массив ID). Эти данные сохраняются в глобальной переменной (например, словарь `skills_meta`).  

- **Структуры данных в памяти:**  
  - `outgoing[skill_id] = список ID, от которых зависит skill_id`  
  - `incoming[skill_id] = список ID, которые зависят от skill_id`  
  - Также храним метаданные навыков для ответов (название, версия и т.п.).  

- **API эндпоинты:**  
  1. `GET /graph` – возвращает полный граф в формате узлов и рёбер.  
     - Ответ:  
       ```json
       {
         "nodes": [
           { "id": "SKILL-001", "name": "Python Refactoring", "version": "1.2.3", "status": "active" },
           ...
         ],
         "edges": [
           { "source": "SKILL-001", "target": "SKILL-042" },
           ...
         ]
       }
       ```  
  2. `GET /graph/{skill_id}` – возвращает информацию о навыке и список его прямых зависимостей.  
     - Ответ:  
       ```json
       {
         "skill": { "id": "SKILL-001", "name": "...", ... },
         "dependencies": [ "SKILL-042", "SKILL-101" ]
       }
       ```  
     - Если навык не найден – 404.  

- **Формирование ответов:**  
  - Для `GET /graph` проходим по всем `skill_id` из `outgoing` и строим узлы и рёбра.  
  - Для `GET /graph/{skill_id}` проверяем наличие в `outgoing` и возвращаем соответствующие данные.  

- **Логирование:** запросы к API логируются в локальный файл `skill_graph.log`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В FastAPI-приложении, созданном в P17.3.1, добавить эндпоинты `GET /graph` и `GET /graph/{skill_id}`.  
- Использовать глобальные переменные (или зависимости FastAPI) для хранения построенного графа.  
- При каждом обновлении данных (по расписанию) перестраивать `outgoing` и `incoming` из нового списка навыков.  
- Для `GET /graph` формировать ответ, обходя все ключи `outgoing`.  
- Для `GET /graph/{skill_id}` проверять наличие ключа в `outgoing` и возвращать информацию о навыке (можно хранить отдельный словарь метаданных).  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- После запуска и получения данных от C17.1 эндпоинт `GET /graph` возвращает корректный JSON со всеми узлами и рёбрами.  
- `GET /graph/{skill_id}` для существующего навыка возвращает его данные и прямые зависимости.  
- Для несуществующего навыка – 404.  
- Логирование запросов работает.  
- При обновлении данных (по расписанию) граф перестраивается автоматически.
