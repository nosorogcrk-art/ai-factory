
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P3.1.4 (LEVEL 5)

**ID:** P3.1.4  
**Контейнер:** C3.1 (Standards Lab)  
**Название:** Валидатор шаблонов (проверка обязательных полей)

**Зависимости:** P3.1.3 (обновлённые шаблоны)

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Создать инструмент для автоматической проверки всех методологических шаблонов на соответствие установленным требованиям: наличие обязательных разделов, корректность структуры, а также, для L4 и L5, наличие полей `required_skills` (пока не обязательно, но мы будем проверять, выдавая предупреждения). Валидатор будет использоваться как часть CI/CD (BR20) и для ручного контроля.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Проверяемые файлы:** все `.md`-файлы в `00_КАНОН/Методология/ШАБЛОНЫ/`.
- **Обязательные разделы для всех уровней (уже есть в P3.1.1):**
  - `# Уровень L[1-6]: ...`
  - `## 1. ЗАМЫСЕЛ`
  - `## 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ`
  - `## 3. РЕАЛИЗАЦИЯ`
  - `## 4. КРИТЕРИЙ ПРИЕМКИ`
  - `## 5. ИСТОРИЯ ИЗМЕНЕНИЙ`
- **Дополнительные требования для L4 и L5:**
  - Наличие в разделе `## 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ` упоминания `required_skills` (пока как предупреждение, не ошибка).
- **Выход:** скрипт возвращает код 0, если все проверки пройдены (предупреждения допустимы), и 1, если есть ошибки (отсутствие обязательных разделов). Генерирует отчёт в `01_ЦЕХ/01_ЖУРНАЛЫ/template_validation.log`.
- **Интеграция:** может вызываться из CI/CD (BR20) или вручную.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ

- Модифицировать существующий скрипт `template_validator.py` (созданный в P3.1.4? Но P3.1.4 как раз и есть валидатор; в предоставленных материалах есть P3.1.4, но он уже описан как валидатор. Однако мы создаём его заново с учётом новых требований. В реальности этот патч должен обновить существующий валидатор или создать новый, если его ещё нет. В имеющихся документах есть `template_validator.py` (см. файл "СПЕЦИФИКАЦИЯ ПАТЧА P3.1.4 (LEVEL 5).md"), но он проверяет только наличие разделов. Мы должны его расширить.

Поэтому задача: взять существующий `template_validator.py` и доработать его, добавив проверку наличия полей `required_skills` (для L4, L5) как предупреждение.

**Пример доработки:**

```python
# Добавить функцию check_skills_field(file_path, content)
def check_skills_field(file_path, content):
    # Определяем уровень из имени файла (L4, L5)
    level = ... # извлечь
    if level in (4,5):
        if 'required_skills' not in content:
            return f"Warning: Missing 'required_skills' field in {file_path.name}"
    return None
```

- Логировать предупреждения, но не считать их ошибками (код возврата 0, если только нет критических ошибок).

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)

- Скрипт `template_validator.py` (обновлённая версия) успешно проверяет все шаблоны на наличие обязательных разделов.
- Для L4 и L5 выдаёт предупреждение, если отсутствует поле `required_skills`.
- При отсутствии обязательных разделов возвращает код 1 и записывает ошибки в лог.
- При наличии только предупреждений возвращает код 0.
- Лог-файл содержит детальную информацию.
