### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P3.3.2 (LEVEL 5) – ИСПРАВЛЕННАЯ ВЕРСИЯ

**ID:** P3.3.2  
**Контейнер:** C3.3 (Training Simulator)  
**Название:** Дополнить симулятор тестами с использованием навыков (подготовительный этап)

**Зависимости:** P3.3.1 (библиотека кейсов)

---

#### 1. ЗАМЫСЕЛ ПАТЧА

Модифицировать существующий скрипт `simulator.py` (движок симулятора) для поддержки тестов, в которых агент должен использовать определённые навыки. На данном этапе реальное взаимодействие с хранилищем навыков (BR17) и интегратором навыков (C7.4) не производится. Вместо этого вводится заглушка: симулятор читает из кейса поле `required_skills` (если есть) и при проверке результата проверяет, что агент вызвал инструменты, соответствующие этим навыкам (например, через анализ логов вызовов). Также добавляется возможность указывать в кейсе ожидаемые вызовы навыков.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Модифицируемый файл:** `agents/tools/simulator.py` (существующий).
    
- **Расширение формата кейса:**
    
    - Добавить опциональное поле `required_skills` (массив строк) – список идентификаторов навыков, которые должны быть задействованы.
        
    - Добавить опциональное поле `expected_skill_calls` – массив объектов, описывающих ожидаемые вызовы навыков (например, `{"skill_id": "SKILL-042", "count": 1, "params": {...}}`).
        
- **Логика работы симулятора:**
    
    - При запуске кейса, если указаны `required_skills`, симулятор записывает их в контекст (например, передаёт агенту через переменные окружения или входные данные), чтобы агент мог их использовать. Агент, в свою очередь, должен логировать, какие навыки он применял.
        
    - После выполнения агента симулятор анализирует журнал вызовов (например, из временного файла логов) и проверяет, что все требуемые навыки были вызваны, и что количество и параметры соответствуют ожиданиям (если задано `expected_skill_calls`).
        
    - В случае несовпадения формируется ошибка валидации.
        
- **Взаимодействие с агентом:**
    
    - Предполагается, что агент (тестируемый) умеет записывать свои действия в специальный лог-файл (например, `/tmp/agent_skill_usage.log`). Симулятор должен настроить окружение так, чтобы агент писал в этот файл.
        
    - Формат записи: каждая строка – JSON вида `{"skill_id": "...", "timestamp": "...", "params": {...}}`.
        
- **Логирование:**
    
    - Добавить запись в отчёт симулятора информации о том, какие навыки требовались и какие были реально использованы.
        
- **Обработка отсутствия поля `required_skills`:**
    
    - Если поле отсутствует, симулятор работает в обычном режиме (без проверки навыков).

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ

- В функции `run_agent` (или аналогичной) добавить создание временного файла для логов навыков и передачу его пути агенту (например, через переменную окружения `SKILL_LOG_FILE`).
    
- После завершения агента прочитать этот файл и собрать статистику вызовов.
    
- Сравнить с требованиями из кейса.
    
- Добавить соответствующие поля в отчёт.
    

**Пример псевдокода:**

python

def run_agent(...):

    calls = []

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)

- Симулятор успешно запускает тестовый кейс, содержащий поле `required_skills`.
    
- Если агент не использует требуемый навык, тест помечается как неудачный, и в отчёте указывается причина.
    
- Если агент использует все требуемые навыки, тест считается успешным (при прочих равных).
    
- Формат логов агента задокументирован.
    
- Изменения не ломают существующие тесты (без поля `required_skills`).
