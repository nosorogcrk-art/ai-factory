### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P3.2.2 (LEVEL 5)

**ID:** P3.2.2  
**Контейнер:** C3.2 (Pipeline Configurator)  
**Название:** Дополнить конфигуратор конвейера новыми этапами

**Зависимости:** P3.2.1 (базовая конфигурация `pipeline_config.json`)

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Модифицировать файл `pipeline_config.json`, добавив в него новые этапы, необходимые для поддержки проверки навыков, тестирования навыков, A/B-тестирования и интеграции с CI/CD. Эти этапы должны быть включены в базовый конвейер, но могут быть помечены как опциональные или обязательные в зависимости от профиля ветки.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Целевой файл:** `00_КАНОН/Методология/pipeline_config.json`.  
- **Добавляемые этапы** (в массив `stages`):  
  1. **Skill Validation**  
     - `id`: `SKILL_VALIDATION`  
     - `name`: "Проверка навыков"  
     - `description`: "Проверка наличия и актуальности навыков, необходимых для выполнения задачи."  
     - `required`: `false` (может быть включена по необходимости)  
     - `allowed_roles`: `["АРХИ", "ДЕДАЛ"]`  
     - `timeout`: 300 (секунд)  
     - `skill_requirements`: `[]` (будет заполняться в профилях)  
  2. **Skill Testing**  
     - `id`: `SKILL_TESTING`  
     - `name`: "Тестирование навыков"  
     - `description`: "Запуск тестов навыков в изолированной среде через C17.4."  
     - `required`: `false`  
     - `allowed_roles`: `["РЕВА"]`  
     - `timeout`: 600  
  3. **A/B Testing**  
     - `id`: `AB_TESTING`  
     - `name`: "A/B-тестирование"  
     - `description`: "Проведение экспериментов для сравнения версий промптов или навыков."  
     - `required`: `false`  
     - `allowed_roles`: `["ДЕДАЛ"]`  
     - `timeout`: 3600  
     - `thresholds`: `{ "improvement": 0.03 }` (порог улучшения)  
  4. **CI/CD Integration**  
     - `id`: `CICD_INTEGRATION`  
     - `name`: "Интеграция с CI/CD"  
     - `description`: "Автоматический деплой конфигураций через BR20 с возможностью отката."  
     - `required`: `false`  
     - `allowed_roles`: `["ГЕРМЕС", "ГЕФЕСТ"]`  
     - `timeout`: 1800  
- **Добавление в список этапов** после существующих (например, после `ARCHIVE`).  
- **Обратная совместимость:** старые профили, не упоминающие эти этапы, должны работать без изменений (этапы будут пропущены).  
- **Валидация:** скрипт `template_validator.py` должен быть обновлён (в будущих патчах) для проверки корректности новых полей.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Вручную или с помощью скрипта добавить новые этапы в JSON-файл.  
- Убедиться, что структура JSON остаётся валидной.  
- При необходимости обновить документацию (комментарии в файле).  

**Пример добавляемого фрагмента:**  
```json
{
  "id": "SKILL_VALIDATION",
  "name": "Проверка навыков",
  "description": "Проверка наличия и актуальности навыков, необходимых для выполнения задачи.",
  "required": false,
  "allowed_roles": ["АРХИ", "ДЕДАЛ"],
  "timeout": 300
}
```

- Добавить аналогично остальные этапы.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- В `pipeline_config.json` присутствуют все четыре новых этапа с корректными ID и параметрами.  
- JSON-файл валиден (можно проверить любым парсером).  
- Существующие профили веток (если есть) не сломаны.  
- После добавления этапов можно запускать конвейер без ошибок (на данном этапе этапы просто игнорируются, так как ещё нет логики их обработки).
