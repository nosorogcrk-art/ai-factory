
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.3.3 (LEVEL 5)

**ID:** P19.3.3  
**Контейнер:** C19.3 (Skill Updater)  
**Название:** Генерация улучшений с помощью LLM  

**Зависимости:** P19.3.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
На основе текущей инструкции навыка и выявленных проблем/успешных кейсов сформировать предложения по улучшению (новые примеры, уточнения, исправления) с использованием внешней LLM. Сгенерированные предложения сохраняются для последующего применения.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Вызов LLM:**  
  – Использовать API OpenAI (или другого провайдера). Ключ и модель задаются переменными окружения `LLM_API_KEY`, `LLM_MODEL` (по умолчанию `gpt-4`).  
  – Промпт для LLM формируется на основе текущей инструкции навыка, списка проблем и успешных кейсов. Пример шаблона:  
    ```text
    Улучши инструкцию навыка "{skill_name}" (текущая версия: {instruction}), исправляя следующие проблемы: {problems}.  
    Также добавь новые примеры из успешных кейсов: {success_cases}.  
    Сгенерируй до {max_suggestions} предложений по улучшению. Каждое предложение должно содержать: тип (add_example, clarify, fix), описание изменения и новый текст (если применимо).
    ```  
  – Ответ LLM должен быть распарсен как JSON-массив предложений.  
- **Сохранение:**  
  – Сгенерированные предложения сохраняются в таблице `suggestions` (поля: `id`, `job_id`, `type`, `description`, `new_text`).  
- **Асинхронность:** генерация выполняется в фоновой задаче после получения контекста.  
- **Обработка ошибок:**  
  – Если LLM недоступен или возвращает некорректный ответ, задача помечается как `failed`.  
  – Можно повторить попытку (настраивается).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В фоновой задаче после получения контекста:  
  1. Сформировать промпт для LLM.  
  2. Отправить запрос к LLM (используя `httpx`).  
  3. Распарсить ответ.  
  4. Для каждого предложения создать запись в `suggestions`.  
  5. Обновить статус задачи на `suggestions_ready`.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При успешной генерации в БД появляются записи предложений.  
- API (например, `GET /updates/{job_id}`) может возвращать сгенерированные предложения.  
- При ошибке LLM задача помечается как `failed`.  
- Логирование работает.
