
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.3.5 (LEVEL 5)

**ID:** P19.3.5  
**Контейнер:** C19.3 (Skill Updater)  
**Название:** Логирование и отчётность  

**Зависимости:** P19.3.4

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить отправку логов о всех этапах работы обновителя навыков в центральный лог-агрегатор C18.1, а также реализовать эндпоинты для получения истории обновлений и деталей по конкретной задаче. Это обеспечит наблюдаемость и возможность аудита.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Адрес C18.1:** переменная окружения `BR18_URL` (по умолчанию `http://br18:8080/api/logs`).  
- **Формат лога:**  
  ```json
  {
    "timestamp": "ISO 8601",
    "service": "C19.3",
    "event_type": "update_started | update_completed | update_failed | suggestion_generated | commit_created | test_result",
    "details": { ... }
  }
  ```  
- **События для логирования:**  
  – Запуск задачи обновления.  
  – Генерация каждого предложения.  
  – Создание коммита.  
  – Результат тестирования.  
  – Завершение задачи (успех/неудача).  
- **API для истории:**  
  – `GET /updates` – возвращает список задач (с основными полями).  
  – `GET /updates/{job_id}` – возвращает детальную информацию по задаче, включая сгенерированные предложения, результат теста и т.д.  
- **Асинхронность:** отправка логов через `BackgroundTasks`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В фоновой задаче на каждом значимом шаге вызывать функцию `send_log(event_type, details, background_tasks)`.  
- В эндпоинтах `GET /updates` и `GET /updates/{job_id}` возвращать данные из БД.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При запуске задачи отправляется лог.  
- При генерации предложений – лог.  
- При создании коммита – лог.  
- При завершении – лог.  
- API возвращает корректную историю.  
- Отправка логов асинхронна и не блокирует основной процесс.
