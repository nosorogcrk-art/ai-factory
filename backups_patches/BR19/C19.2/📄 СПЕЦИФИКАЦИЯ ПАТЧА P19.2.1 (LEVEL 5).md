### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.2.1 (LEVEL 5)

**ID:** P19.2.1  
**Контейнер:** C19.2 (Prompt Optimizer)  
**Название:** Базовая структура и API (заглушка)  

**Зависимости:** отсутствуют

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Создать каркас FastAPI-приложения для оптимизации промптов. Реализовать эндпоинты для запуска процесса оптимизации и получения списка кандидатов, но на данном этапе вся логика заменена заглушками. Это позволит отладить API и подготовить инфраструктуру для последующей интеграции с другими компонентами.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Стек:** Python + FastAPI, Uvicorn.  
- **Порт:** 8102 (настраивается через переменную окружения `PORT`).  
- **Эндпоинты-заглушки:**  
  - `POST /optimize/{prompt_id}` – принимает JSON с параметрами (например, `{"goals": ["reduce_errors"], "num_variants": 5}`), возвращает `{"job_id": "opt_67890", "status": "started"}`.  
  - `GET /candidates` – возвращает пустой список.  
  - `POST /candidates/{id}/promote` – заглушка, возвращает `{"status": "not_implemented"}`.  
- **Асинхронность:** даже заглушка должна использовать фоновые задачи (`BackgroundTasks`), чтобы имитировать реальное поведение. При получении запроса сразу возвращается ответ, а фоновая задача может просто логировать вызов.  
- **Хранение статуса:** для отслеживания задач оптимизации используется SQLite (таблица `optimization_jobs` с полями `job_id`, `prompt_id`, `status`, `created_at`). При запуске задачи создаётся запись со статусом `running`. По завершении статус меняется на `completed`.  
- **Локальное логирование:** все запросы записываются в файл `01_ЦЕХ/01_ЖУРНАЛЫ/prompt_optimizer.log`.  
- **Эндпоинт /health** – возвращает `{"status": "ok"}`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать файл `prompt_optimizer.py` с FastAPI-приложением.  
- При старте инициализировать SQLite (таблица `optimization_jobs`).  
- В эндпоинте `POST /optimize/{prompt_id}` сгенерировать `job_id` (UUID), создать запись в БД со статусом `running`, запустить фоновую задачу (через `BackgroundTasks`), которая через некоторое время обновит статус на `completed` (для заглушки можно просто установить таймер).  
- Для `GET /candidates` возвращать пустой массив.  
- Для `POST /candidates/{id}/promote` возвращать `{"status": "not_implemented"}`.  
- Добавить `/health`.  
- Настроить логирование.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Приложение запускается на порту 8102.  
- `POST /optimize/{prompt_id}` возвращает JSON с `job_id` и сразу отвечает.  
- В БД создаётся запись задачи.  
- Фоновая задача имитирует выполнение (меняет статус).  
- `GET /candidates` возвращает пустой массив.  
- `POST /candidates/{id}/promote` возвращает заглушку.  
- Эндпоинт `/health` отвечает `{"status": "ok"}`.  
- Локальный лог-файл создаётся и содержит записи о запросах.
