
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.2.2 (LEVEL 5)

**ID:** P19.2.2  
**Контейнер:** C19.2 (Prompt Optimizer)  
**Название:** Интеграция с C19.1 и C7.1  

**Зависимости:** P19.2.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить возможность получения входных данных для оптимизации: отчёты о проблемах из Log Analyzer (C19.1) и текущие версии промптов из Identity Core (C7.1). Эти данные будут использоваться в последующих патчах для генерации улучшенных вариантов. На данном этапе реализуется только запрос данных и сохранение их в контексте задачи оптимизации.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Источники данных:**  
  – **C19.1 (Log Analyzer):** API для получения отчёта о проблемах, связанных с конкретным промптом (или общих). Предполагается эндпоинт `GET /reports/{report_id}` или `GET /problems?prompt_id=...`.  
  – **C7.1 (Identity Core):** API для получения текущего промпта по ID (`GET /prompt/{prompt_id}`).  
- **Адреса сервисов:** задаются переменными окружения `LOG_ANALYZER_URL` (по умолчанию `http://c19.1:8101`) и `IDENTITY_CORE_URL` (по умолчанию `http://c7.1:8080`).  
- **Процесс:**  
  – При запуске задачи оптимизации (`POST /optimize/{prompt_id}`) в фоновой задаче выполняются следующие шаги:  
    1. Запросить текущий промпт из C7.1.  
    2. Запросить связанные проблемы из C19.1 (если доступно).  
    3. Сохранить полученные данные в контексте задачи (например, в JSON-поле в таблице `optimization_jobs`).  
    4. Если какой-либо источник недоступен, задача продолжается с предупреждением (проблемы будут пустыми).  
- **Асинхронность:** все запросы выполняются асинхронно в рамках фоновой задачи.  
- **Логирование:** все обращения и ошибки логируются.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В фоновой задаче (в обработчике `POST /optimize/{prompt_id}`) после создания записи в БД выполнить:  
  1. Загрузить параметры задачи.  
  2. Асинхронно запросить промпт из C7.1 (используя `httpx`).  
  3. Асинхронно запросить проблемы из C19.1 (если доступно).  
  4. Сохранить полученные данные в поле `context` записи задачи (JSON).  
  5. Обновить статус задачи на `ready_for_generation` (или оставить `running`).  
- Обработать таймауты и ошибки.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При запуске оптимизации с корректным `prompt_id` данные из C7.1 сохраняются в контексте задачи.  
- При наличии отчёта из C19.1 он также сохраняется.  
- При недоступности сервисов задача продолжается с предупреждением в логе.  
- В БД поле `context` заполняется JSON-объектом с полученными данными.
