
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.2.5 (LEVEL 5)

**ID:** P19.2.5  
**Контейнер:** C19.2 (Prompt Optimizer)  
**Название:** Отправка в A/B Tester  

**Зависимости:** P19.2.4

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Лучшие кандидаты (прошедшие тестирование) должны быть переданы в A/B Tester (C19.4) для проведения эксперимента. Добавляется эндпоинт для ручного продвижения кандидата, а также автоматическая отправка (опционально) при завершении оптимизации.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Эндпоинт для ручного продвижения:**  
  - `POST /candidates/{id}/promote` – принимает JSON с параметрами для A/B теста (например, `{"traffic_split": 0.1, "target_metric": "success_rate"}`).  
  - Вызывает API C19.4 для создания эксперимента.  
- **Интеграция с C19.4:**  
  – Адрес задаётся переменной `AB_TESTER_URL` (по умолчанию `http://c19.4:8104`).  
  – Формат запроса к C19.4:  
    ```json
    {
      "type": "prompt",
      "object_id": "prompt_argus_v1",
      "control_version": "v1.2.3",
      "treatment_version": "v1.2.4",
      "traffic_split": 0.1,
      "target_metric": "success_rate"
    }
    ```  
  – В ответе получаем `experiment_id`.  
- **Автоматическое продвижение:** можно настроить, чтобы лучший кандидат автоматически отправлялся в A/B тест после завершения оптимизации (если включена опция `auto_promote`).  
- **Сохранение:** ID эксперимента сохраняется в записи кандидата.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В эндпоинте `POST /candidates/{id}/promote` извлечь параметры, проверить, что кандидат существует и протестирован.  
- Отправить запрос в C19.4.  
- Сохранить `experiment_id`.  
- При автоматическом продвижении добавить вызов после завершения тестирования.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При вызове `POST /candidates/{id}/promote` создаётся эксперимент в C19.4, возвращается его ID.  
- В БД кандидата сохраняется `experiment_id`.  
- Если C19.4 недоступен, возвращается ошибка.  
- Автоматическое продвижение работает при включённой опции.
