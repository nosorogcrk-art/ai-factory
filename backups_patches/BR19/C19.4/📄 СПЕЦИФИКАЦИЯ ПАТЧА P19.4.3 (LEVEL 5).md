
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.4.3 (LEVEL 5)

**ID:** P19.4.3  
**Контейнер:** C19.4 (A/B Tester)  
**Название:** Сбор метрик и статистический анализ  

**Зависимости:** P19.4.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить сбор метрик для каждого запроса, относящегося к эксперименту (какую версию получил, был ли успех, время выполнения, затраты). По накоплении достаточного количества данных (или по истечении времени) запускать статистический анализ для определения значимости различий. Результаты сохраняются в эксперименте.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Сбор метрик:**  
  – Предполагается, что компоненты, использующие A/B Tester, после выполнения задачи отправляют отчёт POST-запросом на эндпоинт `/api/metrics` с данными:  
    ```json
    {
      "experiment_id": "exp_123",
      "version": "v1.2.3",
      "success": true,
      "duration_ms": 1234,
      "cost_usd": 0.05,
      "context": "user123"
    }
    ```  
  – Эти данные сохраняются в таблице `experiment_metrics` (поля: id, experiment_id, version, success, duration_ms, cost_usd, context, timestamp).  
- **Статистический анализ:**  
  – Фоновый процесс (планировщик, раз в час или по триггеру) проверяет эксперименты, у которых набрано `min_samples` или истекло время.  
  – Для целевой метрики (например, `success_rate`) выполняется статистический тест (z-тест для пропорций или t-тест для средних).  
  – Использовать библиотеку `scipy.stats`.  
  – Результат (p-value, улучшение) сохраняется в поле `result` эксперимента. Статус меняется на `completed`.  
- **API:**  
  - `POST /api/metrics` – приём метрик.  
  - `GET /experiments/{id}/results` – возвращает результаты анализа.  
- **Асинхронность:** анализ выполняется в фоновой задаче, не блокируя API.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать таблицу `experiment_metrics` в БД.  
- Добавить эндпоинт `POST /api/metrics` для приёма данных.  
- Добавить планировщик (APScheduler), который периодически проверяет эксперименты и для тех, у которых `status = running` и набрано достаточно данных, запускает анализ.  
- В анализе выполнить SQL-запрос для получения данных по контрольной и экспериментальной версиям, применить тест, сохранить результат.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При отправке метрик они сохраняются в БД.  
- При достижении `min_samples` эксперимент автоматически анализируется.  
- Результат (p-value, improvement) сохраняется в эксперименте.  
- API возвращает результаты.
