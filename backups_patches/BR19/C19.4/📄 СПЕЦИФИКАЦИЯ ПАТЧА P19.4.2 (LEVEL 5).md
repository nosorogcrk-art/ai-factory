
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.4.2 (LEVEL 5)

**ID:** P19.4.2  
**Контейнер:** C19.4 (A/B Tester)  
**Название:** Маршрутизация запросов  

**Зависимости:** P19.4.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Реализовать механизм, который для запросов, попадающих под эксперимент, перенаправляет их на нужную версию (контрольную или экспериментальную) в зависимости от заданного `traffic_split`. Для этого A/B Tester должен выступать в роли прокси: либо сам принимать запросы, либо предоставлять API для других компонентов (C7.4, C17.5), чтобы они могли определить, какую версию использовать.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Метод маршрутизации:**  
  – Вариант 1: A/B Tester предоставляет эндпоинт `GET /version/{object_type}/{object_id}?context=...`, который возвращает, какую версию использовать для данного запроса (на основе случайного числа и активных экспериментов).  
  – Вариант 2: Интеграторы (C7.4, C17.5) сами вызывают этот эндпоинт перед обращением к хранилищу.  
- **Алгоритм выбора версии:**  
  1. Найти все активные эксперименты для данного `object_id` и `object_type` (статус `running`).  
  2. Если экспериментов нет, вернуть `control` (или `null`).  
  3. Для каждого эксперимента (обычно один) сгенерировать случайное число от 0 до 1. Если оно меньше `traffic_split`, выбрать `treatment_version`, иначе `control_version`.  
  4. Вернуть выбранную версию.  
- **Кэширование:** результаты выбора можно кэшировать по ключу (object_id + user_id или что-то ещё) для согласованности в рамках одного пользователя/сессии, но на первом этапе можно без этого.  
- **API:**  
  - `GET /api/version/{type}/{object_id}` – возвращает JSON: `{"version": "v1.2.4"}` или `{"version": null}`.  
  - Параметры запроса: `context` (строка, опционально) – может использоваться для идентификации пользователя, чтобы обеспечить консистентность (например, хеш).  
- **Интеграция с C7.4 и C17.5:** в их API будет добавлена логика вызова этого эндпоинта перед получением промпта/навыка.  
- **Логирование:** каждый вызов логируется.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Добавить эндпоинт `GET /api/version/{type}/{object_id}`.  
- В функции реализовать:  
  1. Загрузить активные эксперименты из БД.  
  2. Применить алгоритм выбора.  
  3. Вернуть результат.  
- Для случайности использовать `random.random()`.  
- Для консистентности можно использовать `hash(context) % 1000 / 1000` вместо случайного числа, если передан `context`.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При наличии активного эксперимента с `traffic_split=0.1` примерно 10% запросов возвращают `treatment_version`, остальные – `control_version`.  
- Если эксперимента нет, возвращается `null`.  
- Если эксперимент завершён, он не участвует в выборе.  
- Логирование запросов работает.
