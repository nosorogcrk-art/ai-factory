
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P19.1.4 (LEVEL 5) – ИСПРАВЛЕННАЯ

**ID:** P19.1.4  
**Контейнер:** C19.1 (Log Analyzer)  
**Название:** Интеграция с BR2 и смежными компонентами  

**Зависимости:** P19.1.3

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить отправку наиболее значимых результатов анализа (например, успешные кейсы, типовые ошибки) в эволюционную память BR2 для долгосрочного хранения и использования. Также передавать структурированные данные в Prompt Optimizer (C19.2) и Skill Updater (C19.3) через их API. Для этого необходимо использовать идентификаторы навыков, извлечённые из логов (через C18.4 или напрямую из поля `related_entities`).

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Извлечение ID навыков:**  
  – В процессе анализа (P19.1.2/P19.1.3) для каждого лога уже должны быть извлечены связанные сущности (через C18.4 или путём парсинга `details`). Эти данные сохраняются в таблице `entity_links`.  
  – При формировании рекомендаций для навыков используются эти ID.  
- **Интеграция с BR2:**  
  – После завершения анализа отправлять POST-запрос на эндпоинт BR2 (например, `/api/memory/add`) с выводами (кластеры, паттерны) в формате, подходящем для индексации.  
  – Адрес BR2 задаётся переменной окружения `BR2_URL`.  
- **Интеграция с C19.2 и C19.3:**  
  – Для каждого выявленного проблемного места (например, частые ошибки в определённом навыке) создавать задачу для оптимизатора промптов или обновителя навыков.  
  – Вызывать их API (`POST /optimize/prompt_id` или `POST /update/skill_id`) с соответствующими параметрами.  
  – Адреса задаются переменными `PROMPT_OPTIMIZER_URL` и `SKILL_UPDATER_URL`.  
- **Асинхронность:** все вызовы выполняются в фоне (в рамках той же задачи анализа), но не блокируют друг друга.  
- **Логирование:** все вызовы и ошибки логируются.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В фоновой задаче после получения всех результатов анализа:  
  1. Сформировать JSON-отчёт для BR2.  
  2. Отправить асинхронный POST-запрос в BR2.  
  3. Для каждого навыка, по которому обнаружены проблемы, сформировать запрос в C19.2 или C19.3 (в зависимости от типа проблемы).  
  4. Отправить эти запросы (параллельно).  
  5. Записать результаты отправки в лог (успех/ошибка).  
- Использовать `asyncio.gather` для параллельной отправки.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- После успешного анализа отправляются данные в BR2.  
- При наличии проблем с навыками создаются задачи в C19.2/C19.3.  
- При недоступности сервисов ошибки логируются, но анализ считается завершённым.  
- Все вызовы асинхронны и не блокируют завершение задачи.
