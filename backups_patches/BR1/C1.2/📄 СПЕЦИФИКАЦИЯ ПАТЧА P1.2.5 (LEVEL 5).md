
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P1.2.5 (LEVEL 5)

**ID:** P1.2.5  
**Контейнер:** C1.2 (Patch Architect)  
**Название:** Генератор зависимостей с учётом навыков

**Зависимости:** P1.2.4, P1.2.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Модифицировать скрипт `dependency_gen.py` для построения зависимостей между патчами не только на основе явных упоминаний ID, но и на основе общих навыков: если один патч изменяет навык (указан в поле `modified_skills`), а другой патч требует этот навык (поле `required_skills`), то между ними возникает зависимость. На данном этапе поля `modified_skills` могут отсутствовать или быть пустыми; зависимость строится только по `required_skills`, если какие-то патчи явно ссылаются на навыки, которые могут изменяться другими. Для полноты также можно добавить обратную зависимость: если патч A требует навык, а патч B изменяет его, то A зависит от B.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Модифицируемый файл:** `agents/tools/dependency_gen.py`.
- **Дополнительные поля в реестре задач:** `required_skills` (уже добавлено в P1.2.4) и `modified_skills` (пока не используется, но может быть добавлено позже; для совместимости будем проверять наличие).
- **Логика построения зависимостей:**
  1. Загружаются все задачи.
  2. Для каждой задачи извлекаются её `required_skills` и `modified_skills` (если есть).
  3. Строится карта: для каждого навыка список задач, которые его требуют, и список задач, которые его изменяют.
  4. Для каждой пары задач, где одна требует навык, а другая изменяет этот же навык, добавляется ребро зависимости (от требующей к изменяющей). Можно добавить и обратную зависимость, если это имеет смысл, но обычно требуется именно такой порядок.
  5. Учитываются также явные упоминания ID (существующая логика).
- **Обработка отсутствия полей:** если поля нет, считать, что навыки не требуются/не изменяются.
- **Логирование:** добавление информации о зависимостях, построенных на основе навыков.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ

- После загрузки реестра задач создаём два словаря: `skills_required` (навык -> список ID задач, которые его требуют) и `skills_modified` (навык -> список ID задач, которые его изменяют).
- Для каждой задачи проверяем наличие полей и добавляем в соответствующие словари.
- Затем для каждого навыка, если есть пересечение между требующими и изменяющими, для каждой пары (req_id, mod_id) добавляем зависимость (req_id зависит от mod_id), если только это не одно и то же.
- Существующая логика (поиск явных ID) остаётся.

**Пример кода:**
```python
def build_skill_dependencies(tasks):
    required = defaultdict(list)
    modified = defaultdict(list)
    for task in tasks:
        tid = task["id"]
        for skill in task.get("required_skills", []):
            required[skill].append(tid)
        for skill in task.get("modified_skills", []):
            modified[skill].append(tid)
    new_edges = []
    for skill, req_list in required.items():
        mod_list = modified.get(skill, [])
        for req in req_list:
            for mod in mod_list:
                if req != mod:
                    new_edges.append((req, mod))
    return new_edges
```

- После построения новых рёбер добавить их в граф, избегая дубликатов.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)

- При наличии в задачах полей `required_skills` и `modified_skills` (даже если последние пока не заполняются) скрипт строит соответствующие зависимости.
- Если в описании задачи встречаются ID других задач, зависимости по-прежнему добавляются.
- Граф зависимостей обновляется корректно, без дублирования рёбер.
- Логи фиксируют новые зависимости.
- При отсутствии полей скрипт работает как раньше.
