### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P1.2.4 (LEVEL 5)

**ID:** P1.2.4  
**Контейнер:** C1.2 (Patch Architect)  
**Название:** Добавить в декомпозитор учёт зависимостей навыков

**Зависимости:** P1.2.1 (существующий декомпозитор), (опционально) BR2/C2.3 для семантического поиска навыков – на данном этапе используется заглушка.

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Модифицировать скрипт `decomposer.py` таким образом, чтобы при создании атомарных патчей он определял, какие навыки из реестра BR17 потребуются для выполнения каждого патча, и сохранял эту информацию в поле `required_skills` записи патча. На текущем этапе, пока BR17 и семантический поиск не реализованы, используется упрощённая логика: извлечение ключевых слов из описания и сопоставление с предопределённым списком (заглушка). В будущем заглушка будет заменена реальными вызовами к BR2/C2.3.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Модифицируемый файл:** `agents/tools/decomposer.py`.
- **Добавляемые поля в запись патча (в реестре задач):**
  - `required_skills` – список строк (ID навыков), необходимых для выполнения патча.
  - (Опционально) `modified_skills` – список навыков, которые изменяются данным патчем (будет использовано в P1.2.5). На данном этапе можно оставить пустым.
- **Логика определения навыков:**
  - При создании каждого патча (на основе описания) вызывается функция `_detect_skills(description)`, которая пока является заглушкой.
  - Функция-заглушка может:
    - Возвращать пустой список (если не используется никакая логика).
    - Либо на основе простых ключевых слов (например, если в описании есть "рефакторинг" → добавлять `SKILL-042`). Это повысит полезность патча.
  - В дальнейшем эта функция будет заменена на вызов семантического поиска по BR2 (C2.3) для сопоставления описания с существующими навыками, а также запрос к BR17 для проверки существования навыка.
- **Сохранение:** при создании записи патча в реестре добавляется поле `required_skills`.
- **Логирование:** фиксировать факт определения навыков (какие навыки добавлены для каждого патча) в `01_ЦЕХ/01_ЖУРНАЛЫ/decomposer.log`.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ

- В функции `generate_patches` после формирования списка патчей для каждого патча вызывать `_detect_skills(description)` и добавлять результат в словарь патча.
- Функция `_detect_skills` может быть реализована как:
  ```python
  def _detect_skills(description):
      # Заглушка: простой поиск ключевых слов
      skills = []
      if "рефакторинг" in description.lower():
          skills.append("SKILL-042")  # рефакторинг
      if "тест" in description.lower():
          skills.append("SKILL-101")  # тестирование
      return skills
  ```
- В дальнейшем при наличии BR2 можно будет заменить на семантический поиск:
  ```python
  results = semantic_search(description, filters={"source_type": "skill"}, k=3)
  skills = [r["id"] for r in results if r["score"] > 0.7]
  ```
- При создании записи патча добавить поле `required_skills`.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)

- При запуске `decomposer.py` для задачи, содержащей ключевые слова, в создаваемых патчах появляется поле `required_skills` с соответствующими ID (если заглушка их добавляет).
- Если ключевых слов нет, поле остаётся пустым списком.
- Реестр задач обновляется корректно.
- Логи содержат информацию о добавленных навыках.
- Код содержит комментарии, указывающие, где в будущем будет вызываться реальный семантический поиск.
