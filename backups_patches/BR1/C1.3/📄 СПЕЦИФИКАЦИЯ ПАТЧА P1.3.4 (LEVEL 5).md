### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P1.3.4 (LEVEL 5)

**ID:** P1.3.4  
**Контейнер:** C1.3 (Self-Audit)  
**Название:** Интеграция самоаудита с Log Analyzer (BR19) – заглушка  
**Зависимости:** P1.3.2, (ждёт BR19)

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Доработать анализатор промптов (`prompt_analyzer.py`), добавив возможность получать от будущего сервиса BR19 (C19.1 Log Analyzer) кластеризованные данные об ошибках, повторяющихся паттернах и неэффективных стратегиях агентов. Эти данные должны обогащать отчёт анализатора и влиять на рекомендации. Поскольку BR19 ещё не реализован, все вызовы к нему заменяются заглушкой, которая либо читает локальный файл с тестовыми данными, либо возвращает пустой результат. Это позволит в будущем легко переключиться на реальный сервис.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Модифицируемый файл:** `agents/tools/prompt_analyzer.py` (существующий).  
- **Добавляемые функции-заглушки:**  
  - `_fetch_log_analyzer_data(role, period)` – принимает идентификатор роли и период (например, последние 24 часа), возвращает словарь с кластеризованными ошибками и паттернами. Заглушка может:  
    - возвращать пустой словарь;  
    - читать данные из локального файла `stub_log_analyzer.json` (если он есть);  
    - генерировать случайные тестовые данные.  
- **Модификация основного алгоритма:**  
  - В функции `analyze_prompt` после сбора метрик качества добавить вызов `_fetch_log_analyzer_data`.  
  - Полученные данные включить в отчёт (например, в поле `log_analyzer_insights`).  
  - При формировании рекомендаций учитывать, есть ли в данных указания на конкретные проблемы (например, если кластер ошибок указывает на неоднозначность инструкций, добавить соответствующее предложение).  
- **Логирование:** записывать в `prompt_analyzer.log` факт вызова заглушки и объём полученных данных.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В начале файла добавить переменную `USE_BR19_STUB = os.getenv("USE_BR19_STUB", "true").lower() == "true"`.  
- Определить функцию `_fetch_log_analyzer_stub`:  
  ```python
  def _fetch_log_analyzer_stub(role):
      stub_file = Path("01_ЦЕХ/МЕТРИКИ/stub_log_analyzer.json")
      if stub_file.exists():
          with open(stub_file) as f:
              data = json.load(f)
          return data.get(role, {})
      return {}  # или фиксированный пример
  ```  
- В функции `analyze_prompt`, если `USE_BR19_STUB`, вызвать заглушку и добавить результат в анализ.  
- Если в будущем появится реальный Log Analyzer, заглушку можно заменить на HTTP-запрос к его API.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При запуске `prompt_analyzer.py` с включённой заглушкой (по умолчанию) в выходном JSON-отчёте появляется поле `log_analyzer_insights` (может быть пустым).  
- Лог-файл фиксирует использование заглушки.  
- Если существует локальный файл `stub_log_analyzer.json`, его данные корректно подгружаются.  
- При отключённой заглушке (если переменная окружения установлена в `false`) вызовы к заглушке пропускаются (или можно оставить, но это не должно ломать работу).
