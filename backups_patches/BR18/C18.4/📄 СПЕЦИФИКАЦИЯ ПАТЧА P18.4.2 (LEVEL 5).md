
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P18.4.2 (LEVEL 5)

**ID:** P18.4.2  
**Контейнер:** C18.4 (Traceability Index)  
**Название:** Построение индекса (SQLite FTS)  

**Зависимости:** P18.4.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Реализовать построение полнотекстового индекса на основе принятых логов с использованием SQLite FTS (Full-Text Search). Для каждого лога извлекаются идентификаторы сущностей (патчи, задачи, агенты, навыки) из поля `details` и сохраняются в связанных таблицах, чтобы обеспечить быстрый поиск по ID. Также индексируется содержимое `details` для семантического поиска (через FTS).

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **База данных:** SQLite, файл `/data/traceability.db` (монтируемый том).  
- **Таблицы:**  
  - `logs` – хранит все принятые логи (поля: `id`, `timestamp`, `service`, `event_type`, `details_json`, `created_at`).  
  - `fts` – виртуальная таблица FTS5 для полнотекстового поиска по содержимому `details` (и, возможно, другим текстовым полям).  
  - `entity_links` – связь между логами и идентификаторами сущностей (поля: `log_id`, `entity_type` (patch, task, agent, skill), `entity_id`).  
- **Извлечение идентификаторов:**  
  – При добавлении лога парсить поле `details` (JSON) и извлекать все строки, похожие на ID (регулярное выражение, например, `P\d+\.\d+\.\d+`, `IMP-\d{8}-\d{3}`, `SKILL-\d+`, `АРГУС` и т.д.).  
  – Для каждого найденного ID создавать запись в `entity_links`.  
- **Индексация:**  
  – Запись в `fts`: объединить `event_type`, `service` и строковое представление `details` (можно `json.dumps`).  
- **Процесс:**  
  – При получении лога через API (P18.4.1) после валидации выполнять вставку в БД, извлечение ID и добавление в FTS.  
  – Все операции в одной транзакции.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- При старте приложения создать таблицы, если их нет (включая FTS).  
- Добавить функцию `extract_entities(details)` для поиска ID по регулярным выражениям.  
- В эндпоинте `POST /api/logs` после валидации выполнить вставку в БД, используя транзакцию.  
- Для FTS можно использовать `INSERT INTO fts(rowid, content) VALUES (?, ?)`, где rowid – идентификатор записи из таблицы `logs`.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При отправке лога с ID патча (например, в `details.task_id`) в таблице `entity_links` появляется соответствующая запись.  
- Полнотекстовый поиск по содержимому лога работает (можно проверить простым запросом к FTS).  
- База данных создаётся автоматически.  
- Логирование ошибок индексации.
