
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P18.4.3 (LEVEL 5)

**ID:** P18.4.3  
**Контейнер:** C18.4 (Traceability Index)  
**Название:** API для поиска по ID  

**Зависимости:** P18.4.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Предоставить API для поиска всех логов, связанных с конкретной сущностью (патч, задача, агент, навык). Эндпоинт должен возвращать список логов, отсортированных по времени, с возможностью фильтрации по диапазону дат.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Эндпоинт:** `GET /api/trace/{entity_type}/{entity_id}`  
  - `entity_type` – одно из: `patch`, `task`, `agent`, `skill`.  
  - `entity_id` – идентификатор сущности.  
- **Параметры запроса (опционально):**  
  - `from` – начало временного диапазона (ISO 8601).  
  - `to` – конец диапазона.  
  - `limit` – максимальное количество записей (по умолчанию 100).  
  - `offset` – смещение для пагинации.  
- **Ответ:** JSON-массив объектов логов (с полями `timestamp`, `service`, `event_type`, `details`).  
- **Реализация:**  
  – Запрос к таблице `entity_links` с фильтром по `entity_type` и `entity_id`, объединение с таблицей `logs` для получения полных данных.  
  – Учитывать временные фильтры через поле `timestamp` в таблице `logs`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Добавить эндпоинт с параметрами пути и query.  
- Выполнить SQL-запрос с JOIN между `entity_links` и `logs`.  
- Вернуть результат.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При запросе `GET /api/trace/patch/P1.2.3` возвращаются все логи, в которых упоминается этот патч.  
- Фильтрация по времени работает.  
- Пагинация работает.  
- Для несуществующей сущности возвращается пустой массив.
