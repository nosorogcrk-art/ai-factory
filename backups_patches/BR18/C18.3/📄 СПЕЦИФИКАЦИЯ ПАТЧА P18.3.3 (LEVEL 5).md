
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P18.3.3 (LEVEL 5)

**ID:** P18.3.3  
**Контейнер:** C18.3 (Alert Manager)  
**Название:** Интеграция с каналами уведомлений  

**Зависимости:** P18.3.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Реализовать отправку уведомлений при срабатывании правил через различные каналы: Telegram, Slack, email, webhook. Для каждого канала необходима конфигурация (токены, URL). Добавить эндпоинт для тестовой отправки.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Каналы уведомлений:**  
  - **Telegram:** бот отправляет сообщение в указанный чат. Требуется `bot_token` и `chat_id` (хранятся в конфигурации).  
  - **Slack:** входящий webhook URL.  
  - **Email:** SMTP-сервер, логин, пароль, адреса получателей.  
  - **Webhook:** произвольный HTTP POST на заданный URL с JSON-телом.  
- **Конфигурация каналов:** хранится в отдельном файле `channels_config.json` (или в переменных окружения). Для каждого канала свои параметры.  
- **Шаблоны сообщений:** можно задать в конфигурации или использовать простые строки. По умолчанию:  
  ```
  Alert: {rule_name}
  Condition: {condition}
  Current value: {value}
  Threshold: {threshold}
  Time: {timestamp}
  ```  
- **Эндпоинты:**  
  - `POST /api/test` – принимает JSON с полями `channel` (например, `telegram`) и опционально `message`, отправляет тестовое сообщение.  
- **Обработка срабатываний:**  
  – При срабатывании правила (из P18.3.2) для него вызывается функция отправки по всем каналам, указанным в правиле.  
  – Успешность отправки логируется; при ошибке – повторные попытки (например, до 3 раз).  
- **Логирование:** каждая отправка и ошибки записываются в локальный лог и, возможно, в C18.1 (будет в следующем патче).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать модуль `notifiers.py` с классами или функциями для каждого канала.  
- В основном приложении при старте загрузить конфигурацию каналов.  
- В фоновой задаче проверки правил при обнаружении срабатывания вызывать функцию `send_alert(rule, value)`, которая для каждого канала из правила вызывает соответствующий обработчик.  
- Добавить эндпоинт `/api/test` для проверки каналов.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При срабатывании правила отправляются сообщения по всем указанным каналам.  
- Тестовый эндпоинт позволяет проверить каждый канал.  
- Ошибки отправки обрабатываются и логируются.  
- При недоступности канала алерт не теряется (повторные попытки).
