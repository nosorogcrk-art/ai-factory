
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P18.1.3 (LEVEL 5)

**ID:** P18.1.3  
**Контейнер:** C18.1 (Log Aggregator)  
**Название:** Пакетная отправка  

**Зависимости:** P18.1.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить возможность принимать несколько логов в одном запросе (пакетная отправка) для снижения накладных расходов на HTTP. Это повысит эффективность при высокой нагрузке.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Эндпоинт:** `POST /api/logs` теперь может принимать как один объект, так и массив объектов.  
- **Логика:**  
  – Если тело запроса – массив, обработать каждый элемент по отдельности: валидация, запись в файл.  
  – Если хотя бы один лог не проходит валидацию, возвращать `400 Bad Request` с указанием индекса и ошибки.  
  – При успешной обработке всех логов возвращать `202 Accepted` (или `200 OK`).  
- **Производительность:**  
  – Запись в файл может быть буферизована для уменьшения числа операций ввода-вывода. Например, накапливать логи в памяти и сбрасывать на диск раз в несколько секунд или по достижении определённого размера. Это улучшит производительность при пакетной отправке.  
- **Валидация:** та же, что и для одиночного лога.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Модифицировать эндпоинт `POST /api/logs`: проверить тип входных данных (dict или list).  
- Для списка выполнить итерацию, собирая ошибки.  
- Для повышения производительности можно использовать асинхронную запись с буферизацией (например, через очередь и фоновый писатель). Однако на данном этапе допустима синхронная запись каждого лога (при пакетной отправке это может быть медленно). Рекомендуется ввести буфер.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При отправке массива из 10 корректных логов все они сохраняются.  
- При наличии в массиве некорректного элемента возвращается 400, ни один лог не сохраняется (или сохраняются корректные – вопрос атомарности; для простоты можно не сохранять ни одного при ошибке).  
- При одиночном запросе поведение не меняется.
