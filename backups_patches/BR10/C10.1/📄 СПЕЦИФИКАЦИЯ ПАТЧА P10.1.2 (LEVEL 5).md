### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P10.1.2 (LEVEL 5)

**ID:** P10.1.2  
**Контейнер:** C10.1 (Интегратор)  
**Название:** Добавить проверку актуальности навыков при сборке (заглушка)

**Зависимости:** P10.1.1 (базовый интегратор)

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Модифицировать скрипт `integrator.py` (или создать отдельный модуль проверки), добавив в него логику анализа спецификаций патчей для извлечения списка требуемых навыков (`required_skills`), но без реального обращения к BR17. На данном этапе все проверки заменяются заглушкой, которая всегда возвращает положительный результат (навыки считаются доступными). Это позволит в дальнейшем легко подключить реальную проверку, не меняя архитектуру.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Модифицируемый файл:** `agents/tools/integrator.py` (созданный в P10.1.1).  
- **Добавляемые функции:**  
  - `extract_required_skills(patch_list)` – анализирует спецификации патчей (файлы L5 в папке `01_ЦЕХ/ЧЕРНОВИКИ/СПЕКИ/`) и извлекает из них списки `required_skills`. Возвращает объединённый список всех требуемых навыков.  
  - `check_skills_stub(skills_list)` – заглушка, которая просто логирует список навыков и возвращает `{"ok": True, "details": {}}` (все навыки считаются доступными).  
- **Интеграция в основной процесс:**  
  - В начале работы интегратора (после получения списка патчей) вызывается `extract_required_skills`.  
  - Затем вызывается `check_skills_stub`. Если заглушка возвращает ошибку (что не предусмотрено), интеграция прерывается.  
  - Результат проверки логируется в `integrator.log` и отправляется в BR18 (через заглушку логирования).  
- **Логирование:** фиксировать, какие навыки требовались, и что проверка прошла успешно (заглушка).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В файл `integrator.py` добавить функцию `_extract_skills(patch_list)`, которая для каждого патча читает его спецификацию (если файл существует) и парсит поле `required_skills`. Формат спецификации предполагается Markdown с YAML-шапкой или простым списком. Для упрощения можно искать строку вида `- required_skills: ...` или `required_skills: [...]`.  
- Функция `_check_skills_stub(skills)` возвращает словарь `{"success": True, "message": ""}`.  
- В основном потоке после загрузки списка патчей добавить вызов:  
  ```python
  skills = _extract_skills(patches)
  if skills:
      check_result = _check_skills_stub(skills)
      if not check_result["success"]:
          logging.error("Skill check failed (stub)")
          sys.exit(1)
  ```  
- Логировать факт вызова и список навыков.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При запуске интегратора с набором патчей, в спецификациях которых есть поле `required_skills`, скрипт извлекает этот список и передаёт в заглушку.  
- Заглушка всегда возвращает успех, интеграция продолжается.  
- В логе фиксируется информация о проверенных навыках.  
- Если поле `required_skills` отсутствует, проверка пропускается.
