### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P10.2.2 (LEVEL 5)

**ID:** P10.2.2  
**Контейнер:** C10.2 (Стенд Приемки)  
**Название:** Добавить тесты на использование навыков (заглушка)

**Зависимости:** P10.2.1 (базовый стенд)

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Модифицировать скрипт `test_stand.py`, добавив в него возможность проверки использования навыков в тестируемом продукте. На данном этапе это заглушка: она не обращается к реальным сервисам BR17, а лишь имитирует проверку, всегда возвращая успех. Однако она должна читать метаданные о навыках из продукта (например, из файла `metadata.json`, который будет создаваться в будущем) и логировать информацию о том, какие навыки были бы проверены. Это подготовит инфраструктуру для последующей реальной интеграции (P10.2.4).

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Модифицируемый файл:** `agents/tools/test_stand.py` (созданный в P10.2.1).  
- **Новые функции:**  
  - `_load_skill_metadata(product_path)` – загружает файл `metadata.json` из корня продукта (если он есть) и извлекает список навыков, используемых в продукте (поле `skills`). Если файла нет, возвращает пустой список.  
  - `_check_skills_stub(skills)` – заглушка, которая для каждого навыка логирует его и возвращает `True` (проверка пройдена).  
- **Интеграция в основной процесс:**  
  - После успешного развёртывания продукта, но до запуска тестов, вызывать `_load_skill_metadata`.  
  - Если есть навыки, вызвать `_check_skills_stub` и записать результат в лог.  
  - Фактические тесты продукта выполняются как обычно (не зависят от заглушки).  
- **Логирование:**  
  - В `test_stand.log` фиксировать факт проверки навыков, список навыков и результат (всегда успех).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В `test_stand.py` добавить функцию `_load_skill_metadata(product_path)`, которая ищет `product_path / "metadata.json"`. Если файл существует, парсит его и возвращает список `skills` (ожидается, что это массив объектов с полем `id`). Если нет – возвращает пустой список.  
- Добавить функцию `_check_skills_stub(skills)`, которая просто пишет в лог: `"Stub skill check passed for skills: {skills}"` и возвращает `True`.  
- В основной функции `run_tests` после подготовки контейнера, перед вызовом `pytest`, добавить:  
  ```python
  skills = _load_skill_metadata(product_path)
  if skills:
      if not _check_skills_stub(skills):
          logging.warning("Skill check stub failed (should not happen)")
  ```  
- Убедиться, что наличие или отсутствие навыков не влияет на выполнение тестов.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При запуске тестов для продукта, содержащего файл `metadata.json` со списком навыков, в логе появляется запись о проверке навыков с перечислением их ID.  
- Если файла нет, проверка пропускается без ошибок.  
- Тесты выполняются независимо от результата заглушки.  
- Код содержит комментарии, указывающие, что в будущем заглушка будет заменена реальной интеграцией.
