### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.4.1 (LEVEL 5)

**ID:** P20.4.1  
**Контейнер:** C20.4 (Test Runner)  
**Название:** Базовая структура и синтаксические тесты  

**Зависимости:** отсутствуют

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Создать FastAPI-приложение для запуска тестов конфигураций. Реализовать базовую структуру сервиса и первый тип тестов – синтаксическую проверку файлов (JSON, YAML). Предоставить API для запуска тестов и получения результатов. На данном этапе тесты выполняются синхронно, результаты сохраняются в памяти или в БД.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Стек:** Python + FastAPI, Uvicorn, библиотеки: `jsonschema`, `pyyaml`.  
- **Порт:** 8108 (настраивается через переменную окружения `PORT`).  
- **Хранение результатов:** SQLite (таблица `test_results` с полями `id`, `job_id`, `status`, `passed`, `details`, `created_at`).  
- **API эндпоинты:**  
  - `POST /test` – запуск тестов. Принимает JSON:  
    ```json
    {
      "repo": "skills",
      "commit": "abc123",          // опционально, если не указан – тестировать последний коммит
      "files": ["path/file1.json"], // опционально, если не указан – все файлы репозитория
      "tests": ["syntax"]           // список тестов для запуска
    }
    ```  
    Возвращает: `{ "test_id": "tst_789", "status": "started" }`.  
  - `GET /results/{test_id}` – получение результатов теста. Возвращает статус и детали.  
  - `GET /health` – проверка работоспособности.  
- **Синтаксические тесты:**  
  – Для файлов с расширением `.json` – проверка валидности JSON (через `json.loads`).  
  – Для `.yaml`/`.yml` – проверка валидности YAML (через `yaml.safe_load`).  
  – Для остальных – пропуск (или считать успешными).  
  – Результат: `passed` (bool), ошибки (если есть).  
- **Загрузка файлов:** для получения файлов из репозитория используется вызов к C20.1 (GitOps Core). Адрес C20.1 задаётся переменной окружения `GITOPS_CORE_URL` (по умолчанию `http://c20.1:8105`). Запрашивать файлы можно через `GET /repos/{repo}/files/{path}?ref={commit}`.  
- **Локальное логирование:** файл `01_ЦЕХ/01_ЖУРНАЛЫ/test_runner.log`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать файл `test_runner.py` с FastAPI-приложением.  
- При старте инициализировать БД (таблица `test_results`).  
- В эндпоинте `POST /test`:  
  1. Сгенерировать `test_id` (UUID).  
  2. Создать запись в БД со статусом `running`.  
  3. Запустить фоновую задачу (через `BackgroundTasks`), которая выполнит синтаксические тесты.  
  4. Вернуть `test_id`.  
- Фоновая задача:  
  1. Получить список файлов (если не передан – определить по репозиторию).  
  2. Для каждого файла загрузить содержимое из C20.1.  
  3. Выполнить синтаксическую проверку.  
  4. Сохранить результаты в БД, обновить статус на `completed`.  
- Эндпоинт `GET /results/{test_id}` возвращает данные из БД.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Приложение запускается на порту 8108.  
- При отправке запроса на тестирование создаётся задача, возвращается ID.  
- Для корректного JSON-файла тест проходит, для некорректного – падает с ошибкой.  
- Результаты доступны через `/results`.  
- Локальный лог содержит записи о запусках.  
- Эндпоинт `/health` отвечает `{"status": "ok"}`.
