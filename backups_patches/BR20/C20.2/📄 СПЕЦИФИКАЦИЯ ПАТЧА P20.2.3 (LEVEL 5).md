
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.2.3 (LEVEL 5)

**ID:** P20.2.3  
**Контейнер:** C20.2 (Auto Deployer)  
**Название:** Интеграция с C20.4 (тесты)  

**Зависимости:** P20.2.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
После успешной синтаксической проверки запустить тесты через Test Runner (C20.4). Тесты должны выполняться для всех конфигураций, затрагиваемых деплоем. Результат тестов влияет на продолжение pipeline.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Интеграция с C20.4:**  
  – Адрес C20.4 задаётся переменной окружения `TEST_RUNNER_URL` (по умолчанию `http://c20.4:8108`).  
  – Вызывается эндпоинт `POST /test` с телом, содержащим информацию о репозитории и коммите (или списке файлов). Например:  
    ```json
    {
      "repo": "skills",
      "commit": "abc123",
      "tests": ["syntax", "semantic", "functional"]
    }
    ```  
  – Ожидается ответ `{ "test_id": "tst_789", "status": "started" }`.  
  – Затем необходимо периодически опрашивать `GET /results/{test_id}` до получения результата (polling).  
- **Ожидание результата:** в фоновой задаче организовать цикл с таймаутом.  
- **Действия по результату:**  
  – Если тесты пройдены (`passed: true`), деплой продолжается.  
  – Если не пройдены, деплой завершается с ошибкой, статус `failed`.  
- **Хранение:** результат тестов сохраняется в БД.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В фоновой задаче после синтаксической проверки:  
  1. Сформировать запрос к C20.4.  
  2. Отправить запрос, получить `test_id`.  
  3. В цикле (с задержкой) опрашивать `GET /results/{test_id}`.  
  4. При получении результата обработать.  
- При таймауте или ошибке – деплой прерывается.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При успешных тестах деплой продолжается.  
- При неуспешных тестах деплой останавливается, статус `failed`.  
- Результат тестов сохраняется.  
- При недоступности C20.4 деплой прерывается с ошибкой.
