
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.5.3 (LEVEL 5)

**ID:** P20.5.3  
**Контейнер:** C20.5 (Environment Manager)  
**Название:** Интеграция с BR0 (Docker API)  

**Зависимости:** P20.5.2

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить возможность управления контейнерами через Docker API (BR0) при деплое или изменении параметров окружения. Например, после применения новых конфигураций может потребоваться перезапуск контейнеров, обновление переменных окружения. Реализуется как опциональный шаг, вызываемый из C20.2 или вручную через API.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Интеграция с BR0:**  
  – Предполагается, что BR0 предоставляет доступ к Docker API через Unix-сокет или TCP.  
  – Для управления контейнерами используется библиотека `docker` для Python.  
  – Контейнеру Environment Manager необходим доступ к Docker-сокету (`/var/run/docker.sock`).  
- **Новые эндпоинты:**  
  - `POST /environments/{name}/restart` – перезапускает все контейнеры, связанные с указанным окружением (список контейнеров можно получить из параметров окружения, например, `params.containers`).  
  - `POST /environments/{name}/apply` – применить параметры окружения к контейнерам (обновить переменные окружения, перезапустить при необходимости).  
- **Логика применения:**  
  1. Получить список контейнеров из параметров окружения (поле `containers` в `params`).  
  2. Для каждого контейнера выполнить необходимые действия:  
     – Если нужно обновить переменные окружения, можно пересоздать контейнер с новыми переменными (или использовать `docker update`, но это ограничено).  
     – Проще перезапустить контейнер, чтобы он подхватил новые переменные из окружения.  
  3. Логировать результат.  
- **Безопасность:** доступ к этим эндпоинтам должен быть ограничен (аутентификация – будет в будущих патчах).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Добавить библиотеку `docker` в зависимости.  
- В эндпоинтах использовать клиент Docker (`docker.from_env()`).  
- Для перезапуска: `container.restart()`.  
- Для применения: можно просто перезапускать (более грубо), или реализовать логику обновления переменных через пересоздание контейнера.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При вызове `/restart` для окружения с указанными контейнерами они перезапускаются.  
- При вызове `/apply` происходит перезапуск (или обновление) контейнеров.  
- Ошибки (контейнер не найден, недоступность Docker) логируются и возвращаются.  
- Доступ к Docker сокету должен быть настроен.
