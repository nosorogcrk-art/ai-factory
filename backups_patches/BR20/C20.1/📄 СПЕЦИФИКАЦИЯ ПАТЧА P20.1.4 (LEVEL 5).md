
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P20.1.4 (LEVEL 5)

**ID:** P20.1.4  
**Контейнер:** C20.1 (GitOps Core)  
**Название:** Интеграция с BR12 (права доступа)  

**Зависимости:** P20.1.3

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить проверку прав доступа при выполнении операций, изменяющих репозиторий (создание веток, коммитов, слияние, теги). Для этого интегрироваться с системой аутентификации BR12, которая предоставляет API для проверки прав пользователя на основе переданного токена. На данном этапе можно реализовать заглушку, которая проверяет наличие токена в заголовке и при его отсутствии возвращает 401. В будущем заглушка будет заменена на реальные вызовы к BR12.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Механизм аутентификации:**  
  – При запросах к API (кроме `/health`, `/repos` для чтения) ожидается заголовок `Authorization: Bearer <token>`.  
  – Токен передаётся в BR12 для проверки. Адрес BR12 задаётся переменной окружения `BR12_AUTH_URL` (по умолчанию `http://br12:8080/api/auth/check`).  
  – Запрос к BR12: `POST /api/auth/check` с JSON-телом `{ "token": "token", "permission": "write" }` (или `"read"`).  
  – Ответ: `{ "allowed": true, "user": "...", "roles": [...] }`.  
- **Заглушка:** пока BR12 не реализован, разрешать все запросы с любым непустым токеном (или без токена, но с предупреждением). Можно добавить конфигурацию `AUTH_ENABLED` для включения/отключения проверки.  
- **Применение:** проверять права для всех методов, которые изменяют состояние (POST, PUT, DELETE). Для GET можно разрешить без проверки (или проверять чтение).  
- **Логирование:** фиксировать факт проверки, результат, ошибки.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать зависимость FastAPI `get_current_user(token: str = Header(...))`, которая вызывает заглушку (или реальный BR12).  
- В каждом эндпоинте, требующем прав, добавить эту зависимость.  
- Если проверка не пройдена, возвращать `401 Unauthorized` или `403 Forbidden`.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При запросе без токена (если аутентификация включена) возвращается 401.  
- С токеном (любым, пока заглушка) запрос проходит.  
- Если заглушка отключена, все запросы работают без проверки.  
- Логирование фиксирует попытки доступа.
