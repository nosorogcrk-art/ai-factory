## 🔧 Исправленная спецификация патча P2.6.1 (L5) – с учётом аудита

**ID:** P2.6.1  
**Контейнер:** C2.6 Project Memory  
**Название:** Базовая структура проектов  

---

### 1. Цель  
Создать базовое FastAPI-приложение, которое управляет проектами: создание, чтение, обновление, мягкое удаление. При создании проекта создаётся папка в `01_ЦЕХ/ПРОЕКТЫ/` и файл `metadata.json`. Данные о проектах хранятся в SQLite (таблица `projects`). Это фундамент для последующего хранения диалогов и артефактов.

---

### 2. Входные и выходные данные

- **Вход:**  
  – HTTP‑запросы к API (POST, GET, PATCH, DELETE).  
  – При создании проекта – JSON с полями `name` (обязательное) и `description` (опционально).

- **Выход:**  
  – JSON‑ответы с метаданными проекта (id, name, description, status, created_at, updated_at).  
  – При успешном создании – статус 201, при ошибках – 400, 404, 409 (если имя уже существует), 500.

---

### 3. Технические параметры

- **Стек:**  
  – Python 3.12, FastAPI, Uvicorn, Pydantic, SQLite3, httpx (для логов в BR18), python-dotenv.  
- **Порт:** 8090 (настраивается через переменную окружения `PORT`).  
- **Хранение:**  
  – SQLite: файл `01_ЦЕХ/ПРОЕКТЫ/projects.db`. Таблица `projects` с полями:  
    ```sql
    CREATE TABLE IF NOT EXISTS projects (
        id TEXT PRIMARY KEY,
        name TEXT NOT NULL,
        description TEXT,
        status TEXT DEFAULT 'active',
        created_at TEXT DEFAULT CURRENT_TIMESTAMP,
        updated_at TEXT DEFAULT CURRENT_TIMESTAMP
    );
    CREATE INDEX IF NOT EXISTS idx_projects_status ON projects(status);
    CREATE INDEX IF NOT EXISTS idx_projects_name ON projects(name);
    ```  
  – Файловая система:  
    - Корневая папка: `01_ЦЕХ/ПРОЕКТЫ/`.  
    - Для каждого проекта: `01_ЦЕХ/ПРОЕКТЫ/{project_id}/` (создаётся при создании проекта).  
    - Внутри папки – `metadata.json` (содержит те же поля, что и запись в БД). Это нужно для переносимости проекта.  
- **Генерация ID:** `proj_{uuid.hex[:8]}` (например, `proj_a1b2c3d4`).  
- **Уникальность имени:** при создании проверяется, нет ли активного проекта с таким же именем. Если есть – возвращается 409 Conflict.  
- **Восстановление при старте:** при запуске приложения сканируется папка `01_ЦЕХ/ПРОЕКТЫ/`. Для каждого подкаталога, если в БД нет записи с соответствующим `id`, создаётся запись из `metadata.json` (если файл существует). Если запись в БД есть, но папка отсутствует – статус проекта устанавливается в `archived` (или логируется ошибка). Это обеспечивает согласованность после переноса проекта.  
- **Мягкое удаление:** при DELETE меняем статус на `archived`. Запись остаётся в БД, папка не удаляется.  
- **Логирование:**  
  – Локальный файл: `01_ЦЕХ/01_ЖУРНАЛЫ/project_memory.log`.  
  – Отправка в BR18: **асинхронно** (через `BackgroundTasks` или `asyncio.create_task`), чтобы не блокировать ответ.  
    Формат: `{ "timestamp": "...", "service": "C2.6", "event_type": "project_created|project_updated|project_deleted", "details": {...} }`.  
- **Healthcheck:** эндпоинт `GET /health` возвращает `{"status": "ok"}`.  
- **Конфигурация:** переменные окружения: `PORT`, `BR18_URL`, `LOG_LEVEL`.  

---

### 4. Эндпоинты

- `GET /health` – healthcheck.  
- `POST /projects`  
  – Тело: `{ "name": "...", "description": "..." }`.  
  – Проверка уникальности имени (активные проекты).  
  – Генерация `id`.  
  – Создание записи в БД, папки, `metadata.json`.  
  – Асинхронная отправка лога в BR18.  
  – Возврат 201 с метаданными.  
- `GET /projects`  
  – Параметр `include_archived` (опционально, default false).  
  – Возвращает список проектов (без пагинации – можно добавить позже).  
- `GET /projects/{id}`  
  – Возвращает метаданные, если проект не архивный. Если `include_archived=true` в query – возвращает и архивные.  
  – При отсутствии – 404.  
- `PATCH /projects/{id}`  
  – Тело: `{ "name": "...", "description": "..." }` (оба опциональны).  
  – Обновляет БД и `metadata.json`.  
  – Обновляет `updated_at`.  
  – Асинхронный лог.  
- `DELETE /projects/{id}`  
  – Меняет статус на `archived` в БД и в `metadata.json`.  
  – Возвращает 204 No Content.  

---

### 5. Обработка ошибок

| Ситуация | HTTP статус | Ответ |
|----------|-------------|-------|
| Отсутствует `name` в POST | 400 | `{"detail": "name is required"}` |
| Проект с таким именем уже существует (активный) | 409 | `{"detail": "project with this name already exists"}` |
| Проект не найден (GET/PATCH/DELETE) | 404 | `{"detail": "project not found"}` |
| Внутренняя ошибка | 500 | `{"detail": "internal server error"}` |
