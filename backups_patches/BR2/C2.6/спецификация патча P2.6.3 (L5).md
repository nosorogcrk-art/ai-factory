## 🔧 Исправленная спецификация патча P2.6.3 (L5) – с учётом аудита

**ID:** P2.6.3  
**Контейнер:** C2.6 Project Memory  
**Название:** Интеграция с Chroma и семантический поиск  

---

### 1. Цель  
Добавить семантический поиск по истории диалогов и содержимому артефактов. Каждый проект получает отдельную коллекцию в Chroma. При добавлении сообщения или артефакта текст автоматически индексируется. При удалении артефакта или проекта вектор удаляется из коллекции. При старте сервиса выполняется выборочная синхронизация (только недостающие данные).

---

### 2. Технические параметры  

#### 2.1. Векторное хранилище  
- **Библиотека:** Chroma (PersistentClient).  
- **Папка:** `01_ЦЕХ/ПРОЕКТЫ/chroma_data/`. Создаётся при инициализации.  
- **Коллекция для проекта:** имя `project_{project_id}` с заменой дефисов на подчёркивания (`project_id.replace('-', '_')`).  
- **Эмбеддинги:** `embedding_functions.SentenceTransformerEmbeddingFunction(model_name="all-MiniLM-L6-v2")`.  

#### 2.2. Управление жизненным циклом векторов  

| Действие | Операция с Chroma |
|----------|------------------|
| **Добавление сообщения** | После сохранения в SQLite добавить документ в коллекцию. ID: `msg_{message_id}`. Метаданные: `type="message"`, `message_id`, `project_id`, `role`, `timestamp`. |
| **Добавление артефакта** | После сохранения файла и SQLite добавить документ в коллекцию. ID: `art_{artifact_id}`. Метаданные: `type="artifact"`, `artifact_id`, `artifact_type`, `name`, `version`. |
| **Удаление артефакта** | В эндпоинте `DELETE /projects/{id}/artifacts/{artifact_id}` после удаления записи из БД и файла выполнить `collection.delete(ids=[f"art_{artifact_id}"])`. |
| **Архивация/удаление проекта** | При мягком удалении (`status = 'archived'`) коллекция не удаляется (она может понадобиться при восстановлении). При полном удалении (если реализовано) – удалить коллекцию через `client.delete_collection(name)`. |
| **Перезапуск сервиса** | Восстановление: для каждого проекта сравнить количество документов в Chroma и в SQLite. Индексировать только недостающие (по ID). Не переиндексировать всё. |

#### 2.3. API семантического поиска  

- **Эндпоинт:** `POST /projects/{project_id}/search`  
- **Тело запроса:**  
  ```json
  {
    "query": "строка для поиска",
    "n_results": 5
  }
  ```  
- **Ответ (200 OK):**  
  ```json
  {
    "results": [
      {
        "score": 0.95,
        "type": "message",
        "id": 1,
        "content": "Привет, система!",
        "metadata": {
          "role": "user",
          "timestamp": "2026-03-23T22:49:30.682484+00:00"
        }
      },
      {
        "score": 0.87,
        "type": "artifact",
        "id": "art_26b5e033",
        "content": "print(\"Hello\")",
        "metadata": {
          "artifact_type": "code",
          "name": "test.py",
          "version": "1.0"
        }
      }
    ]
  }
  ```  
- **Ошибки:**  
  – 404 – проект не найден.  
  – 503 – Chroma недоступен (ошибка при поиске).  
  – 500 – внутренняя ошибка.  

#### 2.4. Выборочная синхронизация при старте  

Функция `reindex_project(project_id)`:
1. Получает все ID сообщений (`msg_*`) из SQLite и ID артефактов (`art_*`) из БД.  
2. Запрашивает из коллекции Chroma существующие ID (через `collection.get(ids=...)` или простым получением всех).  
3. Для каждого отсутствующего ID извлекает текст (сообщение – `content`, артефакт – читает файл) и добавляет в коллекцию.  

Функция `reindex_all_projects()`:  
- Проходит по всем проектам со статусом `active` (и, возможно, `archived` – по желанию) и вызывает `reindex_project` для каждого, но с ограничением по времени или в фоне (чтобы не затягивать запуск).  

#### 2.5. Логирование и обработка ошибок  

- При добавлении вектора ошибки логируются, но не отменяют основное сохранение.  
- При удалении вектора ошибки логируются, но не влияют на успешность удаления (запись уже удалена из БД).  
- При поиске, если Chroma недоступен – возвращать 503 с сообщением.
