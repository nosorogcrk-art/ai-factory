
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P6.3.2 (LEVEL 5)

**ID:** P6.3.2  
**Контейнер:** C6.3 (Token Guard)  
**Название:** Проверка лимитов перед запросом

**Зависимости:** P6.3.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить эндпоинт `GET /check`, который агенты вызывают перед выполнением запроса к LLM, чтобы проверить, не превышен ли лимит. Эндпоинт анализирует текущий расход, учитывая оценочное число токенов, и возвращает разрешение или отказ, а также может предложить альтернативную модель.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Эндпоинт `GET /check`:**  
  – Параметры (query string): `agent_id`, `model`, `estimated_tokens` (опц.), `task_id` (опц.), `branch` (опц.).  
  – Логика:  
    1. Определить, какие лимиты затрагиваются (глобальный, ветка, агент, тип задачи).  
    2. Для каждого лимита проверить, не превысит ли текущий расход + `estimated_tokens` допустимое значение.  
    3. Если превышение по запрашиваемой модели, но есть альтернативная (из конфига), вернуть `{"allowed": true, "suggested_model": "..."}`.  
    4. Если превышение и альтернатив нет, вернуть `{"allowed": false, "reason": "limit exceeded"}`.  
    5. Иначе `{"allowed": true}`.  
- **Конфигурация альтернативных моделей:**  
  – В `limits_config.json` добавить раздел `model_alternatives`, например:  
    ```json
    {
      "model_alternatives": {
        "gpt-4": ["gpt-3.5-turbo", "claude-instant"]
      }
    }
    ```  
- **Оценочные токены:** если `estimated_tokens` не передан, используется среднее значение для данной модели (можно хранить в конфиге).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Добавить эндпоинт `GET /check` в FastAPI.  
- Реализовать функцию `check_limits(agent, branch, model, estimated_tokens)`, которая обращается к БД за текущими расходами.  
- Для получения альтернатив использовать конфиг.  
- Возвращать JSON-ответ.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При запросе с параметрами, не превышающими лимиты, возвращается `{"allowed": true}`.  
- При превышении с альтернативой возвращается `{"allowed": true, "suggested_model": "..."}`.  
- При превышении без альтернативы возвращается `{"allowed": false}`.  
- Все проверки учитывают уже накопленные расходы.
