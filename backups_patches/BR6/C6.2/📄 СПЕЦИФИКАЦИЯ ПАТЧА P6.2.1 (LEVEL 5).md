### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P6.2.1 (LEVEL 5)

**ID:** P6.2.1  
**Контейнер:** C6.2 (Semantic Auditor)  
**Название:** Базовый модуль проверки traceability  

**Зависимости:** отсутствуют

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Реализовать функцию, которая проверяет каждый патч (задачу) из реестра задач на наличие связи с узлом Вики-Вселенной (BR2). Связь может быть указана в поле `related_entities` записи задачи или в виде явной ссылки `[[ID]]` в спецификации патча (L5). Патчи без такой связи должны считаться нарушающими принцип traceability. Результаты проверки сохраняются в локальный журнал.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Источники данных:**  
  – Реестр задач: `01_ЦЕХ/ТЕКУЩИЕ_ЗАДАЧИ/task_registry.json`.  
  – Спецификации патчей (L5): файлы в `01_ЦЕХ/ЧЕРНОВИКИ/СПЕКИ/` с именами вида `<ID патча>.md`.  
- **Алгоритм проверки:**  
  1. Загрузить список всех задач из реестра.  
  2. Для каждой задачи с типом `improvement` или любой задачи, имеющей статус, проверить наличие поля `related_entities` (массив строк). Если поле есть и не пусто – задача считается удовлетворяющей traceability.  
  3. Если поле отсутствует или пусто, попытаться найти файл спецификации по пути `01_ЦЕХ/ЧЕРНОВИКИ/СПЕКИ/<task_id>.md`. Если файл существует, прочитать его и найти в нём любые ссылки вида `[[ID]]` (регулярное выражение). Если ссылки найдены – задача считается ок, и эти ID добавляются в поле `related_entities` (можно обновить реестр или просто зафиксировать).  
  4. Если ни поле, ни ссылки не найдены – задача помечается как нарушающая traceability.  
- **Действия при обнаружении нарушения:**  
  – Записать в локальный журнал `01_ЦЕХ/01_ЖУРНАЛЫ/semantic_audit.log` информацию о задаче и типе нарушения.  
  – (Опционально) обновить статус задачи в реестре на `BLOCKED` – пока не требуется, это будет в P6.2.4.  
- **Выходные данные:**  
  – Список задач с нарушениями (можно сохранять в JSON-файл для последующего использования).  
- **Логирование:** все действия записываются в указанный лог-файл в формате JSON Lines.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать файл `traceability_check.py`.  
- Определить функцию `check_traceability()`:  
  - Загрузить реестр задач.  
  - Для каждой задачи извлечь `related_entities`. Если поле есть и не пусто – пропустить.  
  - Иначе попытаться найти файл спецификации.  
  - При наличии файла прочитать его, извлечь ссылки, добавить их в временный список.  
  - Если после всех попыток список ссылок пуст – зафиксировать нарушение.  
- Логировать каждое нарушение с указанием ID задачи и типа (отсутствие поля или отсутствие ссылок в спецификации).  
- Функция возвращает словарь со статистикой (сколько проверено, сколько нарушений).  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Скрипт успешно обрабатывает существующие задачи.  
- Для задачи без поля `related_entities`, но с файлом спецификации, содержащим ссылки, нарушение не фиксируется.  
- Для задачи без поля и без файла спецификации (или файл без ссылок) фиксируется нарушение.  
- Лог-файл создаётся и содержит записи о нарушениях.  
- Скрипт не модифицирует реестр задач (только читает).
