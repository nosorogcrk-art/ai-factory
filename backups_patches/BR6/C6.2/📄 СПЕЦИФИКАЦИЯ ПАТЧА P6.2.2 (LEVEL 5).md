### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P6.2.2 (LEVEL 5)

**ID:** P6.2.2  
**Контейнер:** C6.2 (Semantic Auditor)  
**Название:** Анализ противоречий в документах  

**Зависимости:** P6.2.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Добавить возможность выявления логических противоречий между документами Вики-Вселенной (BR2). Используя семантический поиск (C2.3), находить документы, которые могут содержать противоположные утверждения. Для оценки противоречий можно использовать пороговое значение релевантности и, опционально, вызов LLM для классификации. Результаты фиксируются в отчёте.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Источник данных:**  
  – Список всех документов из индексатора BR2 (C2.2) или прямой обход файлов.  
- **Семантический поиск:** для каждого документа формируется запрос к C2.3, чтобы найти другие документы, близкие по смыслу.  
- **Пороги:**  
  – `similarity_threshold` – минимальный косинусный коэффициент (например, 0.8) для отбора кандидатов.  
  – `contradiction_threshold` – может быть реализован через LLM (позже). На первом этапе можно просто считать все пары документов с высокой близостью потенциально противоречивыми и выводить их в отчёт.  
- **Алгоритм:**  
  1. Получить список всех документов (их ID и текст).  
  2. Для каждого документа выполнить семантический поиск по всем документам, исключая сам документ, с порогом `similarity_threshold`.  
  3. Для каждой найденной пары записать в отчёт как потенциальное противоречие.  
  4. (Опционально) передать пару в LLM для проверки на противоречие.  
- **Выход:** JSON-файл с перечнем пар документов, которые могут противоречить друг другу.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать функцию `detect_contradictions()`.  
- Использовать API C2.3 для семантического поиска (эндпоинт `/search`).  
- Для экономии можно сначала получить все ID документов, а затем для каждого выполнять поиск с ограничением `k`.  
- Результаты сохранять в `contradictions_report.json`.  
- Логировать количество проверенных документов и найденных потенциальных противоречий.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Скрипт успешно обращается к C2.3.  
- При обнаружении документов с высокой семантической близостью они фиксируются в отчёте.  
- При недоступности C2.3 скрипт выдаёт ошибку и завершается.  
- Логирование работает.
