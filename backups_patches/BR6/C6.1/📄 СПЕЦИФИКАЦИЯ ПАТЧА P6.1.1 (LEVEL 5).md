### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P6.1.1 (LEVEL 5)

**ID:** P6.1.1  
**Контейнер:** C6.1 (Chaos Monkey)  
**Название:** Базовый модуль остановки контейнера

**Зависимости:** отсутствуют

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Реализовать базовую функциональность Chaos Monkey: возможность остановить указанный Docker-контейнер и дождаться его автоматического восстановления (или зафиксировать отсутствие восстановления). Это первый шаг к созданию полноценного инструмента тестирования отказоустойчивости. На данном этапе типы сбоев ограничены только остановкой контейнера (`docker stop`). Результат эксперимента (успех/неудача, время восстановления) логируется локально.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Язык:** Python 3.11.  
- **Библиотеки:** `docker` (Docker SDK для Python), `logging`, `time`.  
- **Функциональность:**  
  – Функция `stop_container(container_name: str, timeout: int = 30) -> dict`, которая:  
    * через Docker API останавливает указанный контейнер (`container.stop()`).  
    * ожидает, пока контейнер не перейдёт в состояние `running` (или пока не истечёт таймаут). Для проверки используется `container.reload()` и проверка статуса.  
    * возвращает словарь с результатом: `{"recovered": bool, "recovery_time_ms": int, "error": str}`.  
  – В случае, если контейнер не восстановился в течение таймаута, фиксируется ошибка.  
- **Логирование:**  
  – Результаты каждого вызова записываются в файл `01_ЦЕХ/01_ЖУРНАЛЫ/chaos_monkey.log` в формате JSON Lines.  
  – Пример записи:  
    ```json
    {"timestamp": "...", "container": "br1", "action": "stop", "recovered": true, "recovery_time_ms": 2500, "error": null}
    ```  
- **Конфигурация:**  
  – Таймаут ожидания восстановления задаётся через переменную окружения `RECOVERY_TIMEOUT` (по умолчанию 120 секунд).  
- **Интеграция с Docker:** контейнер должен иметь доступ к Docker-сокету (монтирование `/var/run/docker.sock`).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать файл `chaos_monkey.py`.  
- В функции `stop_container` использовать `docker.from_env()` для получения клиента.  
- Получить контейнер по имени. Если контейнер не существует – вернуть ошибку.  
- Остановить контейнер и засечь время. Затем в цикле проверять статус, пока не истечёт таймаут.  
- При восстановлении зафиксировать время и вернуть успех.  
- Логировать результат.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При вызове функции с именем существующего контейнера он останавливается.  
- После остановки функция ожидает восстановления (если контейнер настроен на автоматический перезапуск).  
- Возвращается корректный результат (успех/неудача).  
- Логирование работает.  
- Код обрабатывает ошибки (контейнер не найден, таймаут).
