### **C10.2: Стенд Приемки**

**Ветка-родитель:** BR10 | **ID:** C10.2 | **Ответственный:** ГЕФЕСТ / РЕВА (совместно)

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Создание и поддержка изолированной среды для автоматизированного тестирования собранного продукта перед релизом. Стенд запускает тесты, проверяет соответствие функциональных требований и архитектурному замыслу, выявляет регрессии, а также верифицирует корректность использования навыков (из BR17) в коде продукта. Обеспечивает, что продукт правильно взаимодействует с навыками, передаёт ожидаемые параметры и обрабатывает результаты.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**  

- **Тестовая среда:** изолированное окружение (Docker-контейнер или виртуальная машина), в котором разворачивается собранный продукт. Среда настраивается так, чтобы иметь доступ к тестовым версиям навыков (мокам) или к реальным навыкам, но с контролируемыми параметрами.  

- **Автоматические тесты:** выполнение набора тестов (юнит-тесты, интеграционные, end-to-end) согласно конфигурации. В тесты включены проверки использования навыков:  
  – Для каждого навыка, заявленного в метаданных продукта (из C10.3), создаются тестовые сценарии, проверяющие корректность вызовов (аргументы, частота, обработка ошибок).  
  – При необходимости навыки замещаются мок-объектами, которые эмулируют их поведение и записывают историю вызовов для последующей проверки.  
  – Используется интеграция с **BR17 (C17.4 Skill Tester)** для получения эталонных тестовых данных или для запуска тестов навыков в изолированном режиме.  

- **Проверка метаданных навыков:**  
  – Перед запуском тестов стенд может запросить у **C10.3 (Упаковщик)** метаданные о требуемых навыках (список `required_skills` с версиями).  
  – Сверяет, что все необходимые навыки доступны в тестовом окружении (либо через моки, либо через реальные вызовы к BR17).  

- **Сбор отчётов:** формирование детализированного отчёта о прохождении тестов:  
  – Успешность/неудачи по каждому тесту.  
  – Покрытие кода (если измеряется).  
  – Результаты проверки использования навыков (количество вызовов, соответствие параметров, ошибки).  
  – Время выполнения.  

- **Интеграция с реестром задач:** при успешном прохождении всех тестов задача переводится в статус `ON_RELEASE`, при неудаче – возвращается на доработку с приложением отчёта.  

- **Логирование:** все действия стенда, включая результаты тестирования навыков, записываются в `01_ЦЕХ/01_ЖУРНАЛЫ/test_stand.log`, а также отправляются в **BR18 (Log Aggregator)** для централизованного мониторинга и анализа.  

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**  

- **Input:**  
  – Собранный продукт (артефакты, код, метаданные о навыках).  
  – Набор тестов (может передаваться как файл с описанием или как ссылка на репозиторий).  
  – (Опционально) запросы к BR17 для получения тестовых данных или статуса навыков.  

- **Output:**  
  – Отчёт о тестировании в формате JSON/Markdown.  
  – Обновлённый статус задачи в реестре (`task_registry.json`).  
  – Логи (в BR18).  

**4. ИНТЕГРАЦИИ**  

- **BR17 (Skills Repository):**  
  – **C17.4 Skill Tester** – для получения тестовых сценариев навыков или запуска их в изолированном режиме.  
  – **C17.1 Skill Registry** – для проверки существования навыков, указанных в метаданных.  
- **BR18 (Monitoring):** отправка логов и метрик тестирования.  
- **BR10 (C10.3 Упаковщик):** получение метаданных о навыках, встроенных в продукт.  
- **BR7 (Workforce):** обновление статуса задач.  

**5. СТЕК ТЕХНОЛОГИЙ**  

- Docker (для изоляции тестовой среды).  
- Фреймворки тестирования (pytest, unittest, JUnit и др. – в зависимости от стека продукта).  
- Библиотеки для создания моков (unittest.mock, pytest-mock).  
- Python-скрипты для оркестрации тестов, сбора результатов, вызовов API BR17.  
- HTTP-клиент для взаимодействия с BR17.  
- JSON-отчёты.  

**6. СПИСОК ПАТЧЕЙ И ИХ ФУНКЦИИ**  

- **P10.2.1 (Базовый стенд):** Скрипт `test_stand.py`, который запускает контейнер с продуктом и выполняет переданный набор тестов, сохраняет результаты.  
- **P10.2.2 (Интеграция с реестром задач):** Модуль, который после выполнения тестов обновляет статус задачи в `task_registry.json` в зависимости от результатов.  
- **P10.2.3 (Метрики тестирования):** Добавление сбора метрик (покрытие кода, время выполнения) и их сохранение в отдельный файл для последующего анализа.  
- **P10.2.4 (Тестирование использования навыков):** Доработка стенда для поддержки проверок навыков:  
  – Чтение метаданных о навыках из C10.3.  
  – Создание мок-окружения для навыков (возможно, через интеграцию с C17.4).  
  – Добавление в отчёт секции о результатах тестирования навыков.  
  – Логирование в BR18.  
  – Этот патч выполняется после того, как BR17 и C10.3 достигнут необходимой зрелости.
