
### 📄 ПАСПОРТ КОНТЕЙНЕРА C19.3: SKILL UPDATER (ОБНОВИТЕЛЬ НАВЫКОВ)

**Ветка-родитель:** BR19 | **ID:** C19.3 | **Ответственный:** [назначить]

---

#### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ
Автоматическое улучшение и обновление навыков в хранилище BR17 на основе анализа успешных кейсов выполнения задач (из логов C18.1) и выявленных паттернов ошибок (из C19.1). Выделяет эффективные приёмы, добавляет их в инструкции навыков в качестве новых примеров или уточнений, исправляет обнаруженные ошибки. Все изменения версионируются через C17.2 (Skill Version Control). Обеспечивает непрерывную эволюцию библиотеки навыков.

---

#### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **Входные данные:**  
  – Кластеризованные ошибки и успешные паттерны из C19.1 (Log Analyzer).  
  – Логи успешных выполнений задач (из C18.1), где задача была выполнена идеально или с высокими метриками.  
  – Текущая версия навыка из BR17 (C17.1).  

- **Анализ и извлечение улучшений:**  
  – Для успешных кейсов извлекаются фрагменты переписки, использованные инструменты, последовательности действий.  
  – С помощью LLM формируются рекомендации по дополнению инструкции навыка (новые примеры, более точные формулировки).  
  – Для ошибочных кейсов определяется, какие шаги навыка привели к ошибке, и формулируются исправления (например, добавление предупреждения, уточнение условия).  

- **Применение изменений:**  
  – Создаётся новая версия навыка через вызов C17.2 (коммит) и обновление метаданных в C17.1.  
  – Изменения сопровождаются комментарием (например, "добавлен пример обработки краевого случая").  
  – Обновлённый навык проходит тестирование в C17.4 (Skill Tester) перед публикацией.  

- **API:**  
  – `POST /update/{skill_id}` – запустить процесс обновления для конкретного навыка (с указанием фокуса: ошибки/успехи).  
  – `GET /updates` – история обновлений.  

- **Логирование:**  
  – Все действия по обновлению отправляются в C18.1.

---

#### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8103):**  
  – Пример запуска: `POST /update/SKILL-042`  
    ```json
    {
      "based_on": "errors",   // или "successes", "both"
      "max_suggestions": 3
    }
    ```  
    Ответ: `{ "job_id": "upd_abcde", "status": "started" }`  

- **Выход:** после завершения возвращает отчёт о внесённых изменениях.

---

#### 4. ИНТЕГРАЦИИ

- **C19.1 (Log Analyzer):** получение данных об ошибках и успешных кейсах.  
- **C18.1 (Log Aggregator):** прямой доступ к логам (если нужно).  
- **BR17 (Skills):** чтение навыка (C17.1), запись новой версии (C17.2), тестирование (C17.4).  
- **BR18 (Monitoring):** логирование.  

---

#### 5. СТЕК ТЕХНОЛОГИЙ

- Python + FastAPI.  
- Вызов LLM для генерации улучшений.  
- HTTP-клиент.  
- SQLite для истории обновлений.  
- Docker.
