### 📄 ПАСПОРТ КОНТЕЙНЕРА C19.1: LOG ANALYZER (АНАЛИЗАТОР ЛОГОВ) – ИСПРАВЛЕННАЯ ВЕРСИЯ

**Ветка-родитель:** BR19 | **ID:** C19.1 | **Ответственный:** [назначить]

---

#### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ
Инструмент глубинного анализа логов и метрик, поступающих из BR18 (Log Aggregator и Metrics Dashboard). Выполняет кластеризацию ошибок на основе семантических эмбеддингов, поиск повторяющихся проблем, выявление неэффективных паттернов поведения агентов, а также собирает статистику использования навыков и промптов. Результаты анализа (структурированные отчёты, выявленные паттерны, рекомендации) передаются в смежные компоненты BR19 (Prompt Optimizer, Skill Updater) и могут использоваться BR1 для стратегического планирования. Все операции логируются в BR18.

---

#### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **Источники данных:**  
  – **C18.1 (Log Aggregator):** получение логов за заданный период через API (`GET /api/logs`) или через потоковую подписку.  
  – **C18.2 (Metrics Dashboard):** получение агрегированных метрик для контекста.  
  – **C18.4 (Traceability Index):** для связывания логов с конкретными артефактами (патчи, задачи, навыки).  

- **Аналитические методы:**  
  – **Кластеризация ошибок** выполняется на основе семантических эмбеддингов, полученных через единый модуль `embedding_model.py` из контейнера C2.1 (Vector Store). Используется модель `sentence-transformers/all-MiniLM-L6-v2`.  
  – Нормализация текста ошибки: приведение к нижнему регистру, удаление дат, времени, IP-адресов, UUID; сохранение трёхзначных кодов (404, 500).  
  – **Алгоритм:** k‑means с автоматическим выбором числа кластеров (метод локтя) или фиксированное количество через переменную `FIXED_CLUSTERS`.  
  – **Выявление часто встречающихся последовательностей событий** (sequence mining) для обнаружения неэффективных сценариев.  
  – **Статистический анализ:** частота ошибок, среднее время выполнения, корреляция с используемыми навыками.  
  – **Использование LLM** (опционально) для семантического обобщения проблем (аннотация кластеров, формулировка рекомендаций).

- **Режим работы:**  
  – Запускается по расписанию (например, раз в сутки) для глубокого анализа исторических данных.  
  – Также может запускаться по триггеру (например, при накоплении определённого количества новых логов) или вручную через API.

- **Хранение результатов:**  
  – Результаты анализа (отчёты, кластеры ошибок) сохраняются в локальной БД (SQLite).  
  – Наиболее важные выводы могут отправляться в BR2 (как эволюционная память) и в BR18 (логи).

- **API:**  
  – `GET /health` – проверка работоспособности сервиса (возвращает `{"status": "ok"}`).  
  – `POST /analyze` – запуск анализа (с параметрами: период, типы событий, глубина).  
  – `GET /reports` – список доступных отчётов.  
  – `GET /reports/{id}` – получение конкретного отчёта.  
  – `GET /patterns` – список выявленных паттернов (ошибки, неэффективности).  
  – `POST /cluster` – запуск кластеризации ошибок (с опциональными фильтрами `from_time`, `to_time`, `service`).  
  – `GET /clusters` – список кластеров (с пагинацией).  
  – `GET /clusters/{cluster_id}` – детали конкретного кластера.

- **Логирование:**  
  – Все запуски анализа, ошибки и ключевые результаты отправляются в C18.1.

#### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8101):**  
  – Пример запуска кластеризации:  
    `POST /cluster`  
    ```json
    {
      "from_time": "2026-03-01T00:00:00Z",
      "to_time": "2026-03-31T23:59:59Z",
      "service": "C7.2"
    }
    ```  
    Ответ: `{ "job_id": "cluster_abc123", "status": "started" }`  
  – `GET /clusters` – возвращает список кластеров.

- **Выходные данные:**  
  – Отчёты в формате JSON, содержащие кластеры ошибок, частотные таблицы, рекомендации.

---

#### 4. ИНТЕГРАЦИИ

- **C18.1 (Log Aggregator):** чтение логов.  
- **C18.2 (Metrics Dashboard):** получение метрик.  
- **C18.4 (Traceability Index):** обогащение данных контекстом.  
- **BR2 (Memory):** отправка значимых выводов в эволюционную память.  
- **C19.2 (Prompt Optimizer):** передача выявленных проблем для улучшения промптов.  
- **C19.3 (Skill Updater):** передача паттернов для обновления навыков.  
- **BR1 (Мета-Мозг):** (опционально) уведомление о критических аномалиях.  
- **C2.1 (Vector Store):** использование модуля `embedding_model.py` для получения эмбеддингов.

---

#### 5. СТЕК ТЕХНОЛОГИЙ

- Python + FastAPI (микросервис).  
- Библиотеки для анализа данных: pandas, scikit-learn, numpy.  
- **sentence-transformers (версия 2.2.2 или выше)** – для эмбеддингов.  
- torch или onnxruntime (опционально, для ускорения).  
- HTTP-клиент (`httpx`) для взаимодействия с другими компонентами.  
- SQLite для хранения отчётов и кластеров.  
- Планировщик (`APScheduler`).  
- Docker.
