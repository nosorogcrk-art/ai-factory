
### 📄 ПАСПОРТ КОНТЕЙНЕРА C19.2: PROMPT OPTIMIZER (ОПТИМИЗАТОР ПРОМПТОВ)

**Ветка-родитель:** BR19 | **ID:** C19.2 | **Ответственный:** [назначить]

---

#### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ
Генерация улучшенных версий системных промптов на основе анализа логов (из C19.1), лучших практик промпт-инжиниринга (в том числе из внешних источников, индексированных BR2) и метрик эффективности. Создаёт несколько вариантов промпта, тестирует их на калибровочных кейсах (C3.3) и передаёт лучшие кандидаты в A/B Tester (C19.4). Обеспечивает непрерывное повышение качества работы агентов.

---

#### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **Входные данные:**  
  – Отчёты и выявленные проблемы из C19.1 (Log Analyzer).  
  – Текущие версии промптов из C7.1 (Identity Core) – через API.  
  – Внешние источники знаний (статьи, рекомендации) из BR2 (C2.3 семантический поиск).  
  – Результаты предыдущих A/B-тестов (из C19.4).  

- **Методы генерации:**  
  – Использование шаблонов с переменными частями (например, можно менять стиль, детализацию, примеры).  
  – Применение LLM для генерации вариантов на основе инструкций («создай более точную версию промпта, исправляющую следующие ошибки...»).  
  – Эволюционные алгоритмы (мутация, кроссовер) для комбинирования удачных фрагментов.  

- **Тестирование на калибровочных кейсах:**  
  – Перед отправкой в A/B тестер каждый вариант прогоняется на фиксированном наборе тестовых заданий из C3.3 (Training Simulator).  
  – Оцениваются метрики: точность, полнота, соответствие формату, время выполнения.  
  – Варианты, не прошедшие минимальный порог, отбрасываются.  

- **API:**  
  – `POST /optimize/{prompt_id}` – запустить оптимизацию для конкретного промпта (с указанием целевых метрик).  
  – `GET /candidates` – список сгенерированных кандидатов.  
  – `POST /candidates/{id}/promote` – отправить кандидата в A/B Tester.  

- **Хранение:**  
  – Кандидаты и результаты их тестирования сохраняются в локальной БД.

#### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8102):**  
  – Пример запуска: `POST /optimize/prompt_argus_v1`  
    ```json
    {
      "goals": ["reduce_errors", "improve_clarity"],
      "num_variants": 5
    }
    ```  
    Ответ: `{ "job_id": "opt_67890", "status": "started" }`  

- **Выход:** массив кандидатов с метриками.

#### 4. ИНТЕГРАЦИИ

- **C19.1 (Log Analyzer):** получение проблемных мест.  
- **C7.1 (Identity Core):** чтение текущих промптов.  
- **BR2 (Memory):** семантический поиск внешних практик.  
- **C3.3 (Training Simulator):** запуск тестов на калибровочных кейсах.  
- **C19.4 (A/B Tester):** передача кандидатов для эксперимента.  
- **BR18 (Monitoring):** логирование действий.
