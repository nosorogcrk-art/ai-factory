### **C4.3: Command Console (Консоль управления)** – ИСПРАВЛЕННАЯ ВЕРСИЯ

**Ветка-родитель:** BR4 | **ID:** C4.3 | **Ответственные:** АРХИ / ГЕФЕСТ

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Графический интерфейс для отправки команд агентам и системным компонентам завода. Консоль предоставляет Владельцу (или оператору) возможность вручную управлять задачами, патчами, навыками, CI/CD процессами, а также выполнять системные команды (просмотр логов, перезапуск сервисов). Все действия аутентифицируются, авторизуются и логируются для обеспечения безопасности и прослеживаемости.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**  

- **Архитектура:**  
  – Консоль является частью единого микросервиса BR4, включающего также компоненты C4.1 (Dashboard) и C4.2 (Graph Visualizer).  
  – Бэкенд на FastAPI предоставляет общие эндпоинты, включая `/api/command` для обработки команд.  
  – Фронтенд реализован как React-компонент, интегрированный в общее SPA (доступен по вкладке «Консоль»).  

- **Обработка команд:**  
  – Пользователь вводит текстовую команду в поле ввода (поддерживается отправка по Enter).  
  – Фронтенд отправляет POST-запрос на `/api/command` с JSON-телом: `{ "command": "deploy BR1" }`.  
  – Бэкенд выполняет следующие шаги:  
    1. Проверка аутентификации пользователя (получение роли из заголовка или сессии).  
    2. Парсинг команды с целью определения типа и целевой ветки (BR7, BR1, BR17, BR20, BR18, BR0).  
    3. Проверка прав: администратор может выполнять любые команды, оператор – только команды просмотра и управления задачами (без `deploy`, `restart`, `rollback`).  
    4. Вызов соответствующего API целевой ветки (см. раздел «Интеграции»). Для команды `restart` используется Docker API (BR0).  
    5. Логирование команды и результата в BR18 и локальный журнал.  
    6. Возврат результата фронтенду.  

- **Поддерживаемые команды (примеры):**  
  – `take <task_id>` – взять задачу в работу (BR7).  
  – `complete <task_id>` – завершить задачу (BR7).  
  – `delegate <task_id> <agent>` – передать задачу другому агенту (BR7).  
  – `cancel <task_id>` – отменить задачу (BR7).  
  – `create-patch <description>` – создать новый патч (BR1).  
  – `skill-status <skill_id>` – просмотр статуса навыка (BR17).  
  – `skill-update <skill_id>` – запустить обновление навыка (BR17).  
  – `deploy <branch>` – запустить деплой ветки (BR20).  
  – `rollback <branch>` – откатить изменения (BR20).  
  – `status` – общая сводка (агрегируется из разных источников).  
  – `logs <service>` – последние логи сервиса (BR18).  
  – `restart <service>` – перезапуск контейнера (BR0, через Docker API).  

- **История команд:**  
  – Локальный журнал сохраняется в файле `01_ЦЕХ/01_ЖУРНАЛЫ/console_history.log` в формате JSON Lines.  
  – На странице консоли отображаются последние 20 команд с результатами, доступна кнопка «повторить» (копирует команду в поле ввода).  

- **Логирование в BR18:**  
  – Каждая выполненная команда отправляется в Log Aggregator (C18.1) в формате:  
    ```json
    {
      "timestamp": "2026-03-18T12:00:00Z",
      "service": "C4.3",
      "event_type": "command_executed",
      "details": {
        "user": "admin",
        "command": "deploy BR1",
        "target_service": "BR20",
        "success": true,
        "output": "Deployment started",
        "execution_time_ms": 250
      }
    }
    ```

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**  

- **API бэкенда:**  
  – `POST /api/command` – принимает JSON с полем `command`, возвращает JSON с результатом:  
    ```json
    {
      "success": true,
      "output": "Deployment started",
      "execution_time_ms": 250
    }
    ```  
  – При ошибках прав доступа или неверной команде возвращается `success: false` и описание ошибки.  

- **Фронтенд:**  
  – React-компонент, встроенный в общее SPA, доступный по маршруту `/console`.  

**4. ИНТЕГРАЦИИ**  

- **BR7 (Workforce):**  
  – **C7.2 SAD Logic** – управление задачами (взять, завершить, делегировать, отменить).  
- **BR1 (Мета-Мозг):**  
  – **C1.2 Patch Architect** – создание патчей.  
- **BR17 (Skills):**  
  – **C17.1 Skill Registry** – просмотр статуса навыков.  
  – **C17.5 Skill Publisher** – запуск обновления навыка (через BR19).  
- **BR20 (CI/CD):**  
  – **C20.2 Auto Deployer** – запуск деплоя.  
  – **C20.3 Rollback Manager** – откат изменений.  
- **BR18 (Monitoring):**  
  – **C18.1 Log Aggregator** – получение логов (для команды `logs`).  
- **BR0 (Infrastructure):**  
  – **Docker API** – для команды `restart` (перезапуск контейнера).  
- **BR12 (Users):**  
  – Аутентификация и роли (перспективная интеграция).  

**5. СТЕК ТЕХНОЛОГИЙ**  

- **Бэкенд:** Python + FastAPI (в составе общего сервиса BR4).  
- **Фронтенд:** React (компонент в общем SPA).  
- **Логирование:** локальный файл JSON Lines + отправка в BR18 через HTTP.  
- **Контейнеризация:** единый Docker-контейнер для BR4.
