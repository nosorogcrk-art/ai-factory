### 📄 ПАСПОРТ КОНТЕЙНЕРА C2.6: PROJECT MEMORY

**ID:** C2.6  
**Ветка-родитель:** BR2 (Память)  
**Ответственный:** МНЕМОСИНА  

---

#### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ  
Управление изолированной памятью для каждого разрабатываемого проекта. Обеспечивает хранение диалогов, артефактов (патчи, спецификации, код) и предоставляет семантический поиск по всем данным проекта. Позволяет переносить проект между экземплярами завода путём копирования папки.

---

#### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)  

- **Хранение:**  
  – Корневая папка: `01_ЦЕХ/ПРОЕКТЫ/`.  
  – Каждый проект: `01_ЦЕХ/ПРОЕКТЫ/{project_id}/`  
    - `metadata.json` – название, даты, статус (active, archived).  
    - `dialogues.jsonl` – все сообщения (каждая строка – JSON).  
    - `artifacts/` – подпапки для патчей, спецификаций, кода.  
    - `vector_index/` – файлы векторной БД (Chroma).  
  – SQLite для метаданных (проекты, сообщения, артефакты) с индексами.

- **Векторный индекс (Chroma):**  
  – Для каждого проекта создаётся отдельная коллекция.  
  – При добавлении сообщения или артефакта автоматически генерируется эмбеддинг (через sentence-transformers) и сохраняется в коллекцию с метаданными (идентификатор, тип, путь к файлу).  
  – Эмбеддинги для сообщений вычисляются на основе содержимого сообщения; для артефактов – на основе текста файла (или извлечённого содержимого).  
  – API семантического поиска: `POST /projects/{id}/search` принимает текст, возвращает топ-K фрагментов с оценкой релевантности и метаданными.

- **API (внутренний):**  
  – `POST /projects` – создать проект (возвращает `project_id`).  
  – `GET /projects` – список проектов (только активные, или с параметром `include_archived`).  
  – `GET /projects/{id}` – метаданные проекта.  
  – `POST /projects/{id}/messages` – добавить сообщение (сохраняется в `dialogues.jsonl`, индексируется).  
  – `GET /projects/{id}/messages` – получить историю (с пагинацией).  
  – `POST /projects/{id}/artifacts` – добавить артефакт (тип, путь, содержимое или ссылку). Сохраняет файл, регистрирует в SQLite, индексирует.  
  – `POST /projects/{id}/search` – семантический поиск по всем индексированным данным (сообщения, артефакты).  
  – `DELETE /projects/{id}` – мягкое удаление (меняет статус на `archived`).  
  – Фоновая задача для полного удаления проектов, архивированных более N дней (удаляет папку и коллекцию).

- **Логирование:** все операции записываются в локальный файл `01_ЦЕХ/01_ЖУРНАЛЫ/project_memory.log` и отправляются в BR18.

---

#### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)  

- **Input:**  
  – HTTP-запросы к API.  
  – Содержимое артефактов при их сохранении.  

- **Output:**  
  – JSON-ответы с данными проектов, сообщений, результатами поиска.  
  – Файловая структура проектов.  

---

#### 4. ИНТЕГРАЦИИ  

- **BR18 (Monitoring):** отправка логов.  
- **C9.4 (Dialogue Manager):** вызовы `POST /projects/{id}/search`, `POST /projects/{id}/messages`.  
- **C4.4 (Dialogue Console):** вызовы `GET /projects`, `POST /projects`, `GET /projects/{id}/messages`.  
- **C1.2, C10.1 и другие агенты:** при необходимости могут запрашивать контекст через `POST /projects/{id}/search`.  

---

#### 5. СТЕК ТЕХНОЛОГИЙ  

- Python + FastAPI.  
- SQLite (с индексами на `project_id`, `timestamp`).  
- Chroma для векторного хранения.  
- sentence-transformers (или другой эмбеддер) для генерации эмбеддингов.  
- httpx для вызовов к BR18.  
- python-dotenv для переменных окружения.
