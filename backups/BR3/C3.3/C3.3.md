### **C3.3: Training Simulator (Тренировочный симулятор)** – ОБНОВЛЁННАЯ ВЕРСИЯ

**Ветка-родитель:** BR3 | **ID:** C3.3 | **Ответственный:** АРХИ

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Создание контролируемой среды («песочницы») для калибровки и тестирования агентов, а также для проверки корректности использования навыков. Позволяет прогонять типовые сценарии (кейсы), оценивать соответствие действий агентов Золотому стандарту и методологии, а также верифицировать, что агенты правильно применяют навыки из реестра BR17. Результаты тестов сохраняются для анализа и могут пополнять Эволюционную память (BR2) эталонными решениями.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**

- **Библиотека кейсов:** файлы с описанием тестовых заданий, эталонными результатами и критериями оценки. Хранятся в `00_КАНОН/Методология/Кейсы/`.  
  – Каждый кейс может включать требования к навыкам (например, `required_skills: ["SKILL-042", "SKILL-101"]`).  
  – Для кейсов, проверяющих навыки, в описании указывается, какой именно навык тестируется и какие ожидаются результаты.

- **Запуск теста:**  
  – Инициатором может выступать Аргус, Дедал или автоматический триггер (например, при обновлении навыка в BR17).  
  – Симулятор загружает кейс, определяет, требуется ли агенту использовать какие-либо навыки.  
  – При необходимости запрашивает у **C7.4 (Skill Integrator)** актуальные версии навыков и подставляет их в контекст агента (или в промпт).  
  – Запускает агента в изолированном режиме (через вызов его API или в отдельном контейнере), собирает результат.  
  – Сравнивает результат с эталоном по заданным критериям (метрики точности, полноты, соответствия формату).  

- **Интеграция с BR17 (навыки):**  
  – При запуске кейса, требующего навыков, симулятор может запросить у **C17.4 (Skill Tester)** информацию о том, прошёл ли навык внутренние тесты (опционально).  
  – Если навык не протестирован или отсутствует, кейс может быть пропущен с соответствующей пометкой.  

- **Логирование и отчёты:**  
  – Результаты каждого теста (успех/неудача, отклонения, время выполнения) отправляются в **BR18 (Log Aggregator)** в формате:  
    ```json
    {
      "timestamp": "2026-03-18T12:00:00Z",
      "service": "C3.3",
      "event_type": "test_run",
      "details": {
        "test_case": "L4_template_valid",
        "agent": "ГЕФЕСТ",
        "skills_used": ["SKILL-042"],
        "success": true,
        "deviation": 0.05,
        "duration_ms": 1200
      }
    }
    ```  
  – Полный отчёт сохраняется в `01_ЦЕХ/01_ЖУРНАЛЫ/Калибровка/` с указанием всех метрик.

- **Интеграция с BR2 (Память):** успешно пройденные кейсы (особенно те, где агент продемонстрировал идеальное выполнение) могут быть добавлены в Эволюционную память как эталонные решения для последующего обучения (через BR19).

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**

- **Input:**  
  – Запрос на калибровку агента (или всей команды) с указанием набора кейсов (может передаваться как список имён кейсов или тегов).  
  – Автоматический запуск при обновлении навыка (через webhook от BR17).  
- **Output:**  
  – Отчёт о прохождении тестов в формате JSON/Markdown.  
  – Логи (отправляются в BR18).  
  – (Опционально) предложение о добавлении эталона в BR2.

**4. ИНТЕГРАЦИИ**

- **BR17 (Skills Repository):** через C17.4 (Skill Tester) получает статус навыков, через C17.1 (Registry) проверяет существование навыков, указанных в кейсах.  
- **C7.4 (Skill Integrator):** для подгрузки актуальных версий навыков в тестируемого агента.  
- **BR18 (Monitoring):** логирование результатов тестов.  
- **BR2 (Memory):** сохранение успешных кейсов как эталонов.  
- **BR19 (Self-Learning):** результаты тестов могут использоваться для анализа эффективности агентов и навыков.  
- **BR4 (Visual Dashboard):** отображение прогресса калибровки и результатов тестов.

**5. СТЕК ТЕХНОЛОГИЙ**

- JSON/YAML для описания кейсов.  
- Python (скрипты для управления тестами, сравнения результатов, генерации отчётов).  
- HTTP-клиент для взаимодействия с BR17, C7.4, BR18.  
- Возможно, использование Docker для изоляции тестируемых агентов (опционально).  
- Библиотеки для статистического анализа (если требуется оценка отклонений).

**6. СПИСОК ПАТЧЕЙ И ИХ ФУНКЦИИ**

- **P3.3.1 (Библиотека кейсов):** создание структуры папок и первых тестовых кейсов (например, «правильное заполнение шаблона L4», «корректный переход статусов»).  
- **P3.3.2 (Движок симулятора):** скрипт `simulator.py`, который умеет загружать кейс, запускать агента (через вызов его инструментов или в изолированном процессе) и сравнивать результат.  
- **P3.3.3 (Интеграция с памятью):** сохранение успешных кейсов в Эволюционную память (BR2) для дальнейшего использования как «золотых решений».  
- **P3.3.4 (Поддержка тестирования навыков):** доработка симулятора для работы с навыками:  
  – Чтение полей `required_skills` из кейсов.  
  – Запрос актуальных версий навыков через C7.4.  
  – Валидация наличия навыков через BR17.  
  – Логирование использованных навыков в BR18.  
  – Этот патч выполняется после того, как C7.4 и BR17 реализованы.
