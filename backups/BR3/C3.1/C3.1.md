### **C3.1: Standards Lab (Лаборатория стандартов)** – ОБНОВЛЁННАЯ ВЕРСИЯ

**Ветка-родитель:** BR3 | **ID:** C3.1 | **Ответственный:** АРХИ

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Централизованная разработка, версионирование и распространение методологических документов: шаблонов для уровней L1–L6, Золотого стандарта, канонов и регламентов. Обеспечивает единую базу знаний о том, «как правильно» выполнять задачи на всех этапах конвейера. Шаблоны дополнены полями для указания требуемых навыков и ссылок на соответствующие записи в хранилище навыков (BR17), что позволяет формализовать зависимость задач от конкретных компетенций агентов.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**

- **Хранилище канонов:** файлы в формате Markdown, расположенные в `00_КАНОН/Методология/` (например, `ШАБЛОН_L1.md`, `ЗОЛОТОЙ_СТАНДАРТ.md`).  
- **Версионирование:** все изменения отслеживаются через Git (аналогично промптам). Каждая значимая правка фиксируется тегом `canon-<дата>-<номер>`. Интеграция с BR20 (CI/CD) обеспечивает автоматическое тестирование и деплой обновлённых шаблонов.  
- **Шаблоны с поддержкой навыков:**  
  – В шаблоны L4 (патчи) и L5 (спецификации) добавлены обязательные поля:  
    * `required_skills` – список идентификаторов навыков (например, `SKILL-042`, `SKILL-101`), необходимых для выполнения задачи.  
    * `skill_version_constraints` – опциональные ограничения на версии навыков (например, `>=1.2.0`).  
  – В шаблоны L1–L3 могут быть добавлены рекомендательные или справочные поля для указания потенциально полезных навыков.  
- **Автоматическая проверка:** скрипт валидации (`template_validator.py`) при изменении шаблонов:  
  – проверяет наличие всех обязательных разделов;  
  – сверяет указанные в `required_skills` идентификаторы с реестром навыков BR17 (через API C17.1) – если навык не существует или устарел, валидация не проходит.  
- **Публикация:** при успешном обновлении канона генерируется уведомление для агентов (через общий чат или личные сообщения) и для BR1 (Дедал) для учёта изменений в планировании.

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**

- **Input:**  
  – Запросы на создание/изменение методологических документов от АРХИ или ДЕДАЛА.  
  – Автоматические триггеры от BR20 при изменениях в Git-репозитории.  
- **Output:**  
  – Актуальные версии шаблонов и канонов.  
  – Результаты валидации (успех/ошибка).  
  – Уведомления об изменениях (в BR18, а также в интерфейс BR4 для ручного контроля).

**4. ИНТЕГРАЦИИ**

- **BR17 (Skills Repository):** через API C17.1 выполняется проверка существования и актуальности навыков, указанных в шаблонах.  
- **BR20 (CI/CD):** шаблоны хранятся в Git, изменения проходят через пайплайн (тестирование, деплой).  
- **BR18 (Monitoring):** логирование событий изменения шаблонов и результатов валидации.  
- **BR4 (Visual Dashboard):** отображение текущих версий методологических документов и оповещений.  
- **BR1 (Мета-Мозг):** получение уведомлений об изменениях для корректировки планирования.

**5. СТЕК ТЕХНОЛОГИЙ**

- Markdown + Git.  
- Python (скрипты валидации, интеграции с API BR17).  
- HTTP-клиент для запросов к BR17.  
- Библиотеки для работы с YAML/JSON (если метаданные шаблонов хранятся в структурированном виде).

**6. СПИСОК ПАТЧЕЙ И ИХ ФУНКЦИИ**

- **P3.1.1 (Структура методологии):** создание директории `00_КАНОН/Методология/` и базовых шаблонов L1–L6 (пустые каркасы).  
- **P3.1.2 (Золотой стандарт):** написание и утверждение основного документа «Золотой стандарт» (свод правил для всех агентов).  
- **P3.1.3 (Версионирование канонов):** скрипт `canon_versioning.py`, аналогичный `prompt_versioning.py`, для автоматического коммита и тегирования изменений в методологических файлах.  
- **P3.1.4 (Валидатор шаблонов):** скрипт `template_validator.py`, проверяющий наличие обязательных разделов и корректность ссылок на навыки через API BR17.  
- **P3.1.5 (Обновление шаблонов под навыки):** модификация существующих шаблонов L4 и L5 – добавление полей `required_skills` и `skill_version_constraints`. Этот патч выполняется после утверждения структуры навыков в BR17.
