### 📄 ПАСПОРТ КОНТЕЙНЕРА C20.1: GITOPS CORE (ЯДРО GITOPS)

**Ветка-родитель:** BR20 | **ID:** C20.1 | **Ответственный:** ГЕФЕСТ

---

#### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ
Центральное управление Git-репозиториями, в которых хранятся все конфигурационные файлы завода (системные промпты, навыки, MCP-конфиги, методологические каноны, шаблоны). Обеспечивает единую точку входа для изменений, управление ветками, политики слияния (merge), автоматическое создание тегов версий и контроль доступа. Интегрируется с системой аутентификации (BR12) для разграничения прав и с BR7 для привязки изменений к ролям. Предоставляет API для выполнения Git-операций другими компонентами (C20.2, C20.3, C20.4).

---

#### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **Хранение репозиториев:**  
  – Репозитории располагаются на томе Docker (например, `/data/git`).  
  – Для каждого типа конфигураций может быть отдельный репозиторий (например, `prompts.git`, `skills.git`, `canons.git`) или единый монорепозиторий с чёткой структурой папок. Настраивается через конфигурацию.  
  – При инициализации создаются базовые ветки: `main`, `develop`, при необходимости `staging`.

- **Управление доступом:**  
  – Интеграция с BR12 (Users): при выполнении операций (push, merge, создание тега) проверяется наличие у пользователя необходимых прав.  
  – Для автоматических действий от других контейнеров используется служебный токен.

- **API для Git-операций:**  
  – `GET /repos` – список репозиториев.  
  – `POST /repos/{repo}/branches` – создать ветку.  
  – `POST /repos/{repo}/commits` – выполнить коммит (принимает файлы, сообщение, автора).  
  – `POST /repos/{repo}/merges` – слияние веток.  
  – `POST /repos/{repo}/tags` – создать тег (версию).  
  – `GET /repos/{repo}/commits` – история коммитов.  
  – `GET /repos/{repo}/files/{path}?ref={branch/tag}` – получить содержимое файла.  

- **Валидация перед merge:**  
  – Перед слиянием в `main` можно автоматически запускать тесты (через вызов C20.4).  
  – Результат проверки влияет на разрешение merge.  

- **Логирование:**  
  – Все операции логируются в BR18 (C18.1) для аудита.

---

#### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8105):**  
  – Все эндпоинты принимают и возвращают JSON.  
  – Пример создания коммита:  
    `POST /repos/skills/commits`  
    ```json
    {
      "branch": "feature/new-skill",
      "files": [
        { "path": "skills/SKILL-042.json", "content": "{...}" }
      ],
      "message": "Add new refactoring skill",
      "author": "gefest"
    }
    ```  
    Ответ: `{ "commit_hash": "abc123", "status": "success" }`.

#### 4. ИНТЕГРАЦИИ

- **BR12 (Users):** аутентификация и авторизация.  
- **BR7 (Workforce):** привязка изменений к ролям.  
- **C20.2 (Auto Deployer):** вызывает C20.1 для получения изменений и тегов.  
- **C20.3 (Rollback Manager):** использует API для получения истории и отката.  
- **C20.4 (Test Runner):** может запускаться при merge.  
- **BR18 (Monitoring):** логирование.  

---

#### 5. СТЕК ТЕХНОЛОГИЙ

- Python + FastAPI.  
- Библиотека GitPython для работы с Git.  
- HTTP-клиент (`httpx`) для вызовов к BR12 и другим компонентам.  
- Docker (монтируемый том для репозиториев).
