
### 📄 ПАСПОРТ КОНТЕЙНЕРА C20.2: AUTO DEPLOYER (АВТОДЕПЛОЙ)

**Ветка-родитель:** BR20 | **ID:** C20.2 | **Ответственный:** ГЕФЕСТ

---

#### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ
Автоматический исполнитель pipeline непрерывной доставки: при обнаружении изменений в отслеживаемой ветке Git-репозитория (например, `main`) запускает последовательность шагов: клонирование, проверка синтаксиса, прогон тестов (через C20.4), применение конфигураций в целевом окружении (через C20.5 Environment Manager). Поддерживает стратегии деплоя (blue-green, canary) для минимизации рисков. Все действия логируются в BR18.

---

#### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **Триггеры:**  
  – Периодический опрос Git-репозитория (через C20.1) на наличие новых коммитов в отслеживаемой ветке.  
  – Webhook от Git-сервера (может быть добавлен позже).  

- **Pipeline шаги:**  
  1. Получить последний коммит/тег из C20.1.  
  2. Загрузить файлы конфигураций (через C20.1 `GET /files`).  
  3. Запустить синтаксическую проверку (линтеры) и семантическую валидацию (вызов C20.4).  
  4. Если тесты пройдены, запросить у C20.5 параметры целевого окружения (например, staging).  
  5. Применить конфигурации: для каждого типа конфигурации (промпты, навыки и т.д.) вызвать соответствующий API для обновления (например, для навыков – C17.5).  
  6. Зафиксировать результат деплоя (успех/неудача) и обновить статус в C20.1 (тег).  

- **Стратегии деплоя:**  
  – **Blue-green:** развернуть новую версию параллельно, затем переключить трафик. Требует поддержки со стороны целевых сервисов (может быть реализовано позже).  
  – **Canary:** постепенно увеличивать долю трафика на новую версию, отслеживая метрики через BR18.  

- **API:**  
  – `POST /deploy` – ручной запуск деплоя (с указанием репозитория, ветки, окружения).  
  – `GET /status` – статус текущих и последних деплоев.  

- **Логирование:**  
  – Все этапы pipeline логируются в C18.1.

---

#### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8106):**  
  – Пример ручного запуска: `POST /deploy`  
    ```json
    {
      "repo": "skills",
      "branch": "main",
      "environment": "staging"
    }
    ```  
    Ответ: `{ "deploy_id": "dep_123", "status": "started" }`  

- **Исходящие вызовы:** к C20.1 (чтение репозитория), C20.4 (тесты), C20.5 (получение параметров окружения), к целевым сервисам (C7.1, C17.5 и др.).

---

#### 4. ИНТЕГРАЦИИ

- **C20.1 (GitOps Core):** получение файлов и истории.  
- **C20.4 (Test Runner):** запуск тестов.  
- **C20.5 (Environment Manager):** получение параметров окружения.  
- **Целевые сервисы (C7.1, C17.5 и др.):** применение конфигураций.  
- **BR18 (Monitoring):** логирование.  
- **BR4 (Command Console):** ручной запуск через API.  

---

#### 5. СТЕК ТЕХНОЛОГИЙ

- Python + FastAPI.  
- HTTP-клиент (`httpx`).  
- Планировщик (APScheduler) для периодической проверки.  
- Docker.
