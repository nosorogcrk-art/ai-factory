
### 📄 ПАСПОРТ КОНТЕЙНЕРА C20.4: TEST RUNNER (ЗАПУСКАТЕЛЬ ТЕСТОВ)

**Ветка-родитель:** BR20 | **ID:** C20.4 | **Ответственный:** ГЕФЕСТ

---

#### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ
Набор автоматических тестов для валидации конфигураций перед деплоем. Включает синтаксическую проверку (JSON/YAML-валидаторы, линтеры), семантическую проверку (соответствие внутренним схемам, ссылочная целостность), функциональные тесты в изолированной среде (песочнице) для навыков и промптов (интеграция с C17.4 Skill Tester), а также тесты на регрессию (сравнение с эталонными ответами). Предоставляет API для запуска тестов и получения результатов.

---

#### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **Типы тестов:**  
  1. **Синтаксические:** проверка JSON-схем, YAML-линтеры, валидация Markdown (если применимо).  
  2. **Семантические:**  
     – Проверка, что все ссылки (например, `[[ID]]` или `SKILL-...`) ведут на существующие сущности (через вызовы к C17.1, BR2).  
     – Проверка уникальности идентификаторов.  
  3. **Функциональные:**  
     – Для навыков: запуск тестовых сценариев через C17.4 (Skill Tester).  
     – Для промптов: прогон на калибровочных кейсах C3.3 (Training Simulator).  
  4. **Регрессионные:** сравнение выходов с сохранёнными эталонами.  

- **Входные данные:**  
  – Набор файлов конфигураций (например, из C20.1 по коммиту).  
  – Метаданные о типах файлов (можно определить по расширению или пути).  

- **Режим работы:**  
  – Запускается синхронно (блокируя деплой до получения результата).  
  – Возможен асинхронный запуск с уведомлением по webhook.  

- **API:**  
  – `POST /test` – запустить тесты (передаётся список файлов или ссылка на коммит).  
  – `GET /results/{test_id}` – получить результаты.  

- **Логирование:**  
  – Результаты тестов и ошибки отправляются в C18.1.

---

#### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8108):**  
  – Пример запуска: `POST /test`  
    ```json
    {
      "repo": "skills",
      "commit": "abc123",
      "tests": ["syntax", "semantic", "functional"]
    }
    ```  
    Ответ: `{ "test_id": "tst_789", "status": "started" }`  
  – `GET /results/tst_789`  
    ```json
    {
      "passed": true,
      "details": {
        "syntax": { "passed": true, "errors": [] },
        "semantic": { "passed": true, "errors": [] },
        "functional": { "passed": true, "failed_tests": [] }
      }
    }
    ```

---

#### 4. ИНТЕГРАЦИИ

- **C20.1 (GitOps Core):** получение файлов по коммиту.  
- **C17.1 (Skill Registry), BR2 (Memory):** для семантических проверок.  
- **C17.4 (Skill Tester):** для функционального тестирования навыков.  
- **C3.3 (Training Simulator):** для тестирования промптов.  
- **BR18 (Monitoring):** логирование.  

---

#### 5. СТЕК ТЕХНОЛОГИЙ

- Python + FastAPI.  
- Библиотеки для валидации JSON (jsonschema), YAML (pyyaml).  
- HTTP-клиент.  
- Docker (может запускать изолированные тесты).
