### **C1.3: Self-Audit (Самоаудит)**

**Ветка-родитель:** BR1 | **ID:** C1.3 | **Ответственный:** ДЕДАЛ

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Анализ производительности агентов, качества выполнения задач и эффективности используемых промптов. На основе собранных метрик и данных из системы самообучения (BR19) формирует рекомендации по улучшению системных промптов, инициирует их обновление через BR7, а также пополняет эволюционную память (BR2) эталонными решениями. Обеспечивает непрерывный цикл повышения точности и надёжности работы агентов.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**  

- **Сбор метрик качества (P1.3.1):**  
  – Анализирует историю выполненных патчей: количество итераций ревью, наличие ошибок, соответствие результата замыслу, время выполнения.  
  – Вычисляет ключевые показатели: процент успешных задач с первого раза, среднее количество замечаний, частота возвратов на доработку.  
  – Метрики сохраняются локально и отправляются в **BR18 (Log Aggregator)** для долгосрочного хранения и визуализации.  

- **Получение аналитики из BR19:**  
  – Запрашивает у **C19.1 (Log Analyzer)** кластеризованные данные об ошибках агентов, повторяющихся паттернах, неэффективных стратегиях.  
  – Получает от **C19.2 (Prompt Optimizer)** предложения по улучшению промптов (кандидаты с обоснованием).  
  – Может запрашивать у **C19.4 (A/B Tester)** результаты сравнения текущих и экспериментальных версий промптов.  

- **Анализ и сравнение с эталонами:**  
  – Использует кейсы из **Training Simulator (BR3, C3.3)** для оценки точности работы агентов.  
  – Сравнивает текущие промпты агентов с эталонными (из BR3) и с предложениями BR19, выявляет слабые места.  
  – Для анализа может привлекать внешние LLM (например, DeepSeek) для генерации экспертных заключений.  

- **Инициирование улучшений:**  
  – Если качество работы агента ниже заданного порога (или если BR19 предлагает значимое улучшение), формирует рекомендацию по изменению промпта.  
  – Создаёт задачу (патч) в **BR7 (Identity Core)** на обновление промпта, прикладывая предложенную версию и обоснование.  
  – При необходимости инициирует A/B-тестирование через **C19.4** для сравнения текущего и нового промпта перед массовым внедрением.  

- **Обогащение эволюционной памяти:**  
  – Успешные патчи (выполненные с высоким качеством, без замечаний) добавляются в **BR2 (Memory)** как эталонные решения с пометкой "golden".  
  – Эти эталоны могут использоваться BR19 для обучения и BR3 для калибровки.  

- **Логирование:**  
  – Все действия (анализ, сравнение, создание задач) логируются в BR18 для последующего аудита и улучшения самого процесса самоаудита.  

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**  

- **Input:**  
  – Данные о выполненных патчах (из реестра задач и логов).  
  – Метрики качества (собранные P1.3.1).  
  – Кластеризованные данные об ошибках и предложения по промптам из BR19 (C19.1, C19.2).  
  – Результаты A/B-тестов из BR19 (C19.4).  
  – Эталонные кейсы из BR3 (C3.3).  
  – (Опционально) запросы на анализ от Владельца или других агентов.  

- **Output:**  
  – Рекомендации по изменению промптов (в BR7).  
  – Задачи на проведение A/B-тестов (в BR19).  
  – Новые эталонные решения (в BR2).  
  – Логи (в BR18).  

**4. ИНТЕГРАЦИИ**  

- **BR19 (Self-Learning):**  
  – **C19.1 Log Analyzer** – получение аналитики по ошибкам.  
  – **C19.2 Prompt Optimizer** – получение улучшенных версий промптов.  
  – **C19.4 A/B Tester** – запрос на проведение экспериментов и получение результатов.  
- **BR7 (Workforce):** создание задач на обновление промптов через C7.1.  
- **BR2 (Memory):** сохранение эталонных решений (через API индексации C2.2).  
- **BR3 (Methodology):** получение эталонных кейсов из C3.3.  
- **BR18 (Monitoring):** отправка метрик и логов.  
- **BR1 (Cognitive Engine, Patch Architect):** обмен данными о проблемах и рекомендациях (опционально).  

**5. СТЕК ТЕХНОЛОГИЙ**  

- Python (скрипты анализа, интеграции).  
- HTTP-клиенты для вызовов API BR19, BR7, BR2, BR3.  
- Библиотеки для статистического анализа (numpy, scipy).  
- (Опционально) вызовы LLM для экспертной оценки.  
- Логирование в `01_ЦЕХ/01_ЖУРНАЛЫ/self_audit.log` и отправка в BR18.  

**6. СПИСОК ПАТЧЕЙ И ИХ ФУНКЦИИ**  

| ID патча | Название | Краткое описание |
|----------|----------|------------------|
| **P1.3.1** | Сборщик метрик качества (`quality_metrics.py`) | Анализирует историю задач и ревью, вычисляет метрики (процент успешных с первого раза, среднее количество замечаний, частота возвратов на доработку). |
| **P1.3.2** | Анализатор промптов (`prompt_analyzer.py`) | Сравнивает текущие промпты агентов с эталонными (из BR3), выявляет слабые места, формулирует предложения по улучшению (без интеграции с BR19). |
| **P1.3.3** | Инициатор улучшений (`improvement_initiator.py`) | Создаёт задачи на обновление промптов (через BR7) и добавляет успешные кейсы в память (BR2) как эталонные решения. |
| **P1.3.4** | Интеграция с Log Analyzer (BR19) | Доработка анализатора для получения данных из C19.1; обогащение отчётов кластеризованными ошибками. |
| **P1.3.5** | Интеграция с Prompt Optimizer (BR19) | Получение от C19.2 кандидатов улучшенных промптов; добавление их в процесс анализа и сравнения. |
| **P1.3.6** | Интеграция с A/B Tester (BR19) | Возможность инициировать A/B-тесты для сравнения текущего и предлагаемого промпта; учёт результатов при принятии решения о внедрении. |

*Примечание:* патчи P1.3.4–P1.3.6 реализуются после того, как соответствующие компоненты BR19 достигнут необходимой зрелости. После их выполнения Self-Audit обретает полную функциональность, описанную в данном паспорте.
