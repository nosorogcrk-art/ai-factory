**Ветка-родитель:** BR18 | **ID:** C18.2 | **Ответственный:** [назначить]

---

#### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ

Сбор, агрегация и визуализация ключевых метрик производительности завода в реальном времени. Предоставляет API для получения агрегированных данных (используется C4.1 Project Dashboard) и веб-интерфейс для оперативного мониторинга. Метрики включают: количество выполненных задач, среднее время выполнения, частота ошибок, затраты токенов, загрузка агентов, статусы веток и др.

---

#### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **Источники данных:**  
    – **Логи из C18.1** – для расчёта метрик на основе событий (например, количество успешных handover, ошибки).  
    – **C18.5 (Cost Tracker)** – данные о затратах токенов.  
    – **C0.4 (Registry Manager)** – статусы веток.  
    – **BR7 (реестр задач)** – количество задач в работе и по статусам.  
    – **C6.3 (Token Guard)** – статистика использования токенов.  
    – Другие компоненты могут отправлять метрики напрямую через API (например, агенты сообщают о своей загрузке).
    
- **Агрегация:**  
    – Метрики рассчитываются в реальном времени (скользящие окна) или периодически (например, каждые 5 секунд).  
    – Хранятся в оперативной памяти (кольцевой буфер) для последних N значений, а также могут сохраняться в БД для долгосрочного анализа (опционально).  
    – Поддерживаются следующие агрегаты: среднее, максимум, минимум, сумма, p95, p99.
    
- **API:**  
    – `GET /api/metrics` – возвращает текущие значения всех ключевых метрик (в JSON).  
    – `GET /api/metrics/{name}` – конкретная метрика.  
    – `GET /api/metrics/history/{name}?from=...&to=...` – исторические данные (если хранятся).  
    – `POST /api/metrics` – приём метрик от компонентов (если они не выводятся из логов).
    
- **Веб-интерфейс:**  
    – Встроенная простая HTML-страница (на том же сервисе) с графиками, обновляемая через JavaScript (опрос API).  
    – Может использовать Chart.js или аналоги для отображения временных рядов.
    
- **Логирование:**  
    – События изменения метрик или ошибки агрегации отправляются в C18.1.
    

---

#### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8094):**  
    – Все эндпоинты возвращают JSON.  
    – Пример ответа `GET /api/metrics`:
    
    json
    
    {
      "tasks_completed_total": 1250,
      "tasks_failed_total": 12,
      "avg_duration_ms": 2340,
      "error_rate_percent": 0.96,
      "token_cost_usd": 15.42,
      "agents_active": 7
    }
    
    – Пример ответа `GET /api/metrics/history/avg_duration_ms?from=2026-03-18T10:00Z&to=2026-03-18T11:00Z`:
    
    json
    
    {
      "metric": "avg_duration_ms",
      "data": [
        {"timestamp": "2026-03-18T10:05Z", "value": 2100},
        {"timestamp": "2026-03-18T10:10Z", "value": 2450}
      ]
    }
    
- **Веб-интерфейс:**  
    – Доступен по корневому маршруту `/` (или `/dashboard`) – отдаёт HTML страницу.

#### 4. ИНТЕГРАЦИИ

- **C18.1 (Log Aggregator):** чтение логов для расчёта метрик.
    
- **C18.5 (Cost Tracker):** получение данных о затратах.
    
- **C0.4 (Registry Manager):** статусы веток.
    
- **BR7 (реестр задач):** статистика задач.
    
- **C6.3 (Token Guard):** данные о токенах.
    
- **C4.1 (Project Dashboard):** потребитель API метрик.
    
- **C18.3 (Alert Manager):** может использовать метрики для пороговых уведомлений.
    

---

#### 5. СТЕК ТЕХНОЛОГИЙ

- Python + FastAPI (микросервис).
    
- In-memory хранилище (например, `collections.deque` или специализированные библиотеки для временных рядов).
    
- (Опционально) временная БД типа Redis или TimescaleDB для долгосрочного хранения.
    
- HTTP-клиент (`httpx`) для опроса других компонентов.
    
- Chart.js на фронтенде.
