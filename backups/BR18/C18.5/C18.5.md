
### 📄 ПАСПОРТ КОНТЕЙНЕРА C18.5: COST TRACKER (ТРЕКЕР ЗАТРАТ)

**Ветка-родитель:** BR18 | **ID:** C18.5 | **Ответственный:** [назначить]

---

#### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ
Детальный учёт затрат на использование LLM и других платных API. Получает данные от агентов о количестве потраченных токенов и стоимости каждого вызова, агрегирует их по задачам, веткам, агентам и временным периодам. Строит прогнозы, выявляет аномальные траты, интегрируется с BR5 (биллинг) для формирования счетов и с BR19 (самообучение) для оптимизации использования моделей. Предоставляет API для получения статистики и экспорта данных.

---

#### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **Приём данных о затратах:**  
  – Агенты отправляют отчёты о каждом вызове LLM через HTTP POST на эндпоинт `/api/cost`.  
  – Формат отчёта:  
    ```json
    {
      "timestamp": "2026-03-18T12:00:00Z",
      "agent": "ГЕФЕСТ",
      "task_id": "BR1-P01",
      "branch": "BR1",
      "model": "gpt-4",
      "prompt_tokens": 500,
      "completion_tokens": 300,
      "cost_usd": 0.05,
      "success": true
    }
    ```  
  – Также может получать данные от C6.3 (Token Guard), который уже агрегирует информацию.  

- **Хранение:**  
  – Все записи сохраняются в SQLite (или PostgreSQL) для долгосрочного хранения.  
  – Таблица `cost_logs` содержит все поля отчёта плюс автоматически добавляемый `id`.  
  – Для быстрых агрегатов могут использоваться материализованные представления или кэши.  

- **Агрегация и статистика:**  
  – Фоновые задачи (например, каждый час) вычисляют суммарные затраты по задачам, веткам, агентам за день/неделю/месяц.  
  – Результаты сохраняются в отдельные таблицы или кэшируются для быстрого доступа.  

- **Прогнозирование и аномалии:**  
  – На основе исторических данных строятся прогнозы (простая линейная регрессия или более сложные методы).  
  – При резком отклонении текущих затрат от прогноза генерируется событие (для C18.3 Alert Manager).  

- **API:**  
  – `POST /api/cost` – приём отчёта о затратах.  
  – `GET /api/cost/summary` – суммарные затраты за период (параметры: `from`, `to`, `group_by` = `agent|branch|task`).  
  – `GET /api/cost/history` – временной ряд затрат (для графиков).  
  – `GET /api/cost/forecast` – прогноз на будущий период.  
  – `GET /api/cost/anomalies` – список выявленных аномалий.  

- **Интеграция с BR5:**  
  – Экспорт данных для биллинга (например, в формате CSV или через API).  
  – Может предоставлять стоимость каждого выполненного патча для включения в счёт клиенту.  

- **Логирование:**  
  – Все операции (приём данных, ошибки, запуски агрегации) отправляются в C18.1.

#### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8097):**  
  – Пример ответа `GET /cost/summary?from=2026-03-01&to=2026-03-18&group_by=branch`:  
    ```json
    [
      { "branch": "BR1", "total_cost": 12.34, "total_tokens": 123456 },
      { "branch": "BR2", "total_cost": 5.67, "total_tokens": 56789 }
    ]
    ```

- **Для экспорта в BR5:** может быть отдельный эндпоинт `/export` или прямая БД.

---

#### 4. ИНТЕГРАЦИИ

- **Все агенты (BR7, C7.4 и др.):** отправляют данные о затратах.  
- **C6.3 (Token Guard):** может дублировать или агрегировать данные.  
- **C18.2 (Metrics Dashboard):** предоставляет метрики затрат для отображения.  
- **C18.3 (Alert Manager):** получает сигналы об аномалиях.  
- **BR5 (Commerce):** получает данные для биллинга.  
- **BR19 (Self-Learning):** использует данные для оптимизации выбора моделей.  

---

#### 5. СТЕК ТЕХНОЛОГИЙ

- Python + FastAPI.  
- SQLite (для малых объёмов) или PostgreSQL (для масштабирования).  
- Библиотеки для статистики и прогнозирования (`numpy`, `scikit-learn` опционально).  
- HTTP-клиент (`httpx`).  
- Docker.
