### 📄 ПАСПОРТ КОНТЕЙНЕРА C17.5: SKILL PUBLISHER (ПУБЛИКАТОР НАВЫКОВ)

**Ветка-родитель:** BR17 | **ID:** C17.5 | **Ответственный:** [назначить]

---

### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ
Предоставление унифицированного API для получения навыков потребителям (агентам, другим веткам) с учётом версий, прав доступа, контекста задачи и оптимизации производительности (кэширование). Обеспечивает выдачу навыков в формате, готовом к использованию (обычно в составе промпта). Взаимодействует с реестром навыков (C17.1) и системой версионирования (C17.2) для получения актуальных данных, а также с тестировщиком (C17.4) для проверки статуса. Все запросы логируются в BR18 для последующего анализа и оптимизации.

---

### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **Источники данных:**  
  – **C17.1 (Skill Registry)** – получение метаданных навыка (актуальное содержимое, зависимости, статус).  
  – **C17.2 (Skill Version Control)** – получение исторических версий (опционально, если запрошена конкретная версия).  
  – **C17.4 (Skill Tester)** – проверка, прошёл ли навык тестирование (статус может влиять на выдачу).  

- **Алгоритм выдачи навыка:**  
  1. Получение запроса от потребителя (через REST API). Запрос содержит минимум: `skill_id` (обязательно), опционально `version` (конкретная версия), `agent_type` (для фильтрации `allowed_for_swarm`), `task_context` (для потенциального семантического уточнения).  
  2. Проверка наличия навыка в реестре через C17.1. Если навык не найден или статус `deleted` – возврат ошибки 404.  
  3. Если запрошена конкретная версия, обращение к C17.2 для получения файла этой версии.  
  4. Проверка прав доступа: если `agent_type = "swarm"`, навык должен иметь флаг `allowed_for_swarm: true`. Иначе блокировка с соответствующим сообщением.  
  5. (Опционально) проверка статуса тестирования через C17.4; можно выдавать только навыки со статусом `active` (или разрешить черновики для определённых ролей – настраивается).  
  6. Формирование ответа: JSON-объект с полями навыка (включая `instruction`, `version`, `dependencies`, `metadata`).  
  7. Кэширование результата (в памяти с TTL) для ускорения повторных запросов.

- **Кэширование:**  
  – Используется LRU-кэш (например, `cachetools.TTLCache`) с настраиваемым размером и временем жизни.  
  – Ключ кэша формируется как `{skill_id}:{version}:{agent_type}`.  
  – При обновлении навыка через C17.1 (например, изменение статуса) может отправляться сигнал для инвалидации кэша (опционально, через механизм событий).

- **API:**  
  – `GET /skill/{skill_id}` – получить навык по ID. Параметры запроса: `version` (опционально, по умолчанию последняя активная), `agent_type` (опционально, по умолчанию `main`).  
  – `POST /skills/batch` – получить несколько навыков по списку ID (полезно для C7.4). Тело запроса: `{ "skills": ["SKILL-042", "SKILL-101"], "agent_type": "main" }`.  
  – `GET /skill/{skill_id}/metadata` – получить только метаданные (без `instruction`) для быстрой проверки.  
  – `GET /status` – состояние сервиса, статистика кэша.

- **Логирование в BR18:**  
  – Каждый успешный и неуспешный запрос логируется. Формат:  
    ```json
    {
      "timestamp": "2026-03-18T12:00:00Z",
      "service": "C17.5",
      "event_type": "skill_published",
      "details": {
        "skill_id": "SKILL-042",
        "version": "1.2.3",
        "agent_type": "main",
        "cached": true,
        "response_time_ms": 45
      }
    }
    ```

### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8092):**  
  – Все эндпоинты принимают и возвращают JSON.  
  – При ошибках – соответствующие HTTP-коды с описанием в поле `detail`.  

- **Пример ответа `GET /skill/SKILL-042?agent_type=swarm`:**  
  ```json
  {
    "id": "SKILL-042",
    "version": "1.2.3",
    "name": "Python Refactoring",
    "instruction": "полный текст инструкции по использованию навыка",
    "dependencies": ["SKILL-101"],
    "metadata": {
      "tags": ["python", "refactoring"],
      "task_types": ["refactor"],
      "languages": ["python"]
    }
  }
  ```

- **Пример ответа `POST /skills/batch`:**  
  ```json
  [
    { "id": "SKILL-042", "instruction": "...", "version": "1.2.3" },
    { "id": "SKILL-101", "instruction": "...", "version": "2.0.1" }
  ]
  ```

---

### 4. ИНТЕГРАЦИИ

- **C17.1 (Skill Registry):** получение актуальных метаданных навыков.  
- **C17.2 (Skill Version Control):** получение содержимого конкретной версии (если запрошена).  
- **C17.4 (Skill Tester):** проверка статуса тестирования навыка (опционально).  
- **C7.4 (Skill Integrator):** основной потребитель для batch-запросов.  
- **BR18 (Monitoring):** отправка логов.  
- **BR4 (Command Console):** (опционально) для ручной инвалидации кэша.  

---

### 5. СТЕК ТЕХНОЛОГИЙ

- Python + FastAPI (микросервис).  
- Кэширование: `cachetools.TTLCache`.  
- HTTP-клиент (`httpx`) для вызовов к C17.1, C17.2, C17.4.  
- Логирование через HTTP в BR18.  
- Docker (контейнер без специальных привилегий).
