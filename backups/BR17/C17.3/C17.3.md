---

### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ
Построение и поддержание графа зависимостей между навыками на основе метаданных из реестра навыков (C17.1). Предоставляет API для получения структуры зависимостей, проверки наличия циклов, поиска всех зависимостей конкретного навыка, а также экспорта полного графа для визуализации (например, в C4.2 Graph Visualizer). Обеспечивает целостность графа (отсутствие циклов, ссылки на несуществующие навыки) и уведомляет о нарушениях через BR18.

---

### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **Источник данных:**  
  – При старте и периодически (например, раз в час) C17.3 запрашивает все активные навыки из **C17.1 (Skill Registry)** через его API (`GET /skills?status=active`).  
  – Для каждого навыка извлекается поле `depends_on` (массив ID навыков, от которых он зависит).  

- **Построение графа:**  
  – Граф хранится в оперативной памяти в виде двух индексов:  
    * `outgoing[skill_id] = [список зависимостей]`  
    * `incoming[skill_id] = [списко навыков, которые зависят от данного]`  
  – При каждом обновлении данных (по расписанию или после уведомления от C17.1) граф перестраивается.  
  – Выполняется проверка на циклы (алгоритм топологической сортировки или DFS). При обнаружении цикла событие логируется в BR18 и (опционально) инициируется задача на исправление через BR1/BR19.

- **API (REST):**  
  – `GET /graph` – возвращает полный граф в формате узлов и рёбер (для визуализации).  
  – `GET /graph/{skill_id}` – возвращает информацию о навыке и его прямых зависимостях.  
  – `GET /dependencies/{skill_id}?depth=all` – возвращает все зависимости (транзитивно) для указанного навыка.  
  – `GET /reverse-dependencies/{skill_id}` – возвращает список навыков, которые зависят от данного.  
  – `GET /cycle-check` – проверяет наличие циклов в текущем графе, возвращает список циклов (если есть).  

- **Логирование:**  
  – При обнаружении цикла или других аномалий (несуществующие зависимости) отправляется событие в **BR18 (C18.1 Log Aggregator)**.  
  – Также логируются ошибки при обращении к C17.1.

**Формат лога (пример):**
```json
{
  "timestamp": "2026-03-18T12:00:00Z",
  "service": "C17.3",
  "event_type": "cycle_detected",
  "details": {
    "cycle": ["SKILL-001", "SKILL-042", "SKILL-001"]
  }
}
```

### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8090):**  
  – Все эндпоинты возвращают JSON.  
  – При ошибках – соответствующие HTTP-коды с описанием.

- **Пример ответа `GET /graph`:**  
  ```json
  {
    "nodes": [
      { "id": "SKILL-001", "name": "Python Refactoring" },
      { "id": "SKILL-042", "name": "AST Manipulation" }
    ],
    "edges": [
      { "source": "SKILL-001", "target": "SKILL-042" }
    ]
  }
  ```

### 4. ИНТЕГРАЦИИ

- **C17.1 (Skill Registry):** получение актуальных данных о навыках (через API).  
- **BR18 (Monitoring):** отправка логов и алертов при обнаружении проблем.  
- **C4.2 (Graph Visualizer):** может запрашивать полный граф для отображения.  
- **C7.4 (Skill Integrator), C6.2 (Semantic Auditor):** могут использовать API для получения информации о зависимостях.  

---

### 5. СТЕК ТЕХНОЛОГИЙ

- Python + FastAPI (микросервис).  
- HTTP-клиент (`httpx`) для запросов к C17.1.  
- Внутренние структуры данных (граф хранится в памяти).  
- Логирование через HTTP в BR18.  
- Docker (контейнер без специальных привилегий).
