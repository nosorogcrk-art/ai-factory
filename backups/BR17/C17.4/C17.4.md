### 📄 ПАСПОРТ КОНТЕЙНЕРА C17.4: SKILL TESTER (ТЕСТИРОВЩИК НАВЫКОВ)

**Ветка-родитель:** BR17 | **ID:** C17.4 | **Ответственный:** [назначить]

---

### 1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ
Автоматическая проверка работоспособности и качества навыков в изолированной среде («песочнице»). Для каждого навыка (или набора навыков) запускает тестовые сценарии, имитирующие реальные условия, и оценивает соответствие результатов ожидаемым. Результаты тестирования сохраняются, влияют на статус навыка (например, прохождение тестов может быть обязательным для перевода статуса в `active`) и используются для обратной связи в BR19 (самообучение) и BR1 (мета-мозг). Все операции логируются в BR18.

---

### 2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)

- **Получение навыков для тестирования:**  
  – При запуске по расписанию или по запросу C17.4 запрашивает из **C17.1 (Skill Registry)** список навыков, требующих тестирования (например, новые или изменённые навыки со статусом `draft`).  
  – Также может тестировать конкретный навык по ID через API.

- **Тестовая среда:**  
  – Для каждого навыка создаётся изолированное окружение (Docker-контейнер или временный подпроцесс) с предустановленными зависимостями (если они указаны в метаданных навыка).  
  – В окружение передаётся код/инструкции навыка и набор тестовых данных (из внутренней библиотеки тестов).  
  – Запускается тестовый сценарий (например, через вызов агента, использующего навык, или прямое выполнение инструкций).  

- **Библиотека тестов:**  
  – Тестовые кейсы хранятся в отдельном репозитории или папке (например, `00_КАНОН/Методология/Тесты_навыков/`).  
  – Каждый кейс содержит: входные данные, ожидаемый результат, критерии оценки (например, точность, полнота, время выполнения).  
  – Кейсы могут быть общими для всех навыков или специфичными для конкретного навыка (по ID).

- **Оценка результата:**  
  – Результат выполнения сравнивается с эталоном. Используются метрики: успешность (passed/failed), точность (для генеративных задач), время выполнения, потребление ресурсов.  
  – При несовпадении фиксируется ошибка с деталями.

- **Обновление статуса навыка:**  
  – Если все тесты пройдены успешно, C17.4 может автоматически инициировать изменение статуса навыка через вызов **C17.5 (Skill Publisher)** или напрямую через C17.1 (PATCH /skills/{id} с новым статусом, например, `active`).  
  – Если тесты не пройдены, навык остаётся в статусе `draft`, и создаётся задача на доработку через BR1/BR19.

- **API:**  
  – `POST /test/{skill_id}` – запустить тестирование конкретного навыка. Может принимать параметры (например, конкретные тесты).  
  – `GET /results/{skill_id}` – получить последние результаты тестирования.  
  – `POST /test/all` – запустить тестирование всех навыков, требующих проверки.  
  – `GET /status` – статус текущих тестовых заданий.

- **Логирование в BR18:**  
  – Каждый запуск теста, его результат и ошибки отправляются в Log Aggregator.  
  – Формат лога:  
    ```json
    {
      "timestamp": "2026-03-18T12:00:00Z",
      "service": "C17.4",
      "event_type": "skill_test",
      "details": {
        "skill_id": "SKILL-042",
        "test_case": "basic_refactor",
        "passed": true,
        "duration_ms": 1500,
        "error": null
      }
    }
    ```

### 3. ВХОДЫ И ВЫХОДЫ (INTERFACES)

- **REST API (внутри Docker-сети, порт 8091):**  
  – Все эндпоинты принимают и возвращают JSON.  
  – При ошибках – соответствующие HTTP-коды с описанием.

- **Пример ответа `POST /test/SKILL-042`:**  
  ```json
  {
    "test_run_id": "tr_12345",
    "skill_id": "SKILL-042",
    "status": "in_progress"
  }
  ```

- **Пример ответа `GET /results/SKILL-042`:**  
  ```json
  {
    "skill_id": "SKILL-042",
    "last_test": "2026-03-18T12:00:00Z",
    "overall": "passed",
    "tests": [
      { "name": "basic_case", "passed": true, "duration_ms": 200 },
      { "name": "edge_case", "passed": true, "duration_ms": 150 }
    ]
  }
  ```

### 4. ИНТЕГРАЦИИ

- **C17.1 (Skill Registry):** получение данных навыка (поля `instruction`, `dependencies`), обновление статуса после тестирования.  
- **C17.5 (Skill Publisher):** (опционально) через него можно инициировать публикацию навыка после успешного тестирования.  
- **BR18 (Monitoring):** отправка логов и алертов при критических ошибках тестирования.  
- **BR3 (Methodology):** может предоставлять эталонные тестовые кейсы (C3.3 Training Simulator).  
- **BR1/BR19:** создание задач для доработки при провале тестов.  

---

### 5. СТЕК ТЕХНОЛОГИЙ

- Python + FastAPI (микросервис).  
- Docker SDK для Python (для создания изолированных сред).  
- HTTP-клиент (`httpx`) для взаимодействия с C17.1, C17.5, BR18.  
- Библиотека для работы с JSON, возможно `jsonschema` для валидации результатов.  
- Локальное хранение результатов (опционально SQLite).  
- Docker (контейнер с доступом к Docker-сокету для запуска дочерних контейнеров).  

**Примечание:** контейнеру C17.4 может потребоваться доступ к Docker-сокету (`/var/run/docker.sock`) для запуска изолированных тестовых контейнеров. Это следует учесть в настройках безопасности.
