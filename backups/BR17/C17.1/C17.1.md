### **C17.1: Skill Registry (Реестр навыков)** – ИСПРАВЛЕННАЯ ВЕРСИЯ

**Ветка-родитель:** BR17 | **ID:** C17.1 | **Ответственный:** [назначить]

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Централизованное хранение и управление метаданными всех навыков, используемых агентами завода. Обеспечивает CRUD-операции над записями навыков, валидацию входных данных, поддержку фильтрации и пагинации, а также предоставляет статистику. Все изменения логируются в BR18 для обеспечения прослеживаемости. Реестр служит источником истины для других компонентов BR17 (граф навыков, тестер, публикатор) и внешних потребителей (C7.4, BR1, BR19).

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**  

- **Хранение данных:**  
  – Используется SQLite (файл `skills.db`), расположенный в монтируемом томе `/data`.  
  – Таблица `skills` содержит все поля метаданных навыка (см. раздел 3).  

- **API эндпоинты:**  
  – `GET /skills` – возвращает список навыков с поддержкой:  
    * Фильтрации по полям `status`, `tags`, `task_types`, `languages`.  
    * Пагинации через параметры `limit` (по умолчанию 20, макс 100) и `offset`.  
    * Сортировки по `name` или `created_at` (по умолчанию `created_at DESC`).  
  – `GET /skills/{id}` – возвращает запись конкретного навыка или 404.  
  – `POST /skills` – создаёт новый навык.  
    * ID генерируется автоматически в формате `SKILL-XXX` (XXX – следующий порядковый номер).  
    * Тело запроса должно содержать все обязательные поля (кроме `id`, `created_at`, `updated_at`).  
    * При успехе возвращает созданную запись с заполненными `id`, `created_at`, `updated_at`.  
  – `PUT /skills/{id}` – полностью заменяет запись навыка.  
    * Все поля (кроме `id`, `created_at`) должны быть переданы.  
    * Проверяется существование записи, обновляется `updated_at`.  
  – `PATCH /skills/{id}` – частично обновляет запись (только переданные поля).  
    * Обновляет `updated_at` автоматически.  
  – `DELETE /skills/{id}` – мягкое удаление (устанавливает статус `deleted`).  
    * Фактического удаления из БД не происходит.  
  – `GET /skills/stats` – возвращает статистику:  
    ```json
    {
      "total": 150,
      "active": 120,
      "draft": 20,
      "deprecated": 5,
      "deleted": 5
    }
    ```

- **Валидация:**  
  – При создании и обновлении проверяется:  
    * Наличие обязательных полей: `name`, `version`, `description`, `author`, `status`, `instruction`.  
    * Формат `version` – семантическое версионирование (например, `1.2.3`).  
    * `status` должен быть одним из: `draft`, `active`, `deprecated`, `deleted`.  
    * Поля `tags`, `task_types`, `languages` – массивы строк (могут быть пустыми).  
    * Поле `depends_on` – массив ID навыков, каждый из которых должен существовать в БД (кроме самого себя) и не быть в статусе `deleted`.  
    * Поле `related_patches` – массив строк (формат ID патча), валидация существования не обязательна, но может быть опциональной.  

- **Логирование:**  
  – При каждом успешном изменении (POST, PUT, PATCH, DELETE) отправляется событие в **BR18 (C18.1 Log Aggregator)** в формате:  
    ```json
    {
      "timestamp": "2026-03-18T12:00:00Z",
      "service": "C17.1",
      "event_type": "skill_created | skill_updated | skill_deleted",
      "details": {
        "skill_id": "SKILL-001",
        "version": "1.2.3",
        "changed_fields": ["description", "status"],
        "user": "argus"   // из контекста запроса (можно брать из заголовка X-User)
      }
    }
    ```  
  – Ошибки валидации также логируются с типом `validation_error`.

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**  

- **REST API (внутри Docker-сети, порт 8088):**  
  – Все эндпоинты принимают и возвращают JSON.  
  – Для методов POST/PUT/PATCH ожидается тело с соответствующими полями.  
  – Ответы с ошибками содержат описание в поле `detail`.  

- **Формат записи навыка (пример):**  
  ```json
  {
    "id": "SKILL-042",
    "name": "Python Refactoring",
    "version": "1.2.3",
    "description": "Описание навыка",
    "author": "argus",
    "created_at": "2026-03-18T10:00:00Z",
    "updated_at": "2026-03-18T10:00:00Z",
    "status": "active",
    "tags": ["python", "refactoring"],
    "task_types": ["refactor", "code_review"],
    "languages": ["python"],
    "allowed_for_swarm": false,
    "depends_on": ["SKILL-043"],  // исправлено: теперь зависит от другого навыка
    "related_patches": ["P1.2.3"],
    "instruction": "полный текст инструкции по использованию навыка"
  }
  ```

**4. ИНТЕГРАЦИИ**  

- **Внутренние потребители BR17:** C17.2 (Skill Version Control), C17.3 (Skill Graph), C17.4 (Skill Tester), C17.5 (Skill Publisher) – вызывают API C17.1 для получения данных навыков.  
- **Внешние потребители:** C7.4 (Skill Integrator), BR1 (Cognitive Engine), BR19 (Self-Learning) – для чтения информации о навыках.  
- **BR18 (Monitoring):** отправка логов и алертов.  
- **BR4 (Command Console):** (опционально) для ручного управления через API (потребуется аутентификация).  

**5. СТЕК ТЕХНОЛОГИЙ**  

- Python + FastAPI (микросервис).  
- SQLite (БД).  
- HTTP-клиент (`httpx`) для отправки логов в BR18.  
- Docker (контейнер без специальных привилегий).
