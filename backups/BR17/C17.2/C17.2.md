### **C17.2: Skill Version Control (Версионирование навыков)**

**Ветка-родитель:** BR17 | **ID:** C17.2 | **Ответственный:** [назначить]

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Обеспечение хранения истории изменений навыков в Git-репозитории, возможность просмотра истории, сравнения версий и отката к предыдущим состояниям. Предоставляет API для выполнения Git-операций по запросу от других компонентов (C17.1, BR20). Все действия логируются в BR18.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**

- **Хранение:**  
    – Git-репозиторий располагается в монтируемом томе `/data/skills-repo`.  
    – Каждый навык хранится в отдельном JSON-файле с именем `{skill_id}.json` (например, `SKILL-042.json`).  
    – При первом запуске, если репозиторий не существует, он инициализируется (`git init`).
    
- **Интеграция с C17.1:**  
    – При создании или обновлении навыка C17.1 отправляет в C17.2 запрос `POST /commit/{skill_id}` с новым содержимым и сообщением коммита.  
    – C17.2 сохраняет файл в репозитории и создаёт коммит.  
    – При откате (rollback) C17.1 (или другой компонент) вызывает `POST /rollback/{skill_id}` с указанием целевой версии.
    
- **API:**  
    – `POST /commit/{skill_id}` – создаёт коммит для навыка. Тело запроса:
    
    json
    
    {
      "content": { ... },   // полное содержимое навыка (JSON)
      "message": "commit message"
    }
    
    Ответ: `{ "commit_hash": "abc123def" }`.  
    – `GET /history/{skill_id}` – возвращает список коммитов для навыка:
    
    json
    
    [
      { "hash": "abc123", "author": "...", "date": "...", "message": "..." }
    ]
    
    – `GET /diff/{skill_id}?from=v1&to=v2` – возвращает diff между двумя версиями (v1 и v2 могут быть хешами коммитов или тегами).  
    – `POST /rollback/{skill_id}?to=v1` – откатывает файл навыка к указанной версии (создаёт новый коммит, восстанавливающий старое содержимое).  
    – `GET /file/{skill_id}?ref=v1` – возвращает содержимое файла навыка на определённой версии.
    
- **Логирование в BR18:**  
    – При успешном создании коммита, ошибке, откате отправляется событие в Log Aggregator (C18.1).  
    – Формат лога:
    
    json
    
    {
      "timestamp": "2026-03-18T12:00:00Z",
      "service": "C17.2",
      "event_type": "commit_created | commit_failed | rollback_performed",
      "details": {
        "skill_id": "SKILL-042",
        "commit_hash": "abc123def",
        "message": "Обновлено описание навыка"
      }
    }
    

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**

- **REST API (внутри Docker-сети, порт 8089):**  
    – Все эндпоинты принимают и возвращают JSON.  
    – При ошибках возвращается `4xx` или `5xx` с описанием в поле `detail`.
    

**4. ИНТЕГРАЦИИ**

- **C17.1 (Skill Registry):** получает уведомления о необходимости создать коммит при изменении навыка.
    
- **BR20 (CI/CD):** может использовать API для получения diff и истории в пайплайнах.
    
- **BR18 (Monitoring):** отправка логов.
    

**5. СТЕК ТЕХНОЛОГИЙ**

- Python + FastAPI.
    
- GitPython (для работы с Git-репозиторием).
    
- HTTP-клиент (`httpx`) для отправки логов.
    
- Docker (контейнер с монтируемым томом для репозитория).
