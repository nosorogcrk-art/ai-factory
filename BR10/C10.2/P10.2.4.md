### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P10.2.4 (LEVEL 5)

**ID:** P10.2.4  
**Контейнер:** C10.2 (Стенд Приёмки)  
**Название:** Реальная интеграция тестов навыков с C17.4 (Skill Tester)  
**Статус:** проект

**Зависимости:** P10.2.3, C17.4 (Skill Tester, патчи P17.4.1–P17.4.5)

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Заменить заглушку проверки навыков (P10.2.2) на реальные вызовы к C17.4 (Skill Tester). Перед запуском тестов продукта стенд загружает список навыков из метаданных продукта (`metadata.json`) и для каждого навыка отправляет запрос в C17.4. Если хотя бы один навык не проходит тесты, продукт считается неготовым к релизу, и задача переводится в статус `REWORK`. Все результаты логируются в BR18.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Модифицируемый файл:** `BR10/C10.2/services.py`.  
- **Адрес C17.4:** переменная окружения `SKILL_TESTER_URL` (по умолчанию `http://skill-tester:8091`).  
- **Эндпоинт C17.4:** `POST /test/{skill_id}`.  
  - Запрос: не требует тела (skill_id передаётся в URL).  
  - Ответ (синхронный, тест выполняется сразу):  
    ```json
    {
      "test_run_id": "tr_...",
      "skill_id": "SKILL-001",
      "status": "completed",
      "passed": true,
      "output": "...",
      "duration_seconds": 0.5
    }
Логика проверки:

Загрузить metadata.json из корня продукта, извлечь список skills.
Для каждого skill_id отправить асинхронный POST-запрос к C17.4.
Если ответ содержит passed: false или возникает ошибка HTTP – проверка провалена.
Результаты проверки добавляются в отчёт тестирования и отправляются в BR18.
Обработка ошибок: при недоступности C17.4 стенд завершается с ошибкой (код 1).

Логирование в BR18: через существующий механизм send_to_br18 отправляются события skill_test для каждого навыка.

3. РЕАЛИЗАЦИЯ (L6) – ОПИСАНИЕ
Добавить в services.py функцию check_skills_real(skills, job_id), которая для каждого навыка вызывает C17.4.

Использовать httpx.AsyncClient для асинхронных запросов.

Агрегировать результаты, вернуть общий статус (passed/failed) и детали.

В run_tests_async перед запуском тестов продукта вызвать эту функцию. Если она вернёт False, завершить выполнение с ошибкой.

4. КРИТЕРИЙ ПРИЕМКИ (DoD)
При наличии метаданных о навыках стенд выполняет реальные запросы к C17.4.

Если все навыки проходят тесты, процесс продолжается (запускаются тесты продукта).

Если хотя бы один навык не проходит, стенд завершается с ошибкой, логирует детали.

При недоступности C17.4 стенд возвращает ошибку.

В BR18 отправляются логи о результатах проверки навыков.

Тесты обновлены (мокают вызовы к C17.4).
