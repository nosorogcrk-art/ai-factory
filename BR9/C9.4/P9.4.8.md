## 1. Цель

Добавить в C9.4 асинхронный вызов HTTP-сервиса C1.2 (Patch Architect) после успешного создания задачи в handover, чтобы автоматически разбивать задачу на патчи.

---

## 2. Технические параметры

### 2.1. Модифицируемые файлы
- `BR9/C9.4/services.py` – добавить функцию `call_decomposer`.
- `BR9/C9.4/main.py` – вызвать фоновую задачу после создания задачи.

### 2.2. Добавляемые переменные окружения
- `DECOMPOSER_URL` – адрес C1.2 (по умолчанию `http://patch-architect:8085`).

### 2.3. Алгоритм
1. В функции `dialog` после вызова `create_task_in_registry` (получен `task_id`) запустить асинхронную фоновую задачу.
2. В фоновой задаче:
   - Собрать JSON: `{"description": <описание задачи>, "context": {"task_id": <task_id>}}`.
   - Отправить `POST {DECOMPOSER_URL}/decompose` с помощью `httpx.AsyncClient`.
   - Распарсить ответ, извлечь список `patches`.
   - Если список не пуст:
     - Обновить реестр задач: найти исходную задачу по `task_id`, установить `status = "IN_PROGRESS"`, добавить запись в `history`.
   - Если список пуст:
     - Статус задачи не изменять, добавить запись в `history`: `"decomposition returned no patches"`.
   - Если произошла ошибка (HTTP ошибка, таймаут, невалидный ответ):
     - Статус задачи не изменять, добавить запись в `history` с описанием ошибки.
     - Логировать ошибку и отправить в BR18.
