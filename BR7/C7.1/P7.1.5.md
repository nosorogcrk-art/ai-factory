
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P7.1.5 (LEVEL 5)

**ID:** P7.1.5  
**Контейнер:** C7.1 (Identity Core)  
**Название:** Интеграция версионирования с BR20 (пассивный режим)

**Зависимости:** P7.1.4

---

#### 1. ЗАМЫСЕЛ ПАТЧА
После того как Identity Core переведён в пассивный режим (только чтение файлов), необходимо обеспечить, чтобы файлы промптов обновлялись исключительно через CI/CD-пайплайн BR20. Этот патч добавляет интеграцию с BR20: теперь любые изменения в промптах должны доставляться через деплой BR20, а Identity Core просто реагирует на изменение mtime файлов. Дополнительно можно реализовать механизм уведомлений от BR20 о новых версиях (опционально), но основной способ остаётся — обнаружение изменения файлов.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Зависимости:** выполненный P7.1.4, существование BR20 (может быть ещё не реализован, но мы проектируем интерфейс).
- **Целевой файл:** `agents/tools/prompt_builder.py` (уже модифицирован в P7.1.4).
- **Дополнительно:**
  - Ввести переменную окружения `PROMPT_DIR` (или оставить жёстко `/00_КАНОН/ПРОМПТЫ/`), но файлы туда теперь попадают через деплой BR20.
  - Убедиться, что права доступа к файлам позволяют читать, но не писать (кроме как через BR20).
  - (Опционально) добавить поддержку файла версии (например, `version.txt`), чтобы Identity Core мог сообщить текущую версию промптов (может пригодиться для логирования).
  - Обновить документацию: теперь разработчики должны изменять промпты через Git-репозиторий, а не напрямую в файловой системе завода.

- **Логирование:** добавить логирование факта, что промпт был изменён (уже есть), и, возможно, ID деплоя (если BR20 будет передавать эту информацию). Пока можно без этого.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ

- Никаких изменений кода в `prompt_builder.py` не требуется, если P7.1.4 уже реализован. Интеграция с BR20 заключается в том, что файлы промптов будут обновляться BR20, а Identity Core будет подхватывать изменения автоматически через mtime.
- Для проверки работоспособности можно написать тест: эмулировать появление нового файла промпта через копирование в папку (имитация деплоя) и убедиться, что `prompt_builder` возвращает новый контент.
- Рекомендуется добавить в `prompt_builder` возможность принудительно перечитать все промпты и обновить хеши (например, при старте или по сигналу), но это опционально.
- Документация: в комментариях к коду указать, что файлы промптов находятся под управлением BR20 и не должны редактироваться вручную.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)

- После выполнения патча Identity Core работает в режиме «только чтение» и не пытается писать в Git.
- При обновлении файлов промптов через внешний процесс (например, через ручное копирование, имитирующее деплой BR20) `prompt_builder` автоматически обнаруживает изменения и возвращает актуальное содержимое.
- В логах фиксируются факты обновления.
- Код не содержит зависимостей от Git и не вызывает Git-команды.
