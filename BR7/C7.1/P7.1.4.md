### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P7.1.4 (LEVEL 5)

**ID:** P7.1.4  
**Контейнер:** C7.1 (Identity Core)  
**Название:** Доработка версионирования промптов: переход на пассивное чтение файлов (подготовка к интеграции с BR20)

---

#### 1. ЗАМЫСЕЛ ПАТЧА
Существующий механизм версионирования промптов (P7.1.3) предполагает активную работу с Git: он сам создаёт коммиты и теги при изменениях. В новой архитектуре управление Git-репозиториями и деплой конфигураций возлагается на BR20 (CI/CD). Identity Core должен стать «пассивным читателем»: он только отслеживает изменения файлов промптов через метаданные файловой системы (mtime) и не должен инициировать Git-операции. Этот патч модифицирует код, удаляя прямые вызовы Git и подготавливая основу для будущей интеграции с BR20.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ

- **Зависимости:** выполненный патч P7.1.3 (текущая реализация версионирования).
- **Целевые файлы:** `agents/tools/prompt_versioning.py` (или другой, если переименован), `agents/tools/prompt_builder.py` (возможно, косвенно).
- **Изменения:**
  1. Удалить или закомментировать все функции, работающие с Git: `check_git_repo()`, `get_changed_prompt_files()`, `commit_and_tag()`, `create_new_tag()`, `run_git_command()`.
  2. Вместо этого реализовать простой мониторинг изменений файлов на основе `mtime`:
     - При запуске или по запросу (из `prompt_builder.py`) проверять, изменился ли файл промпта (по сравнению с сохранённым `mtime` в кэше или в отдельном файле состояния).
     - Если файл изменился, обновлять хеш в `prompt_hashes.json` (это уже делается в `prompt_builder.py` при первом запуске? В P7.1.2 есть логика инициализации хешей, но она не обновляет их при изменениях. Нужно добавить автоматическое обновление хеша при обнаружении изменения файла через mtime).
  3. Модифицировать `prompt_builder.py`, чтобы он при каждом запросе проверял `mtime` файла промпта и, если оно изменилось, пересчитывал хеш и обновлял запись в `prompt_hashes.json` (без участия Git).
  4. Логировать события обнаружения изменений в файл `01_ЦЕХ/01_ЖУРНАЛЫ/prompt_watcher.log` (можно объединить с логом доступа).
- **Новый функционал:** не требуется, только удаление Git-логики и адаптация к пассивному режиму.
- **Файл состояния:** можно оставить `prompt_hashes.json` как хранилище эталонных хешей, но теперь он будет обновляться только при изменении файла, без создания коммитов.

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ

- **В `prompt_versioning.py`** (или удалить этот файл, если он больше не нужен). Если файл остаётся, его содержимое можно свести к одной функции `check_for_prompt_changes()`, которая вызывается извне.
- **В `prompt_builder.py`**:
  - Добавить функцию `get_file_mtime(file_path)`, возвращающую время последней модификации.
  - При вызове `get_prompt(role)` загружать текущий mtime файла и сравнивать с сохранённым в `prompt_hashes.json` (можно хранить дополнительное поле `mtime` в том же JSON).
  - Если mtime отличается, пересчитать хеш, обновить запись в `prompt_hashes.json` (включая поля `hash`, `mtime`, `last_verified`) и затем вернуть содержимое. Логировать это событие.
  - Если mtime совпадает, просто вернуть содержимое (как сейчас).
- **Удалить из `prompt_builder.py` все упоминания Git** (их там и не должно быть, так как Git-логика была в отдельном файле).
- **Убедиться, что `prompt_hashes.json` теперь содержит также поле `mtime` для каждого файла.**

Пример структуры `prompt_hashes.json` после изменений:
```json
{
  "ARGUS": {
    "hash": "abc...",
    "mtime": 1742312345.678,
    "last_verified": "2026-03-18T10:00:00Z"
  }
}
```

- **Логирование:** добавить запись в лог-файл `prompt_access.log` (или отдельный) при каждом обнаружении изменения.

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)

- Скрипт `prompt_builder.py` больше не вызывает Git-команды.
- При изменении содержимого файла промпта (например, через ручное редактирование) следующий запрос к `prompt_builder` для этой роли автоматически обновляет хеш в `prompt_hashes.json` и возвращает новый текст промпта.
- При отсутствии изменений хеш остаётся прежним.
- Файл `prompt_hashes.json` содержит поле `mtime` для каждой роли.
- Все события обновления хеша логируются.
- Старый скрипт `prompt_versioning.py` либо удалён, либо не содержит Git-кода (только заглушка).
