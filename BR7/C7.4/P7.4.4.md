
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P7.4.4 (LEVEL 5)

**ID:** P7.4.4  
**Контейнер:** C7.4 (Skill Integrator)  
**Название:** Реализовать семантический поиск навыков через BR2  

**Зависимости:** P17.3.1 (Skill Graph) и P7.4.3 (REST API интегратора) – хотя для семантического поиска нужен C2.3, но P17.3.1, вероятно, обеспечивает доступ к данным навыков. Уточним: семантический поиск выполняется через C2.3, а получение метаданных найденных навыков – через C17.1. Поэтому в реализации будут использованы оба.

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Дополнить алгоритм работы Skill Integrator возможностью семантического поиска навыков по текстовому описанию задачи (`context`). Если после этапа точного сопоставления по метаданным (`task_type`, `language`) набрано меньше требуемого количества навыков, выполняется запрос к C2.3 (Semantic Search) с фильтром на тип "skill". Полученные ID навыков затем дополняются метаданными из BR17 и включаются в результат. Это повышает релевантность подбираемых навыков.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Модифицируемый файл:** `agents/tools/skill_integrator.py` (или аналогичный).  
- **Интеграция с C2.3:**  
  – Адрес C2.3 задаётся переменной окружения `SEMANTIC_SEARCH_URL` (по умолчанию `http://c2.3:5005`).  
  – Используется эндпоинт `POST /search` (или `/api/search`) с телом:  
    ```json
    {
      "query": "текст контекста",
      "k": 10,
      "filters": { "source_type": "skill" }
    }
    ```  
  – Ожидается ответ в формате, аналогичном C2.3: массив объектов с полями `id`, `score`, `metadata`.  
- **Порог релевантности:** задаётся в конфигурации (`similarity_threshold`, по умолчанию 0.7).  
- **Алгоритм интеграции:**  
  1. Выполнить этап точного сопоставления (существующий код P7.4.2).  
  2. Если количество найденных навыков меньше `limit`, и передан `context` (не пустой), то:  
     – Отправить запрос в C2.3 с `query = context` и `k = limit * 2` (чтобы иметь запас).  
     – Отфильтровать результаты по порогу `score >= threshold`.  
     – Для каждого полученного ID проверить, не был ли он уже включён на этапе точного сопоставления. Если нет – добавить в список.  
     – Ограничить общее количество до `limit`.  
  3. Для всех отобранных ID получить метаданные из C17.1 (как обычно).  
  4. Сформировать ответ.  
- **Логирование:**  
  – Запросы к C2.3 логируются в локальный файл `skill_integrator.log` (уровень INFO).  
  – При ошибках доступа к C2.3 – предупреждение, но процесс продолжается (используются только точные совпадения).  
- **Конфигурация:**  
  – Добавить параметры: `enable_semantic_search` (bool, по умолчанию true), `semantic_threshold`.

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- В функции `compile_prompt` (или основной логике) после этапа точного сопоставления добавить условие:  
  ```python
  if context and len(selected_skills) < limit:
      semantic_results = await search_skills_semantic(context, limit - len(selected_skills))
      for res in semantic_results:
          if res['id'] not in selected_skill_ids:
              selected_skills.append(res)
  ```  
- Реализовать асинхронную функцию `search_skills_semantic(context, needed)`, которая обращается к C2.3 и возвращает список ID с метаданными (можно сначала получить только ID, а потом дозапросить метаданные).  
- Обработать возможные таймауты и ошибки.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При наличии контекста и недостаточном количестве точных совпадений выполняется запрос к C2.3.  
- Результаты семантического поиска включаются в ответ, если их score выше порога.  
- При недоступности C2.3 работа продолжается без семантического расширения (логируется предупреждение).  
- Итоговый промпт содержит инструкции из навыков, найденных обоими способами.  
- Логирование запросов к C2.3 работает.
