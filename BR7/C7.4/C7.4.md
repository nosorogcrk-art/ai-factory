### **C7.4: Skill Integrator (Интегратор навыков)**

**Ветка-родитель:** BR7 | **ID:** C7.4 | **Ответственный:** АРГУС

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Централизованный сервис для динамической подгрузки и компиляции навыков из хранилища BR17 в системные промпты агентов. По запросу (от основных или временных агентов) определяет релевантные навыки на основе типа задачи, языка, контекста или явно указанных идентификаторов, объединяет их инструкции в единый промпт и возвращает результат. Обеспечивает фильтрацию по типу агента (`main`/`swarm`) и логирует все операции в BR18 для анализа и оптимизации.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**  

- **Входные параметры (обязательные и опциональные):**  
  – `task_type` (обяз.) – строка из таксономии (например, `"refactor"`, `"test"`, `"document"`).  
  – `agent_type` (опц., по умолчанию `"main"`) – `"main"` или `"swarm"`. Влияет на фильтр `allowed_for_swarm`.  
  – `language` (опц.) – язык (например, `"python"`, `"javascript"`).  
  – `context` (опц.) – свободное текстовое описание задачи (до 500 символов) для семантического поиска.  
  – `required_skills` (опц.) – список конкретных ID навыков (если передан, остальные критерии игнорируются).  
  – `limit` (опц., по умолчанию 5) – максимальное количество навыков в результате.

- **Алгоритм выбора навыков:**  

  1. **Если передан `required_skills`:**  
     – Для каждого ID запрашивается запись из **C17.1 (Skill Registry)**. Проверяется статус (активен) и, для `agent_type="swarm"`, флаг `allowed_for_swarm`.  
     – Возвращаются только найденные и допустимые навыки. Если какой-то навык отсутствует или недопустим, в ответ добавляется предупреждение.  
     – Параметр `limit` игнорируется (возвращаются все валидные из списка).

  2. **Если `required_skills` не задан:**  
     – **Этап 1: точное сопоставление**  
       * Запрос к BR17 (C17.1/C17.3) для поиска навыков, у которых в метаданных:  
         - поле `task_types` содержит `task_type`;  
         - если указан `language` – поле `languages` содержит `language`;  
         - для `agent_type="swarm"` – `allowed_for_swarm: true`.  
       * Результаты сортируются по релевантности (если есть), отбирается до `limit` штук.  
     – **Этап 2: семантическое расширение** (если включено и есть `context`)  
       * Если после точного сопоставления набрано меньше `limit`, выполняется семантический поиск в **C2.3 (Semantic Search)** с фильтром `source_type: "skill"` (навыки должны быть проиндексированы в BR2).  
       * Используется порог релевантности ≥ 0.7.  
       * Результаты, ещё не попавшие в список, добавляются до достижения `limit`.  
     – **Этап 3: возврат результата**  
       * Формируется ответ со списком отобранных навыков (в порядке убывания релевантности).  
       * Если ни один навык не найден – возвращается пустой `prompt` и `used_skills: []`.

- **Компиляция промпта:**  
  – Для каждого выбранного навыка извлекается поле `instruction` (или `description`).  
  – Все инструкции объединяются через разделитель `\n\n---\n\n`.  
  – В выходной объект включается полный текст, список ID использованных навыков, предупреждения, а также статистика (`total_matched`, `returned`).

- **Логирование:**  
  – Каждый вызов эндпоинта `/compile` формирует лог-событие и отправляет его в **BR18 (Log Aggregator)**.  
  – Логируются как успешные запросы, так и ошибки (например, недоступность BR17). Формат см. в разделе 4.

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**  

- **REST API:**  
  – **POST /compile**  
    * **Тело запроса** (JSON):  
      ```json
      {
        "task_type": "refactor",
        "agent_type": "swarm",
        "language": "python",
        "context": "оптимизировать функцию быстрой сортировки",
        "required_skills": ["SKILL-042", "SKILL-101"],
        "limit": 3
      }
      ```  
      (поля `required_skills` и `limit` опциональны).  
    * **Ответ** (JSON):  
      ```json
      {
        "prompt": "инструкция из навыка SKILL-042\n\n---\n\nинструкция из навыка SKILL-101",
        "used_skills": ["SKILL-042", "SKILL-101"],
        "warnings": ["skill SKILL-099 not found"],
        "total_matched": 2,
        "returned": 2
      }
      ```

  – **POST /execute**  
    * **Тело запроса** (JSON):  
      ```json
      {
        "task_type": "decomposition_optimizer",
        "context": {"tasks": [], "constraints": {}}
      }
      ```  
      (поле `context` опционально).  
    * **Ответ** (JSON):  
      ```json
      {
        "result": {"optimized_tasks": [], "reasoning": "..."},
        "skill_id": "SKILL-DECOMPOSITION-001",
        "warnings": []
      }
      ```

- **Коды ответа:**  
  – `200 OK` – успешная компиляция или выполнение навыка.  
  – `400 Bad Request` – неверный формат, отсутствие обязательных полей.  
  – `404 Not Found` – навык не найден (для `/execute`).  
  – `502 Bad Gateway` – ошибка при вызове LLM (для `/execute`).  
  – `500 Internal Server Error` – внутренняя ошибка, недоступность зависимых сервисов (BR17, BR2).

**4. ИНТЕГРАЦИИ**  

- **BR17 (Skills Repository):**  
  – **C17.1 Skill Registry** – получение метаданных навыков по ID.  
  – **C17.3 Skill Graph** – поиск навыков по тегам (`task_types`, `languages`).  
  – **C17.5 Skill Publisher** – (опционально) получение полного текста навыка.  
- **BR2 (Memory):**  
  – **C2.3 Semantic Search** – семантический поиск по `context` (с фильтром на навыки).  
- **BR18 (Monitoring):**  
  – **C18.1 Log Aggregator** – отправка логов.  

**5. СТЕК ТЕХНОЛОГИЙ**  

- Python + FastAPI + Pydantic + Uvicorn.  
- HTTP-клиент (`httpx` или `aiohttp`) для вызовов BR17, BR2.  
- Docker (контейнер добавляется в `docker-compose.yml` ветки BR7).
