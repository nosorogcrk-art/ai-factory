### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P7.3.4 (LEVEL 5)

**ID:** P7.3.4  
**Контейнер:** C7.3 (Specialist Swarm)  
**Название:** Реализовать доступ временных агентов к навыкам (заглушка)  

**Зависимости:** P7.3.2 (менеджер временных агентов), P7.4.1 (базовая функция компиляции C7.4) – хотя C7.4 ещё не полностью готов, его интерфейс уже определён (заглушка).  

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
В соответствии с паспортом C7.3, временные агенты должны получать промпты, обогащённые навыками из BR17 через вызов C7.4 (Skill Integrator). На текущем этапе C7.4 реализован лишь частично (заглушки), поэтому необходимо модифицировать менеджер роя (`swarm_manager.py`) таким образом, чтобы он обращался к C7.4 за промптом, но при этом использовал временную заглушку, возвращающую фиксированный результат. Это позволит отвязать разработку C7.3 от готовности C7.4 и обеспечить возможность интеграции в будущем.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Целевой файл:** `agents/tools/swarm_manager.py` (создан в P7.3.2).  
- **Новый функционал:**  
  - Добавить функцию `_fetch_prompt_from_skill_integrator(task_type, language, context, required_skills, agent_type)`, которая пока является заглушкой.  
  - Вместо прямого формирования промпта из шаблона (как в P7.3.2) менеджер должен вызывать эту функцию.  
  - Если `required_skills` передан, заглушка может возвращать промпт, содержащий простую фразу о том, что навыки не реализованы.  
  - Если `required_skills` не передан, заглушка может возвращать промпт на основе типа задачи, игнорируя реальные навыки.  

- **Формат вызова (имитация будущего API C7.4):**  
  ```python
  def fetch_prompt(task_type, language=None, context=None, required_skills=None, agent_type="main"):
      # Заглушка: возвращает предопределённый ответ
      if required_skills:
          return {
              "prompt": f"[Заглушка] Запрошены навыки: {required_skills}. Используется базовый промпт.",
              "used_skills": required_skills,
              "warnings": ["Skill integration not fully implemented"]
          }
      else:
          return {
              "prompt": f"[Заглушка] Промпт для задачи типа '{task_type}' (язык: {language}). Контекст: {context[:50]}...",
              "used_skills": [],
              "warnings": []
          }
  ```  

- **Интеграция с существующим кодом:**  
  – Вместо загрузки шаблона из файла и подстановки контекста, менеджер теперь сначала вызывает `fetch_prompt`, а затем использует полученный промпт для создания микро-агента.  
  – Шаблоны из P7.3.1 временно не используются (или используются как fallback, если C7.4 вернёт пустой промпт). Можно оставить старую логику для совместимости, но в DoD указать, что приоритет отдаётся C7.4.  

- **Логирование:**  
  – Вызовы `fetch_prompt` логируются в `swarm_manager.log` с указанием параметров и полученного промпта.  
  – При ошибках (например, если C7.4 недоступен) логируется предупреждение, и используется старый механизм (шаблон).  

- **Конфигурация:**  
  – Возможно, добавить переменную окружения `SKILL_INTEGRATOR_URL`, указывающую на будущий сервис C7.4. На данном этапе вызов может быть локальным (функция) или через HTTP (если уже есть заглушка API). Для простоты сделаем локальный вызов, а в будущем заменим на HTTP-клиент.  

---

#### 3. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При создании временного агента через `swarm_manager` менеджер вызывает заглушечную функцию `fetch_prompt`.  
- Полученный промпт используется для запуска агента (вместо или в дополнение к шаблону).  
- В логах фиксируются вызовы к заглушке.  
- Если заглушка возвращает промпт, он корректно передаётся агенту.  
- Старая логика работы с шаблонами остаётся как fallback (например, если заглушка вернула пустой промпт).  
- Код не содержит реальных обращений к внешним сервисам BR17 или BR2.
