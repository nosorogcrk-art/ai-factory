### **C7.3: Specialist Swarm (Рой специалистов)** – ОБНОВЛЁННАЯ ВЕРСИЯ

**Ветка-родитель:** BR7 | **ID:** C7.3 | **Ответственный:** АРГУС

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Создание и управление временными микро-агентами для узкоспециализированных задач (рефакторинг, тестирование, документирование, оптимизация). Микро-агенты получают промпты, обогащённые навыками из BR17 через C7.4 (Skill Integrator), работают в изолированной среде с ограниченным бюджетом и автоматически уничтожаются после выполнения задачи. Все значимые события логируются в BR18.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**  

- **Фабрика агентов:**  
  – По запросу от Аргуса (или другого авторизованного компонента) модуль создаёт нового временного агента. Запрос включает:  
    * `task_id` – уникальный идентификатор задачи;  
    * `task_type` – тип задачи (refactor, test, document, …);  
    * `context` – дополнительные данные (код, файлы, описание);  
    * `language` – язык программирования (опционально);  
    * `priority` – приоритет (влияет на бюджет).  

- **Получение промпта с навыками:**  
  – C7.3 вызывает **C7.4 (Skill Integrator)**, передавая параметры задачи.  
  – C7.4 на основе анализа (ключевые слова, тип) запрашивает из BR17 навыки с флагом `allowed_for_swarm: true`, компилирует их в единый промпт и возвращает его.  
  – Если подходящих навыков нет, C7.3 отклоняет задачу с соответствующим логом.

- **Запуск агента:**  
  – Создаётся изолированный контейнер (Docker) или подпроцесс с предустановленными ограничениями:  
    * доступ только к внутренним ресурсам (запрет внешних сетей);  
    * бюджет вызовов (максимальное количество шагов/токенов), передаваемый в промпте или контролируемый рантаймом.  
  – В контейнер передаётся скомпилированный промпт и контекст задачи.  
  – Агент выполняет задачу, строго следуя инструкциям (включая правило приоритета внутренних источников).

- **Логирование использования навыков:**  
  – Во время работы агент (или C7.3 по его отчёту) фиксирует, какие навыки были реально задействованы.  
  – По завершении (успех/ошибка) C7.3 отправляет лог-событие в BR18 (Log Aggregator) по формату п.3.  

- **Завершение и очистка:**  
  – После получения результата (или при превышении бюджета/тайм-аута) контейнер останавливается и удаляется.  
  – Результат (отчёт, код, аналитика) возвращается инициатору.  
  – Все временные файлы и ресурсы очищаются.

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**  

- **Input:**  
  – JSON-запрос на создание временного агента (от Аргуса или через командную консоль BR4):  
    ```json
    {
      "task_id": "BR1-P01",
      "task_type": "refactor",
      "language": "python",
      "context": {"code": "def old_function(): ...", "file": "path/file.py"},
      "priority": "normal"
    }
    ```  

- **Output:**  
  – Результат работы агента (JSON или текстовый отчёт).  
  – Логи (отправляются в BR18).  
  – Уведомление о завершении или ошибке инициатору.

**Формат лога для BR18:**  
```json
{
  "timestamp": "2026-03-18T12:00:00Z",
  "service": "C7.3",
  "event_type": "skill_used | agent_created | agent_failed | agent_completed",
  "details": {
    "agent_id": "temp_agent_uuid",
    "task_id": "BR1-P01",
    "skill_id": "SKILL-042",                     // для skill_used
    "duration_ms": 2500,                          // для завершённых событий
    "success": true,                               // для agent_completed / agent_failed
    "error": "описание ошибки"                     // при наличии
  }
}
```

**4. ИНТЕГРАЦИИ**  

- **C7.4 (Skill Integrator):** получение скомпилированного промпта с навыками.  
- **BR17 (Skills Repository):** косвенно, через C7.4.  
- **BR18 (Monitoring):** отправка логов и алертов.  
- **BR0 (Infrastructure):** через Docker API для управления контейнерами.  
- **BR4 (Command Console):** возможен приём команд на создание/отмену агентов.  

**5. СТЕК ТЕХНОЛОГИЙ**  

- Python (основной язык реализации).  
- Docker (для изоляции микро-агентов) или `subprocess` с `cgroups` для ограничения ресурсов.  
- HTTP-клиент для вызова C7.4 и отправки логов в BR18.  
- Шаблонизатор (Jinja2) для сборки промпта (используется внутри C7.4, но может понадобиться и здесь для базовых шаблонов).  
- Система тайм-аутов (`asyncio` или `threading.Timer`).  

**6. СПИСОК ПАТЧЕЙ И ИХ ФУНКЦИИ**  

- **P7.3.1 (Библиотека шаблонов):** создание набора базовых шаблонов промптов для временных агентов (уже включает ограничения internal only и бюджет).  
- **P7.3.2 (Менеджер временных агентов):** скрипт `swarm_manager.py`, реализующий создание контейнера/процесса, передачу промпта, контроль бюджета, получение результата.  
- **P7.3.3 (Автоочистка):** механизм автоматического удаления завершённых агентов и сбора отчётов.  
- **P7.3.4 (Интеграция с навыками):** доработка `swarm_manager.py` для вызова C7.4 вместо использования только базовых шаблонов; добавление логирования использования навыков в BR18. Этот патч выполняется после того, как C7.4 и BR18 уже реализованы.
