### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P7.2.3 (LEVEL 5)

**ID:** P7.2.3 | **Контейнер:** C7.2 | **Название:** Тайм-ауты и алерты (timeout_watcher.py)

**1. ЗАМЫСЕЛ ПАТЧА**  
Автоматический мониторинг задач, «зависших» в одном статусе дольше установленного времени. При обнаружении такой задачи генерируется уведомление Аргусу для принятия мер (например, возврат задачи, ручное вмешательство). Это предотвращает блокировку конвейера и повышает общую надёжность системы.

**2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ**

- **Зависимости:** патчи P7.2.1 и P7.2.2 должны быть выполнены (существование `task_registry.json` и `task_model.json`).
- **Конфигурация таймаутов:** файл `00_КАНОН/ПРОЦЕССЫ/timeout_config.json` со структурой:
  ```json
  {
    "IN_PROGRESS": 3600,      // секунды (1 час)
    "ON_REVIEW": 1800,         // 30 минут
    "REWORK": 7200,            // 2 часа
    "BLOCKED": 86400,          // 24 часа – долгая блокировка требует внимания
    "NEW": 86400               // новая задача без назначения – тоже может быть проблемой
  }
  ```
- **Механизм работы:**
  - Скрипт `timeout_watcher.py` запускается периодически (например, каждые 5 минут) через планировщик.
  - Загружает реестр задач и конфигурацию таймаутов.
  - Для каждой задачи вычисляет время, прошедшее с момента последнего обновления (`updated_at`). Если оно превышает лимит для текущего статуса, задача считается зависшей.
  - Для зависшей задачи:
    - Создаётся запись в журнале `01_ЦЕХ/01_ЖУРНАЛЫ/ТАЙМАУТЫ.md`.
    - Отправляется уведомление Аргусу (через механизм `send_message` или запись в личный ящик Аргуса, например, в папку `01_ЦЕХ/01_ЖУРНАЛЫ/АРГУС_ВХОД/`).
    - Опционально: можно автоматически перевести задачу в статус `BLOCKED` (по усмотрению, но для первого этапа только уведомление).
- **Уведомление Аргусу:** формируется JSON-файл в папке `01_ЦЕХ/01_ЖУРНАЛЫ/АРГУС_ВХОД/` с именем `timeout_<timestamp>_<task_id>.json`, содержащий информацию о задаче и превышенном времени. Это соответствует протоколу взаимодействия с Аргусом (BR1).

**3. РЕАЛИЗАЦИЯ (L6 — КОД)**

Файл: `agents/tools/timeout_watcher.py`

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-

"""
timeout_watcher.py – мониторинг зависших задач.
Проверяет время нахождения задачи в статусе и уведомляет Аргуса при превышении лимита.
"""

import json
import time
from pathlib import Path
from datetime import datetime, timedelta
import logging

# Пути
REGISTRY_PATH = Path("01_ЦЕХ/ТЕКУЩИЕ_ЗАДАЧИ/task_registry.json")
TIMEOUT_CONFIG_PATH = Path("00_КАНОН/ПРОЦЕССЫ/timeout_config.json")
ARGUS_INBOX_PATH = Path("01_ЦЕХ/01_ЖУРНАЛЫ/АРГУС_ВХОД/")
LOG_PATH = Path("01_ЦЕХ/01_ЖУРНАЛЫ/ТАЙМАУТЫ.md")

# Создаём необходимые папки
ARGUS_INBOX_PATH.mkdir(parents=True, exist_ok=True)
LOG_PATH.parent.mkdir(parents=True, exist_ok=True)

# Настройка логирования (для отладки)
logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(message)s')

def load_json(path):
    with open(path, "r", encoding="utf-8") as f:
        return json.load(f)

def save_json(path, data):
    with open(path, "w", encoding="utf-8") as f:
        json.dump(data, f, indent=2, ensure_ascii=False)

def log_timeout(task_id, status, duration_seconds, limit_seconds):
    """Запись в журнал таймаутов."""
    timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    entry = f"\n### {timestamp} – Задача [[{task_id}]] превысила таймаут\n"
    entry += f"- **Статус:** {status}\n"
    entry += f"- **Длительность (сек):** {duration_seconds}\n"
    entry += f"- **Лимит (сек):** {limit_seconds}\n"
    with open(LOG_PATH, "a", encoding="utf-8") as f:
        f.write(entry)

def notify_argus(task_id, status, duration, limit):
    """Отправляет уведомление Аргусу в виде JSON-файла."""
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    filename = ARGUS_INBOX_PATH / f"timeout_{timestamp}_{task_id}.json"
    notification = {
        "type": "timeout_alert",
        "task_id": task_id,
        "status": status,
        "duration_seconds": duration,
        "limit_seconds": limit,
        "timestamp": datetime.now().isoformat()
    }
    with open(filename, "w", encoding="utf-8") as f:
        json.dump(notification, f, indent=2, ensure_ascii=False)
    logging.info(f"Timeout alert sent for task {task_id}")

def check_timeouts():
    # Загружаем конфигурацию
    if not TIMEOUT_CONFIG_PATH.exists():
        logging.error(f"Timeout config not found at {TIMEOUT_CONFIG_PATH}")
        return
    config = load_json(TIMEOUT_CONFIG_PATH)

    # Загружаем реестр задач
    if not REGISTRY_PATH.exists():
        logging.error(f"Task registry not found at {REGISTRY_PATH}")
        return
    tasks = load_json(REGISTRY_PATH)

    now = datetime.now()

    for task in tasks:
        task_id = task["id"]
        status = task["status"]
        updated_str = task.get("updated_at")
        if not updated_str:
            continue  # пропускаем, если нет даты обновления

        # Парсим время последнего обновления
        try:
            updated = datetime.fromisoformat(updated_str)
        except:
            continue

        duration = (now - updated).total_seconds()
        limit = config.get(status)

        if limit and duration > limit:
            # Задача зависла
            log_timeout(task_id, status, int(duration), limit)
            notify_argus(task_id, status, int(duration), limit)

if __name__ == "__main__":
    check_timeouts()
```

**5. КРИТЕРИЙ ПРИЕМКИ (DoD)**  
- Скрипт `timeout_watcher.py` создан и размещён в `agents/tools/`.  
- Конфигурационный файл `timeout_config.json` создан с разумными значениями.  
- При запуске скрипта с существующим реестром задач:
  - Для задач, превысивших лимит, формируются уведомления в папке `АРГУС_ВХОД/`.  
  - В журнал `ТАЙМАУТЫ.md` добавляются соответствующие записи.  
- Для задач, не превысивших лимит, ничего не происходит.  
- Скрипт не модифицирует реестр задач (только читает).  
- При отсутствии конфигурации или реестра скрипт логирует ошибку и завершается без паники.
