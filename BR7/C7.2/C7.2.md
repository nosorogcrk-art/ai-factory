### **C7.2: SAD Logic (Протоколы передачи ответственности)**

**Ветка-родитель:** BR7 | **ID:** C7.2 | **Ответственный:** АРГУС

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Реализация протоколов эстафетной передачи ответственности между агентами (SAD Logic). Обеспечивает детерминированные правила того, кто, кому, в каком виде и с какой фиксацией результатов передаёт задачу. Все события, связанные с передачей, логируются в центральную систему мониторинга (BR18) для обеспечения прозрачности, отладки и последующего анализа.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**  

- **Инициация передачи:**  
  Когда агент A завершает свою часть работы или понимает, что задачу должен выполнить другой агент B, он формирует запрос на передачу.  
  Запрос содержит:  
  – идентификатор задачи (task_id);  
  – идентификатор агента-получателя B;  
  – контекст выполнения (результаты, промежуточные данные).  

- **Подтверждение или отклонение:**  
  Агент B получает запрос и принимает решение. Возможные исходы:  
  – принятие (`handover_accepted`);  
  – отклонение (`handover_rejected`) с указанием причины (например, нехватка ресурсов, некомпетентность).  

- **Выполнение и завершение:**  
  После принятия агент B выполняет задачу и сообщает о завершении (`handover_completed`) или о невозможности выполнить (`handover_failed`).  

- **Тайм-ауты и отмена:**  
  Введены временные лимиты на принятие решения и выполнение. При превышении лимита генерируется событие `handover_timeout`.  
  Внешняя команда (от Владельца через BR4 или от Аргуса) может инициировать отмену задачи (`task_cancelled`).  

- **Логирование:**  
  Каждое событие передаётся в **общий модуль логирования** (предоставляемый BR18), который асинхронно отправляет HTTP POST запрос на эндпоинт `http://br18:8080/api/logs`.  
  Модуль обеспечивает fire‑and‑forget, не блокируя основной процесс. Формат лога строго соответствует п.3.  

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**  

- **Input:**  
  – Запросы на передачу от агентов.  
  – Подтверждения/отказы от агентов-получателей.  
  – Сигналы тайм-аутов (внутренний таймер).  
  – Команды отмены (из BR4 или от Аргуса).  

- **Output:**  
  – Уведомления агентам о статусе передачи.  
  – Лог-события, отправляемые в BR18 через общий модуль логирования.  

**Формат лог-события (JSON):**  
```json
{
  "timestamp": "2026-03-18T12:00:00Z",      // ISO 8601, UTC
  "service": "C7.2",
  "event_type": "handover_initiated | handover_accepted | handover_rejected | handover_completed | handover_timeout | handover_failed | task_cancelled",
  "details": {
    "from_agent": "ГЕФЕСТ",                  // агент-инициатор (для handover_rejected может отсутствовать)
    "to_agent": "РЕВА",                       // целевой агент (может отсутствовать при отмене)
    "task_id": "BR1-P01",
    "reason": "опционально, для handover_rejected, handover_failed, task_cancelled",
    "duration_ms": 1500,                      // время выполнения (для завершённых событий)
    "status": "success | failure"              // для handover_completed / handover_failed
  }
}
```
Поле `duration_ms` присутствует только в событиях `handover_completed` и `handover_failed`.  
Поле `reason` обязательно для `handover_rejected`, `handover_failed`, `task_cancelled`; в остальных случаях опционально.

**4. ИНТЕГРАЦИИ**  

- **BR18 (Monitoring):** отправка логов через общий модуль логирования.  
- **BR7 (Identity Core):** получение данных о ролях и лимитах агентов (используется при проверке возможности передачи).  
- **BR4 (Command Console):** приём команд отмены задачи.  
- **BR1 (Мета-Мозг):** (опционально) уведомление о критических сбоях в эстафете.

**5. СТЕК ТЕХНОЛОГИЙ**  

- Python (основной язык реализации).  
- Общий модуль логирования, предоставляемый BR18 (HTTP-клиент, асинхронная отправка).  
- Внутренние структуры данных (классы/словари) для описания задач и передачи.  
- Таймеры (например, `threading.Timer` или `asyncio`) для контроля тайм-аутов.
