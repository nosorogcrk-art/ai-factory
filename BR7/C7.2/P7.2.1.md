### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P7.2.1 (LEVEL 5)

**ID:** P7.2.1 | **Контейнер:** C7.2 | **Название:** Модель статусов и реестр задач

**1. ЗАМЫСЕЛ ПАТЧА**  
Создание формальной модели статусов задачи и правил переходов между ними, а также инициализация файлового хранилища для реестра задач. Это основа для протоколов передачи ответственности (SAD Logic), позволяющая унифицировать управление жизненным циклом задач и обеспечить контроль допустимости действий агентов.

**2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ**

- **Статусы задачи (базовый набор):**
  - `NEW` – новая задача, ожидает назначения.
  - `IN_PROGRESS` – в работе.
  - `ON_REVIEW` – на проверке (передано Реве).
  - `REWORK` – на доработке (возвращено Гефесту).
  - `DONE` – выполнено, готово к слиянию/архивации.
  - `BLOCKED` – заблокировано (зависимости не выполнены или внешние причины).
- **Правила переходов:**  
  Каждый переход должен быть разрешён для определённых ролей. Базовая матрица (может расширяться):
  | From | To | Разрешённые роли |
  |------|----|------------------|
  | NEW | IN_PROGRESS | АРХИ, ГЕФЕСТ (в зависимости от типа задачи) |
  | IN_PROGRESS | ON_REVIEW | ГЕФЕСТ |
  | ON_REVIEW | REWORK | РЕВА |
  | ON_REVIEW | DONE | РЕВА |
  | REWORK | IN_PROGRESS | ГЕФЕСТ |
  | любой | BLOCKED | АРГУС, любой агент (при обнаружении проблемы) |
  | BLOCKED | NEW | АРГУС (после устранения причины) |
- **Форматы хранения:**
  - **Модель переходов:** файл `00_КАНОН/ПРОЦЕССЫ/task_model.json`, содержащий описание статусов и разрешённых переходов (включая роли).
  - **Реестр задач:** файл `01_ЦЕХ/ТЕКУЩИЕ_ЗАДАЧИ/task_registry.json`, содержащий массив активных задач с полями:
    - `id` (строка, уникальный идентификатор)
    - `status` (текущий статус)
    - `assigned_to` (роль или null)
    - `created_at` (timestamp)
    - `updated_at` (timestamp)
    - `history` (массив событий: `{ timestamp, from, to, actor, comment }`)
- **Инициализация:** при первом запуске создаются оба файла с пустыми/начальными данными, если их нет.

**3. РЕАЛИЗАЦИЯ (L6 — КОД)**

Файл: `agents/tools/init_task_model.py`

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-

"""
init_task_model.py – инициализация модели статусов и реестра задач.
Создаёт файлы task_model.json и task_registry.json с базовой структурой.
"""

import json
from pathlib import Path
from datetime import datetime

# Пути к файлам
MODEL_PATH = Path("00_КАНОН/ПРОЦЕССЫ/task_model.json")
REGISTRY_PATH = Path("01_ЦЕХ/ТЕКУЩИЕ_ЗАДАЧИ/task_registry.json")

# Базовая модель переходов
TASK_MODEL = {
    "statuses": ["NEW", "IN_PROGRESS", "ON_REVIEW", "REWORK", "DONE", "BLOCKED"],
    "transitions": [
        {"from": "NEW", "to": "IN_PROGRESS", "allowed_roles": ["АРХИ", "ГЕФЕСТ"]},
        {"from": "IN_PROGRESS", "to": "ON_REVIEW", "allowed_roles": ["ГЕФЕСТ"]},
        {"from": "ON_REVIEW", "to": "REWORK", "allowed_roles": ["РЕВА"]},
        {"from": "ON_REVIEW", "to": "DONE", "allowed_roles": ["РЕВА"]},
        {"from": "REWORK", "to": "IN_PROGRESS", "allowed_roles": ["ГЕФЕСТ"]},
        {"from": "*", "to": "BLOCKED", "allowed_roles": ["АРГУС", "*"]},  # * означает любую роль
        {"from": "BLOCKED", "to": "NEW", "allowed_roles": ["АРГУС"]}
    ]
}

def ensure_dir(path):
    path.parent.mkdir(parents=True, exist_ok=True)

def init_model():
    ensure_dir(MODEL_PATH)
    if not MODEL_PATH.exists():
        with open(MODEL_PATH, "w", encoding="utf-8") as f:
            json.dump(TASK_MODEL, f, indent=2, ensure_ascii=False)
        print(f"Created task model at {MODEL_PATH}")
    else:
        print(f"Task model already exists at {MODEL_PATH}")

def init_registry():
    ensure_dir(REGISTRY_PATH)
    if not REGISTRY_PATH.exists():
        # Пустой реестр (массив задач)
        with open(REGISTRY_PATH, "w", encoding="utf-8") as f:
            json.dump([], f, indent=2)
        print(f"Created empty task registry at {REGISTRY_PATH}")
    else:
        print(f"Task registry already exists at {REGISTRY_PATH}")

if __name__ == "__main__":
    init_model()
    init_registry()
    print("Task model initialization complete.")
```

**4. КРИТЕРИЙ ПРИЕМКИ (DoD)**  
- Скрипт `init_task_model.py` создан и размещён в `agents/tools/`.  
- При первом запуске в папках `00_КАНОН/ПРОЦЕССЫ/` и `01_ЦЕХ/ТЕКУЩИЕ_ЗАДАЧИ/` создаются файлы `task_model.json` и `task_registry.json` с корректной структурой.  
- Модель содержит базовый набор статусов и переходов согласно техническим параметрам.  
- Реестр инициализируется пустым массивом.  
- При повторном запуске скрипт не перезаписывает существующие файлы (только сообщает о наличии).  
- Скрипт завершается без ошибок.
