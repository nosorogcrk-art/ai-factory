
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P6.2.5 (LEVEL 5)

**ID:** P6.2.5  
**Контейнер:** C6.2 (Semantic Auditor)  
**Название:** API для ручного запуска и конфигурации  

**Зависимости:** P6.2.4

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Создать REST API для управления аудитором: запуск полного аудита, получение последнего отчёта, просмотр и изменение конфигурации (пороги, расписание). Это позволит интегрировать аудитор с командной консолью (C4.3) и автоматизировать запуск.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Эндпоинты:**  
  - `POST /audit` – запуск полного аудита (все проверки). Тело запроса может содержать `checks: ["traceability", "contradictions", "skill_graph"]` для выборочного запуска. Возвращает ID задачи аудита.  
  - `GET /audit/{id}` – статус и результаты.  
  - `GET /audit/last` – последний отчёт.  
  - `GET /config` – текущая конфигурация.  
  - `PUT /config` – обновление конфигурации (требуется авторизация).  
- **Конфигурация:** хранится в файле `semantic_audit_config.json` и включает:  
  - `similarity_threshold` – порог для противоречий.  
  - `schedule_interval` – периодичность запуска (например, "24h").  
  - `alert_on_critical` – отправлять ли алерты.  
  - `auto_block` – блокировать ли автоматически.  
- **Асинхронность:** запуск аудита выполняется в фоновом режиме, API сразу возвращает ID.  
- **Интеграция с C4.3:** эндпоинты доступны из внутренней сети.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Встроить FastAPI-приложение в существующий модуль (или создать отдельный файл `audit_api.py`).  
- Использовать `BackgroundTasks` для запуска проверок.  
- Хранить результаты в локальной БД (SQLite) или в файлах.  
- Добавить проверку авторизации через заголовок `X-API-Key` (настраивается в конфиге).  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При `POST /audit` запускается фоновая задача, возвращается ID.  
- `GET /audit/{id}` возвращает статус и результат (если завершён).  
- Конфигурация читается и обновляется.  
- API доступно только с правильным ключом (если включена авторизация).
