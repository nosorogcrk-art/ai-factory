### **C6.2: Semantic Auditor (Семантический аудитор)**

**Ветка-родитель:** BR6 | **ID:** C6.2 | **Ответственный:** РЕВА | **Версия:** 1.0 | **Статус:** Реализован

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Автоматическая проверка кода, паспортов и спецификаций на соответствие Золотому стандарту 5.0. Проверяет наличие тестов, healthcheck эндпоинтов, паспортов контейнеров, соответствие стилю кода (ruff) и типизации (mypy). Возвращает детализированный отчёт с нарушениями и рекомендациями по исправлению. Логирует все события проверки в BR18.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**  

- **Типы проверок (реализованы в версии 1.0):**  
  1. **Наличие тестов:** проверяет существование папки `tests` и файлов `test_*.py`.  
  2. **Наличие healthcheck:** проверяет наличие эндпоинта `/health` в коде.  
  3. **Наличие паспорта:** проверяет наличие файла паспорта контейнера (C6.2.md).  
  4. **Проверка типизации:** запускает `mypy --ignore-missing-imports` для проверки типов.  
  5. **Проверка стиля кода:** запускает `ruff check` для проверки соответствия стилю.  

- **Режим работы:**  
  – **REST API:** эндпоинт `POST /review` принимает путь к файлу или его содержимое, возвращает отчёт с нарушениями.  
  – **Healthcheck:** эндпоинт `GET /health` для мониторинга состояния сервиса.  
  – **Логирование:** все проверки логируются локально и отправляются асинхронно в BR18.  

- **Формат ответа:**  
  ```json
  {
    "status": "approved" | "rework",
    "violations": [
      {"rule": "has_tests", "message": "No tests found", "severity": "error"}
    ],
    "suggestions": ["Add pytest tests"]
  }
  ```

- **Логирование в BR18:**  
  Каждая проверка формирует событие для BR18 с деталями проверки и результатами.

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**  

- **REST API (порт 8106):**  
  – `GET /` – информация о сервисе.  
  – `GET /health` – healthcheck эндпоинт.  
  – `POST /review` – проверка файла на соответствие Золотому стандарту.  
  – `GET /rules` – список правил проверки.  

- **Входные данные:**  
  – Путь к файлу или его содержимое в формате JSON.  

- **Выходные данные:**  
  – Отчёт проверки с статусом, нарушениями и рекомендациями.  
  – Логи в BR18.  

**4. ИНТЕГРАЦИИ**  

- **BR18 (Monitoring):**  
  – **C18.1 Log Aggregator** – отправка логов о проверках.  

- **Внешние утилиты:**  
  – `mypy` – проверка типизации.  
  – `ruff` – проверка стиля кода.  

**5. СТЕК ТЕХНОЛОГИЙ**  

- Python 3.12 + FastAPI (микросервис).  
- Uvicorn – ASGI сервер.  
- Pydantic – валидация данных.  
- HTTP-клиент (`httpx`) для отправки логов в BR18.  
- `mypy` и `ruff` – статический анализ кода.  
- Docker с healthcheck.  
- pytest – тестирование.
