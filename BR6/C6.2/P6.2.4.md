
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P6.2.4 (LEVEL 5)

**ID:** P6.2.4  
**Контейнер:** C6.2 (Semantic Auditor)  
**Название:** Интеграция с BR18 и механизм блокировки  

**Зависимости:** P6.2.3

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Расширить аудитор функциями отправки алертов в BR18 (C18.3 Alert Manager) и блокировки артефактов (патчей, навыков) при обнаружении критических нарушений. Для блокировки патчей используется API BR7 (установка статуса `BLOCKED`), для навыков – обновление статуса через BR17 (C17.5). Также реализуется создание задач на исправление некритических проблем через BR1.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Критические нарушения:**  
  – Отсутствие traceability у патча.  
  – Циклы в графе навыков.  
- **Действия при критических нарушениях:**  
  – Отправка алерта в BR18 (C18.3) с уровнем `high`.  
  – Для патча: вызов API BR7 для установки статуса `BLOCKED`.  
  – Для навыка: вызов API BR17 (C17.5) для пометки навыка как `invalid`.  
- **Некритические нарушения:**  
  – Противоречия в документах, мусорные смыслы, несуществующие зависимости (если не являются критическими).  
  – Для них создаётся задача на исправление через BR1 (C1.2) или через BR19.  
- **Формат алерта:**  
  ```json
  {
    "severity": "high",
    "source": "C6.2",
    "message": "Traceability violation for patch P1.2.3",
    "details": { ... }
  }
  ```  
- **API для блокировки:**  
  – BR7: `POST /api/task/block` с параметром `task_id`.  
  – BR17: `POST /skills/{id}/status` со статусом `invalid`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Добавить функции `send_alert()`, `block_task()`, `invalidate_skill()`.  
- После выполнения проверок (P6.2.1–P6.2.3) вызывать эти функции для каждого найденного нарушения.  
- Для некритических нарушений создавать задачу через BR1 (C1.2) – пока может быть заглушкой.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- При обнаружении критического нарушения отправляется алерт в BR18.  
- Статус патча изменяется на `BLOCKED`.  
- Статус навыка изменяется на `invalid`.  
- При недоступности сервисов ошибка логируется, но не прерывает выполнение.
