### **C6.3: Token Guard (Страж токенов)**

**Ветка-родитель:** BR6 | **ID:** C6.3 | **Ответственный:** РЕВА

**1. ФУНКЦИОНАЛЬНОЕ ПРЕДНАЗНАЧЕНИЕ**  
Централизованный контроль и учёт расхода токенов при использовании LLM агентами завода. Token Guard обеспечивает соблюдение лимитов (глобальных, по веткам, агентам и типам задач), автоматическое переключение на альтернативные модели при превышении порогов, блокировку запросов при исчерпании бюджета и сбор детальной статистики для последующего анализа в BR18 (Cost Tracker). Позволяет предотвращать неконтролируемые затраты и оптимизировать использование ресурсов.

**2. ТЕХНИЧЕСКАЯ ЛОГИКА (МЕХАНИКА)**  

- **Учёт и лимиты:**  
  – Данные хранятся в SQLite (`token_guard.db`).  
  – Лимиты настраиваются в файле `limits_config.json` (монтируется как volume) и могут изменяться через API.  
  – Уровни лимитов:  
    * Глобальный (общий для всего завода).  
    * По веткам (BR0, BR1, …).  
    * По агентам (ролям).  
    * (Опционально) по типам задач.  
  – Лимиты могут быть дневными, месячными или абсолютными.  

- **Взаимодействие с агентами:**  
  1. **Предварительная проверка:** агент отправляет `GET /check` с параметрами:  
     – `agent_id` – идентификатор агента (роли).  
     – `model` – запрашиваемая модель.  
     – `estimated_tokens` – оценочное число токенов (опционально).  
     – `task_id` – идентификатор задачи (опционально).  
     – `branch` – ветка (опционально).  
     Token Guard проверяет доступный остаток и возвращает:  
     * `"allowed": true` – запрос разрешён.  
     * `"allowed": false` – запрос заблокирован с причиной.  
     * При превышении лимита для запрашиваемой модели, но наличии альтернативы – может вернуть `"allowed": true, "suggested_model": "gpt-3.5-turbo"`.  
  2. **Отчёт о фактическом использовании:** после выполнения запроса агент отправляет `POST /report` с фактическими данными:  
     – `agent_id`, `task_id`, `model`, `prompt_tokens`, `completion_tokens`, `success`, `duration_ms`.  
     – Token Guard обновляет статистику и уменьшает доступный бюджет.  

- **Автоматическое переключение моделей:**  
  – Конфигурация содержит список моделей с приоритетами и стоимостью за токен.  
  – При превышении лимита для дорогой модели, если есть более дешёвая альтернатива, Token Guard предлагает её агенту. Агент может принять предложение и выполнить запрос к другой модели.  

- **Блокировка запросов:**  
  – Если ни одна модель не доступна (лимиты исчерпаны), запросы блокируются с HTTP 429.  

- **Сбор статистики и отчёты:**  
  – Вся статистика сохраняется локально и периодически (раз в час или по запросу) отправляется в **BR18 (C18.5 Cost Tracker)** агрегированными данными.  

- **Логирование:**  
  – Каждое значимое событие (превышение лимита, блокировка, отчёт) логируется в **BR18 (C18.1 Log Aggregator)** и в локальный журнал.  

**3. ВХОДЫ И ВЫХОДЫ (INTERFACES)**  

- **REST API (внутри Docker-сети):**  
  – `GET /check` – предварительная проверка.  
    Параметры: `agent_id`, `model`, `estimated_tokens` (опц.), `task_id` (опц.), `branch` (опц.).  
    Ответ: `{ "allowed": true/false, "suggested_model": "...", "reason": "..." }`.  
  – `POST /report` – отчёт о фактическом использовании.  
    Тело: JSON с полями `agent_id`, `task_id`, `model`, `prompt_tokens`, `completion_tokens`, `success`, `duration_ms`.  
    Ответ: `200 OK`.  
  – `GET /limits` – получение текущих лимитов (только для администратора).  
  – `PUT /limits` – изменение лимитов (только для администратора).  
  – `POST /reset` – сброс статистики (например, начало нового месяца).  
  – `GET /stats` – получение агрегированной статистики (для отладки).  

- **Локальный журнал:** `01_ЦЕХ/01_ЖУРНАЛЫ/token_guard.log` (JSON Lines).  

**4. ИНТЕГРАЦИИ**  

- **BR7 (агенты):** вызовы `/check` и `/report` от всех агентов.  
- **BR18 (Monitoring):**  
  – **C18.5 Cost Tracker** – периодическая отправка агрегированной статистики.  
  – **C18.1 Log Aggregator** – отправка событий.  
  – **C18.3 Alert Manager** – отправка алертов при превышении лимитов.  
- **BR4 (Command Console):** через API для ручного управления.  

**5. СТЕК ТЕХНОЛОГИЙ**  

- Python + FastAPI (микросервис).  
- SQLite (для хранения статистики и лимитов).  
- HTTP-клиент (`httpx`) для отправки данных в BR18.  
- Конфигурационный файл `limits_config.json`.  
- Docker (контейнер без специальных привилегий).
