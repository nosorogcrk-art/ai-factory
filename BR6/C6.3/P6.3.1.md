### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P6.3.1 (LEVEL 5)

**ID:** P6.3.1  
**Контейнер:** C6.3 (Token Guard)  
**Название:** Базовая структура и приём отчётов

**Зависимости:** отсутствуют

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Создать базовую инфраструктуру Token Guard: хранилище лимитов и статистики (SQLite), а также эндпоинт `POST /report` для приёма отчётов о фактическом использовании токенов от агентов. Это позволит начать сбор данных и подготовить основу для последующего контроля лимитов.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Хранение данных:**  
  – Используется SQLite, файл `token_guard.db` в монтируемом томе (например, `/data`).  
  – Таблица `limits` для хранения лимитов (поля: `level` (global, branch, agent, task_type), `name`, `limit_value`, `period` (daily, monthly, absolute)).  
  – Таблица `usage` для записи каждого отчёта (поля: `timestamp`, `agent_id`, `task_id`, `branch`, `model`, `prompt_tokens`, `completion_tokens`, `success`, `duration_ms`).  
  – Таблица `budget` для хранения текущего состояния расходов по каждому лимиту (поля: `limit_id`, `spent`, `reset_time`).  

- **Конфигурация лимитов:**  
  – Загружается из файла `limits_config.json` при старте. Если файла нет – создаётся пустая конфигурация.  
  – Пример структуры:  
    ```json
    {
      "global": {"daily": 1000000},
      "branches": {"BR1": {"daily": 50000}},
      "agents": {"ГЕФЕСТ": {"daily": 20000}}
    }
    ```  

- **Эндпоинт `POST /report`:**  
  – Принимает JSON с полями: `agent_id`, `task_id`, `model`, `prompt_tokens`, `completion_tokens`, `success` (bool), `duration_ms` (опционально).  
  – Валидация: проверка наличия обязательных полей.  
  – Сохраняет запись в таблицу `usage`.  
  – Обновляет соответствующие лимиты в таблице `budget` (увеличивает `spent`).  
  – Возвращает `200 OK`.  

- **Логирование:**  
  – Все операции записываются в локальный журнал `01_ЦЕХ/01_ЖУРНАЛЫ/token_guard.log` (JSON Lines).  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать файл `token_guard.py` с FastAPI-приложением.  
- При старте инициализировать БД (создать таблицы, если их нет).  
- Загрузить конфигурацию лимитов из `limits_config.json`.  
- Реализовать эндпоинт `POST /report` с валидацией через Pydantic.  
- Для обновления лимитов написать функцию `update_budget(agent, branch, task, tokens)`, которая увеличивает соответствующие счётчики.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Приложение запускается, БД создаётся.  
- При отправке корректного POST-запроса на `/report` данные сохраняются в БД.  
- При неполных данных возвращается ошибка 422.  
- Лог-файл создаётся и содержит записи о полученных отчётах.
