
### 📄 СПЕЦИФИКАЦИЯ ПАТЧА P6.1.2 (LEVEL 5)

**ID:** P6.1.2  
**Контейнер:** C6.1 (Chaos Monkey)  
**Название:** Добавление других типов сбоев

**Зависимости:** P6.1.1

---

#### 1. ЗАМЫСЕЛ ПАТЧА  
Расширить функциональность Chaos Monkey новыми типами сбоев: удаление контейнера, потеря сети, искусственные задержки, высокая нагрузка CPU/памяти, потеря тома. Каждый тип сбоя реализуется как отдельная функция, вызываемая из общего интерфейса. Результаты также логируются.

---

#### 2. ТЕХНИЧЕСКИЕ ПАРАМЕТРЫ  

- **Новые типы сбоев:**  
  1. `container_rm` – удаление контейнера (`docker rm`). После удаления ожидается, что оркестратор (BR0) пересоздаст контейнер.  
  2. `network_loss` – изоляция контейнера от внутренней сети (например, с помощью `docker network disconnect`). Проверка восстановления – подключение обратно.  
  3. `network_latency` – добавление задержки с помощью `tc` внутри контейнера (требуется привилегированный режим и утилита `tc`).  
  4. `cpu_stress` – запуск стресс-теста CPU (через `stress` или `stress-ng` внутри контейнера).  
  5. `memory_stress` – нагрузка на память.  
  6. `volume_loss` – временное отключение тома (перемонтирование или удаление связи).  
- **Каждая функция принимает имя контейнера и опциональные параметры (длительность, интенсивность).**  
- **Возвращаемое значение:** аналогично `stop_container`.  
- **Логирование:** в том же формате, добавляется поле `experiment_type`.  

---

#### 3. РЕАЛИЗАЦИЯ (L6 — КОД) – ОПИСАНИЕ  

- Создать отдельные функции для каждого типа сбоя.  
- Для сетевых задержек использовать `exec_run` внутри контейнера с командой `tc`.  
- Для стресс-тестов выполнить `docker exec` с запуском `stress`.  
- Для удаления контейнера – `container.remove(force=True)`, затем ожидание восстановления.  
- Для потери тома – отмонтировать том (сложно, возможно, через пересоздание контейнера без тома).  
- Добавить общую функцию `run_experiment(container, type, params)`, которая вызывает соответствующую функцию.  

---

#### 4. КРИТЕРИЙ ПРИЕМКИ (DoD)  

- Каждый тип сбоя успешно выполняется (контейнер переживает воздействие).  
- Восстановление корректно отслеживается.  
- Логи содержат тип эксперимента.  
- При неверных параметрах возвращается ошибка.
